# 通用 Agent 自主回查与纠偏实测

日期：2026-10-27。用户确认继续上一轮提出的真实模型场景验证。功能基线为 `ae008f0`；本轮首先验证原能力，不新增模式或业务流程。

## 预先确定的场景与判据

复用现有隔离模型验收脚本，仅读取已配置的连接信息。新建临时联系人、任务和数据库；以下访谈、反馈、商业想法均为合成案例，不是用户真实工作或真实市场证据。运行结束关闭执行器并移除临时数据，保留脱离凭据的测试日志、输入、工具结果和输出。

同一任务先保存七轮历史，关键事实位于最近三份报告/分节/反馈之外：早期二手玩具寄售方案被用户否定（不承担保管、清洁、退货）；书店报名工具付费假设为 candidate；后续合成回访显示免费表格已足够、店主不愿为通用报名工具付费。近期报告故意遗留“继续打磨书店付费报名工具”的旧下一步。关闭再打开数据库后，给模型正常任务上下文，由它自主决定如何查历史与构思下一步，不在测试回复中指定工具调用或注入标准答案。

1. 原任务保持持续状态，本轮能完成交付，不重复要求用户确认继续。
2. 实际工具返回中包含早期否定反馈、回访反证和未验证假设；初始提示未直接塞入这些正文。规划阶段发生回查。
3. 输出体现旧方向的限制和反证，而不是重复推荐已经否定的业务或把付费猜测宣称为事实。机器检查关键依据，人工逐段核对新方案与旧方案的区别、论据和不确定性。
4. 研究候选在数据库中仍为 candidate，不因使用而自动确认。

检索摘要属于真实提供的上下文，短记录可能完整落在摘要内；不强迫模型再调用一次正文工具充数。是否读取完整正文另行记录。通过一次样本不意味着长期新颖度或任意任务的纠偏可靠性已通过。

## 执行入口

`node scripts/test-contact-model.cjs --autonomy --engine=native` 与 `--engine=dsh`。省略 engine 时顺序验证两种执行器。普通 `npm test` 跳过这类付费验证。

每个隔离任务最多 18 次模型调用、180000 token，并受原调度/取消/超时/用量结算约束。这是验收运行边界，不是新增产品配置。

## 实测结果与修复

使用现有连接的 `as-glm-5.2`，分别通过 Native 和 DSH 实际请求模型。初始输入、逐次工具结果、输出与用量保存在忽略目录 `artifacts/agent-autonomy/`，不包含连接凭据。结果如下，不能只看最终机器断言：

| 样本 | 实际结果 |
| --- | --- |
| 初始验证 | Native 已回查关键记录，但输出协议错误、恢复缺少结束标记，未完成；DSH 未查早期反馈，提出与限制冲突的实物方案 |
| v2 | 提醒旧反馈并加强输出协议后，仍因低效检索、逐条重读触及原六轮工具上限 |
| v3–v4 | 支持多关键词检索、完整摘要标记和剩余回复轮数后，可以提出新方案；部分样本仍漏查候选研究。DSH v4 机器判据通过，但商业效果仍只是未验证假设 |
| v5 | 提供有界候选引用目录后，DSH 机器判据通过；Native 把反馈 ID 改写成 `feedback_1`，导致整轮失败 |
| v6 | 可纠正引用错误不再直接终止任务。Native 机器判据通过，但人工发现恢复正文整段重复，因此内容验收未通过；DSH 在 235 秒验收等待内未完成，按失败记录并关闭隔离执行器 |

本轮补正的是通用能力与可靠性，不把场景中的行业判断写进产品规则：

- 回查支持最多八个空格分隔关键词、命中任一词；完整短摘要明确标记，减少无意义重读。Unicode 字符计数不会把仍有后文的摘要误报为完整。
- 开轮反馈快照含总数，说明是否还有更早反馈；候选目录最多六个引用，不直接附入内容，也不把目录记成已读。仍保留联系人/任务/版本范围与未验证状态。
- 两种执行器共用原六轮工具往返上限，工具结果提示剩余回复机会；实际任务和每日额度仍生效。输入错误返回明确的可纠正结果，生命周期、存储等不可恢复异常中止本次执行，不能被 DSH 当作普通回复继续生成。
- 结构化结果及分段恢复明确遵守各自输出协议。恢复只去除与已保存长前缀完全相同的回放，不改写其他正文；正常短续文保留。中断时强制保存归一化后的草稿，避免流式节流留下重复片段。
- 独立审查确认另一个既有故障：失败通知为说明影响再次读取损坏正文，导致整个失败事务回滚。现将这部分说明降级为“保存情况无法核实”，保留失败状态、事件和通知，不声称旧正文可读，也不修改损坏数据。
- 验收脚本由父进程在 Electron 退出后清理独立 profile，避免 Windows 文件锁导致清理异常与进程挂起；支持单独选择执行器，模型调用仍显式启用。

## 回归与验收边界

定向回归四文件 54 项通过，包含 Native/DSH 真正损坏数据库正文后停止、失败持久化、错误引用纠正、候选权限/历史版本、续写重复前缀及中断恢复。长前缀流式回放尚未收齐时暂缓保存及重复计数，最终与异常收尾仍保留不能确定为回放的短续文。核心新回归均先记录失败，再验证修复；日志为 `targeted-red.log`、`corrupt-failure-red.log`、`continuation-red.log`、`stream-flush-red.log`、`long-replay-red.log` 与 `final-targeted3.log`。

最终全量、类型与构建结果见下方验证记录。本轮不继续反复调用模型直到得到成功样本。v6 原始结果另存 `live-native-v6.json`、`live-dsh-v6.json`；最新恢复修复由确定性回归验证，尚未重新用付费模型抽测。人工确认的重复正文及 DSH 超时仍计为本轮真实模型验收未通过；不能以之前的成功样本覆盖。

后续仍需评估跨多轮的新颖度、不同任务的纠偏质量和交付稳定性。没有运行用户真实赚钱任务，合成访谈不是市场证据，也未验证盈利。完整桌面与全天运行仍沿用既有未完成范围。
