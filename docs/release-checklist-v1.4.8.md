# ChouYu 1.4.8 发布验证

## 范围

产品代码沿用未公开的 1.4.7：持续提醒与退出备份提速，见[持续提醒验收](persistent-reminders-acceptance-20261117.md)及[退出性能与原始发布记录](release-checklist-v1.4.7.md)。从 `3da7214` 起仅修正测试条件及版本/文档，不修改生产重试次数、超时、数据保存或模型执行行为。

## 云端失败定位与测试修正

1.4.7 两轮质量失败的文件不同，主要为真实 SQLite/fsync、进程初始化测试触及默认 5 秒。CI 降为两个 worker，给真实集成夹具 15 秒完成时间；本地默认四个 worker、5 秒保持原样。测试数量、数据规模、业务断言、原生数据库操作均保留。

Windows SHM 映射测试原先假设向 PowerShell 写入释放信号后必在首次 100 ms 退避前完成进程清理；云端已观察到第二次重试才释放，而来源完整且恢复成功。成功场景改为核验在原有 1～3 次边界内恢复；不释放时仍须恰好三次后失败，保留数据和完整性检查不变。

真实 DSH 请求原先使用默认一秒 readiness 等待。改为五秒，原有不同提供者/联系人隔离、取消不影响同伴及结果断言不变。提前附加拒绝处理，防止 readiness 失败时清理关闭运行时产生额外未处理拒绝；正常路径仍等待原 promise 并验证真实结果。

这些测试等待时间不代表产品响应承诺，也没有放宽单独的实际应用退出 15 秒门槛。退出验收仍要求最后修改同时保存到主库与最新备份，并检查两库摘要和检查点归属。

## 验证与发布状态

本地使用 `CI=true npm test` 按云端两个 worker / 15 秒配置复跑，324 文件、2,427 项通过，17 文件、62 项跳过，耗时 188.45 秒；类型检查通过。独立审查未发现 Important/Critical，也未发现测试修正掩盖业务失败。

`3da7214` 的[主干完整 Quality](https://github.com/cone387/ChouYu/actions/runs/44016182891)第二轮在原测试配置下也已通过，包括完整桌面和退出落盘核验；保留首轮失败，不将复跑成功当成所有托管机器时序问题已消失。

新标签验收进行中。必须通过标签质量、双平台构建和成品门槛后才公开；保留 1.4.7 原失败日志与标签，不用重写标签掩盖失败。
