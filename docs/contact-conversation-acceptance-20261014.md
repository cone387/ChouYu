## 当前覆盖

### 2026-10-15 真实模型与实际应用全链路回归

用户明确要求实际调用模型覆盖各种场景，本轮同时保留确定性单元测试和真实模型验收，不再用路由返回 `none` 代替最终回答。新增入口：先 `npm run build`，再 `node scripts/test-contact-model.cjs --matrix`。使用当前阿笔配置的 `as-glm-5.2`；供应商密钥仅通过进程环境传递，不输出到日志。测试在经过路径核验的临时 Electron 数据目录创建合成联系人/任务，不修改用户真实消息、任务或设置。

| 实际应用场景 | 检查结果要求 |
| --- | --- |
| 空人设身份 | 以自己的名字回复，不借用ChouYu身份 |
| 编辑历史后的原话续写、另一种续写说法 | 完整正文包含指定人物，不退回旧追问；后台状态和卡片不变 |
| 聊天稿两轮修订 | 按最新人称/人物要求交稿，不改后台任务 |
| idea与评审两轮 | 直接给想法、结论及依据，不生成任务操作 |
| 引用与否定修改 | 讨论不执行，无设置/任务变更 |
| 工作时间确认、设置拒绝 | 真实卡片经自然语言同意落盘；拒绝后保持原设置 |
| 名称与权限组合请求 | 两张卡分别处理，改名生效、拒绝的权限保持原值 |
| 含糊任务后补充名称 | 首轮必要追问，次轮真实修改正确任务预算；另一任务及暂停状态保持 |
| 不存在的恢复目标、单任务暂停 | 不拿其他任务替代；暂停只作用于指定任务 |
| 旧版本卡片、纠正卡片方案 | 旧卡不能覆盖已变更新值；新方案确认后实际保存 |
| 恢复后台、正式成果修订 | 生成正确确认卡，未确认不启动；拒绝不改变任务 |
| 固定版本与联系人长期输出偏好 | 两种范围分别保存；确认前不变，不改正文/任务状态 |
| 搜索凭据请求 | 生成安全输入入口，不要求在聊天里发送密钥 |
| 实际编辑→保存重发→首字前关闭 | 成功完整回复留在原会话，旧后续回复移除；隐藏完成保持未读，磁盘消息逐项一致 |

上述共22个场景（纠正卡片含三种表述，聊天稿修订含两种表述），多轮场景共用真实历史，经生产 `startStream` IPC、注册工具、卡片提交及数据库执行；保存输入、完整输出、工具事件和状态前后对照。最后一项使用实际React编辑/重发/关闭按钮，其余通过实际IPC调用。普通IPC场景由测试保存会话历史，不能据此证明UI生命周期；UI场景另核对成功完成标记、无错误状态、超时失败、未读及实际磁盘文件。
