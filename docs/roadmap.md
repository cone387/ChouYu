# ChouYu 迭代路线

更新日期：2026-08-31

当前版本：`1.2.0`（开发中）

这份路线把当前功能状态、发布前验收和后续能力拆成可独立验收的阶段。每个阶段完成后再进入下一阶段，避免同时引入多个高风险变量。

## 当前基线

### 已完成

- 桌面宠物、拖拽吸附、点击穿透、托盘和全局快捷键
- OpenAI-compatible / Claude 流式聊天、模型诊断和配置引导
- 多会话、Markdown、附件、截图、剪贴板快捷操作
- 工具调用、逐次授权、风险分级和插件工具
- SQLite 长期记忆、Embedding、冲突处理、版本历史、主题聚类和导入导出
- Mem0 Platform / Self-hosted 同步适配器
- 自适应聊天/设置面板、暗色模式、焦点样式、减少动画和设置导航搜索

### 工程门禁

- TypeScript 类型检查通过
- Vitest 单元测试通过（当前 126 项）
- Electron 生产构建通过
- Electron 启动冒烟测试通过

## P0：发布前稳定性

目标：把开发版变成可交付的 Windows 版本。

### 验收项

- [ ] 在干净 Windows 环境完成安装、启动、卸载
- [ ] 验证开机自启、托盘显示/隐藏和退出
- [ ] 验证自动更新、下载进度和重启安装
- [ ] 验证 OpenAI-compatible 不同 Base URL、模型列表和流式响应
- [ ] 验证 Claude 官方接口的模型列表、鉴权和流式响应
- [ ] 验证 100% / 125% / 150% DPI、多显示器和不同分辨率下的定位
- [ ] 验证透明窗口点击穿透、拖拽吸附和快捷键冲突恢复
- [x] 生成当前版本 Windows 安装包、SHA-256 和更新元数据
- [x] 验证 packaged Electron 产物可以独立启动
- [ ] 创建 Git Tag 和 GitHub Release
- [ ] 决定 Windows 代码签名证书方案

### 完成标准

所有验收项在干净用户环境通过，且安装包可以被另一台 Windows 机器独立安装和卸载。

## P1：UI/UX 收敛

目标：降低设置和记忆功能的学习成本，补齐 UI 级质量保护。

### 计划

- [x] 将记忆中心从长设置页整理为独立工作区（总览、待处理、记忆库、整理、连接）
- [x] 待处理视图支持配置显示范围并持久化选择
- [ ] 增加设置项搜索结果的快捷定位和清晰的空状态
- [ ] 为设置、工具、能力和记忆建立统一字号/间距 token
- [ ] 增加亮色/暗色、窄屏和 DPI 缩放的视觉回归截图
- [ ] 增加 Electron UI 冒烟：面板开关、点击穿透、拖拽、导航和输入聚焦
- [ ] 检查所有图标、错误提示、加载态和焦点顺序

### 完成标准

核心流程可以只用键盘完成；375px 等效窄视口无横向滚动；主要正文和控件在 100% 缩放下清晰可读。

## P1.5：Mem0 主引擎收敛

目标：选择 Mem0 后只保留“配置一次、正常聊天”的主流程。

- [x] Mem0 聊天检索直接调用远程 `/memories/search`
- [x] Mem0 模式不启动本地生命周期维护，不执行本地 Embedding、主题聚类和记忆整理
- [x] Mem0 模式隐藏 SQLite 专属的待处理、记忆库和整理入口
- [x] 移除备份、迁移和双向同步能力
- [ ] 用 Electron runtime fake server 覆盖 Mem0 主引擎连接和错误恢复

## P2：感知能力补齐

目标：完成截图和桌面感知的本地/低延迟场景。

- [ ] 本地离线 OCR
- [ ] 滚动截图
- [ ] 录屏
- [ ] 自动活动窗口跟随
- [ ] 权限拒绝、超时和失败重试的统一反馈

## P3：插件安全与同步生态

目标：让外部能力可以安全安装和隔离运行。

- [ ] 外部插件发现、安装和版本管理
- [ ] 签名验证、目录白名单和依赖隔离
- [ ] helper 进程环境变量过滤、崩溃回退和超时处理
- [ ] Mem0 OSS 运行时
- [ ] Letta 适配器与双向增量同步

## P4：高级交互

目标：在核心体验稳定后扩展为更主动的桌面伙伴。

- [ ] 多步骤 Agent 规划和后台任务
- [ ] 在线工具市场
- [ ] 语音输入和 TTS
- [ ] 3D/VRM 角色、多角色和多设备同步

## 迭代规则

1. 每个阶段先补验收标准，再实现功能。
2. 涉及外部网络、密钥或用户数据的功能必须有显式开关和失败恢复路径。
3. UI 改动必须同时覆盖窄屏、暗色模式、键盘焦点和减少动画。
4. 新功能合并前至少通过类型检查、单测、构建和 Electron 冒烟测试。
