# 全局看板实施计划

用户已要求直接按全局看板方案实施。沿用 Electron / React / TypeScript 和现有主题，不新增依赖。

## 设计与范围

新增全局「看板」，迁入通讯录的全员活动日志，集中展示联系人工作概况、任务数量、累计 Token，按联系人筛选。复用 `agents.dashboard()`、`ContactsActivityLog`、联系人详情与任务来源导航；通讯录恢复全宽列表。单个联系人的任务、成果、记忆、人设与工作设置保留原入口。

方案选择：采用全局入口，满足跨联系人查看；每个联系人内新增看板无法承接原全员活动；仅移动日志不能提供工作概览。选择依据是用户在上述提案后要求「直接做」。

统计仅覆盖当前保留的联系人后台工作任务，不将普通聊天、助手内置职责/定时安排计入同一口径。未加载/缺失数据不冒充零；供应商未报告 Token 保留「未记录」或部分记录提示。读取失败保留上次数据并显式报错；隐藏页面停止轮询；页面切换保留筛选。空状态与已删除联系人可恢复。

不更改执行引擎、通知未读或任务表单；不新增快速录入、多选、批量操作。受影响验收项：UI-01、UI-05、UI-06、HIST-01、SCOPE-01。

- [x] 验证与文档：适配原 agents-smoke 的日志入口；新增真实 Electron 看板回归，验证筛选保留、导航、宽窄/深浅色并保存截图；执行类型、单测、边界、构建检查，更新规范实现记录和工作区说明。

## 审查重点

筛选后统计与日志必须同范围；未知与部分数据不能伪零；页面隐藏停止工作；已删除联系人的选项重置；日志进入详情/任务后可以关闭并回到原筛选。尽量复用原流程，避免引入第二套联系人任务 UI。
