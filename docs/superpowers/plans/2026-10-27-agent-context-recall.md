# 通用 Agent 工作上下文与按需回查

依据：`../specs/2026-10-27-agent-autonomy-direction.md`、`../../agent-autonomy-audit-20261027.md`、`../../contact-task-spec.md`。用户已确认继续实施；在现有 `feat/agent-autonomy` 分支顺序执行，不新增产品模式或配置表单。

## 完成标准

- 规划获得本轮已选择的有效记忆、近期工作与用户成果反馈；生成阶段也获得相同反馈。
- 规划、生成可以按需检索并分页读取当前任务的旧成果、有效记忆、待验证研究记录、成果反馈。引用含版本、状态与来源，候选研究不自动确认。
- 接单阶段无工具；规划只允许当前任务的只读回查；实际执行工具仍受原授权限制。
- 不跨联系人、任务或私聊泄露数据，不读取运行开始后才发布的成果/反馈。修正或忘记已用记忆、暂停、删除、终止会阻止继续提交。
- 两种后台引擎均有真实工具往返的本地集成验收，不调用真实模型；现有调度、资源、成果事务与通信契约不回退。

## 步骤

1. 新增 `src/main/agents/task-context.test.ts`，先验证旧正文、研究候选、反馈检索读取及权限/分页/版本边界失败；实现 `task-context.ts`。查询绑定 run，不接受外部 owner/topic；固定成果版本与反馈上界。输出有界，实际提供的记忆（包含检索摘要）记录到 run 的独立回查引用并校验。复用现有数据库，无新 schema。
2. 将回查引用纳入 `mutations.ts` 的失效与提交校验；增加数据修改/忘记、来源删除回归测试。避免把候选引用塞入仅允许 active 的旧引用字段。
3. 修改 `model.ts`、`workflow.ts`、`scheduling.ts`：增加只读上下文工具层与规划专用权限；保留接单工具隔离。规划携带实际记忆和历史，规划与执行共用近期反馈。更新 `planning-tools.test.ts` 并添加 Native/DSH 实际检索、读取与交付的集成测试，先红后绿。
4. 运行关联测试、类型/边界检查、完整单测及构建。按执行计划技能进行一次全改动独立审查，修复重要问题并复验。更新产品规范缺口、审计与路线图，说明本轮能力范围及未覆盖的真实模型行为。

## 实施约束

只读工具命名 `search_task_context`、`read_task_context`。资源为 memories/deliveries/feedback；检索最多 6 项、摘要最多 300 字，正文每页最多 6000 字；游标采用稳定序号。正文仍从已保存成果读取。当前任务研究候选以来源 run 的真实归属判断，其他任务候选及 session 记忆不开放。新取得的记录仅是历史依据，不伪装成本轮外部证据。

检索/读取同步完成，调用前后检查运行与取消信号。记忆引用去重且数量有界；恢复时继续验证引用，不复制无界历史。旧运行没有新快照字段时使用运行时间作为反馈上界，成果使用已有 pinned delivery version。

审查补正：成果检索增加可选 version 参数，默认仍查开轮累计版本，可主动查旧反馈所指版本，不能超过开轮上界。删除来源任务时，事务内失效依赖记忆，并向命令层返回全部受影响运行以取消和清理；这也补齐了迁移的 active/contact 研究记忆被其他任务引用时的生命周期边界。
