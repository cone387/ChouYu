# Windows 安装升级路径修复

目标：用户直接运行 EXE 完成升级，不需要启动脚本、修改系统设置或清空应用数据。

现有证据：1.4.2 包含 198 字符相对路径，旧卸载器移动到 `%TEMP%\ns*.tmp\old-install` 后超过 MAX_PATH。相同 NSIS Rename 在普通 TEMP 失败、继承 `\\?\` TEMP 后成功。

方案：新安装器在初始化时，仅为其子进程设置扩展长度格式的 TEMP/TMP，让原有卸载器支持长路径；安装结束、启动应用之前恢复原环境。保留原卸载、回滚、用户数据和应用关闭流程，不替换旧卸载器、不禁用失败检查。源码修改限安装器。

执行：
- [x] 用真实 NSIS 编译的父安装器/旧卸载器构建长路径回归，先确认失败（退出码 73）。
- [x] 增加 NSIS include，验证长路径迁移、已有前缀、环境恢复和失败退出码。
- [x] 生成修正安装包，检查安装升级及成品桌面冒烟。
- [x] 更新安装验证记录并交付普通 EXE。

工作决策：按用户要求直接修复，使用当前已安装依赖，在独立修复分支执行；不发布远程 release、不修改用户产品约定。

补充验证：真实 electron-builder NSIS 小型安装包，旧版安装成功；旧卸载器 `--updated` 长路径失败并恢复旧文件；修正版覆盖升级成功、实际独立 APPDATA 中的哨兵文件保留；普通卸载成功。第一次修正版编译发现 BUILD_UNINSTALLER 阶段未使用变量，补充编译条件后通过。
