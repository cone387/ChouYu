# 联系人完整体验迭代设计

日期：2026-10-12。
状态：用户于本轮以「en」确认完整设计；新功能尚未开始实现，实施计划待审阅。已先修复两项现行规范偏差，见第 8 节。

## 1. 目标与依据

用户在评估联系人能力、体验与 UI 后要求「嗯 全部迭代好」。本次覆盖上一轮建议的全部六项能力、五项 UI 改善和两项既有规范偏差，不将第一阶段交付视为全部完成。

目标是让用户能找到合适的联系人、自然延续共同经历、方便阅读和讨论成果、维护长期资料，并明确交接成果给另一联系人。日常操作应围绕真实内容与需要用户回应的事情组织。

[联系人任务产品与交互规范](../../contact-task-spec.md)仍是唯一产品规范入口；本文是该入口下的本轮设计附件，不替代现有任务、消息、权限与验收契约。新增规则经本设计审阅后并入规范，实施状态与证据随代码更新。

必须保留：各联系人独立身份与记忆；ChouYu 的专属助手职责；任务新建/编辑单自然语言描述与公共弹窗；公共任务详情及原执行引擎；所有主动消息未读闪烁；正式正文直接交付；任务预算、工作时间、暂停、并发限制、权限与恢复机制。不得新增快速新建、多选或批量操作，不增加今天页过期提示或筛选条件标签，不引入表单彩色焦点装饰。

## 2. 已核对的实现基础

- `ContactsView` 卡片主要展示模型、人设摘要、工作方式、任务/Token/记忆统计；`ContactDailyOverview` 默认展示时间、调用与日志。
- `ContactAgentPanel` 并列八个联系人标签；任务内部五个标签由公共 `ContactTopics` 提供，两层导航不可混淆。
- `AgentDeliveries` 在 SQLite 的 `delivery_versions` 中保存不可变完整版本；每版包含分节、来源、展示与轮次，具备上一版比较及导出基础。
- `ContactDelivery` 的阅读分节仅在组件状态保存，现有讨论引用工作记录，不具备持久段落锚点。
- `AgentMemory` 只有内容、轮次与创建时间。已有最多 100 条、每条 2000 字限制；聊天上下文目前截取最近 12 条，没有任务/会话范围与版本引用。
- `ContactSources` 已检查读方读取权限、作者共享权限，并以版本、分节与正文哈希去重。共享对象不含私人聊天、记忆或凭据。
- 技能有安装/启用/脚本授权、能力报告、Docker 运行及工作文件，但文件归属主要是联系人与技能，需要补齐任务/轮次关联。
- 初次核对发现的偏差：联系人卡片空人设提示称使用默认丑鱼人格；独立记忆新增表单在页面内展开。两项已在 ea98736 修复，见第 8 节。

## 3. 采用的方案与边界

采用现有引擎上增量扩展的方案：在现有联系人数据库中持久保存新对象，通过原主进程 → worker → service 路径校验并读写，UI 复用任务、消息、成果和交互卡片。

仅调整视觉层级不能完成记忆、阅读、资料和协作需求；另建统一项目引擎会扩大迁移风险，且违背共用 UI 不迁移引擎的约定。因此保留现有引擎和任务身份，补充独立存储模块与引用契约。

本轮协作是明确的版本交接和已安排的持续评审，不增加自由群聊、自主招募、第三方发布或未经要求的外部服务连接。资料空间提供长期存储、版本、范围和可验证读取；首轮文档格式采用已有文本附件能力支持的文本与 Markdown，文件导入界面明确支持范围，不能假报已读取 PDF/Word。PDF/Word 解析不属于此前承诺的格式，本设计不借文件名推断正文。

## 4. 完整需求与交互

### A. 联系人列表、概览与导航

1. 卡片第一层保留头像、名字与擅长方向。使用现有人设信息，未设置时显示「尚未设置人设」，不为每张卡片调用模型生成介绍。
2. 第二层显示真实待回应事项、最近正式交付及当前任务状态。摘要是保存内容的截取或状态投影，不拼装成联系人聊天发言。缺失数据明确加载/读取失败，不伪造零值或忙碌。
3. 任务/Token/记忆统计与模型服务仍可查，视觉上次级。已配置工作方式仍显示；联系人的固定排序不会因后台运行抖动，沿用现有排序选择。
4. 概览首屏依次为需要用户处理、最近交付、当前任务。用同一张交互卡片处理问题；工作时间图、日志和用量继续保留为次级内容，不删现有统计能力。
5. 联系人详情的日常入口为概览、任务、成果；记忆和资料作为个人内容入口；技能、人设、工作设置、工作记录、活动与消耗为次级工具。通过分组和宽度适配建立层级，不改变任务内部五标签结构。
6. 窄容器下内容单列，工具自然换行或进入带清晰标签的更多菜单。聊天当前任务操作仍并入现有快捷工具栏，不加独立控制行。
7. 从待处理、设置、原聊天和成果往返时恢复联系人、任务、阅读位置及合理焦点。处理成功以实际事务结果反馈；打开设置不标已解决，读消息不清除未解决事项。

### B. 成果集、收藏、搜索与续读

1. 每个联系人的「成果」入口聚合其各任务的正式成果，一项作品默认对应一个任务；同时可浏览该联系人的所有任务或指定任务，按更新时间或名称排序，并筛选收藏。
2. 搜索覆盖正式分节标题与正文，显示匹配片段；默认搜索各作品最新版本，历史版本通过该作品的版本入口查看。结果带任务、版本与分节，打开精确匹配的版本。列表每页 30 项，以查询开始时的索引快照和稳定复合游标分页，更新不造成重复或跳项；搜索不触发模型调用。
3. 默认展示最新成果，历史消息或来源链接仍打开当时版本。阅读器清楚显示当前版本、新版可用及切换入口，后台交付不会切走正在读的章节。
4. 收藏按任务保存，默认指向最新版本；用户从某条历史消息打开时仍保留其精确版本。收藏不改变任务生命周期或共享权限。
5. 持久阅读记录包含联系人、任务、版本、分节、段落锚点、位置及时间。打开作品提供「继续阅读」，关闭和重启后有效；普通浏览不会把全部分节标已读。
6. 每个分节保存实际阅读过的正文哈希，用于区分新增、已修改与已读。只改阅读样式不产生虚假新增章节；未显示内容不自动标读。滚动保存节流，关闭时提交末次位置。
7. 返回最新版本时，原锚点可匹配则恢复，否则显示「内容已更新」并定位原分节开头；原分节不存在时保留旧版入口，不把随机位置当原位置。
8. 同一个阅读组件供任务成果与联系人作品集复用。原自定义展示、正文、版本比较和导出保持可用。自定义 iframe 只能发送受校验的阅读/选择事件，主进程重新核对正式正文；无法匹配时明确切换正文继续定位。

### C. 正文引用、讨论与精确修订

1. 在正式成果选择文本后可「引用讨论」或「提出修改」；键盘也能调用，未选中时可引用当前分节。选择只建立草稿，不发送消息或开始任务。
2. 引用包含作者、任务、成果版本、分节、选中文字及可核对锚点。用户界面显示标题、版本和引文，内部 ID 不拼进聊天正文。发送前服务端按已保存版本核对引文，不能信任 UI 提交的任意文本。
3. 普通讨论在原联系人聊天中进行，系统携带结构化引用读取原文；仅讨论不启动写作。聊天气泡能打开引用原文，重启后仍有效。
4. 提出修改使用模态意见输入，引用作为只读上下文；沿用现有修订路径、额度、排队和暂停规则。意见明确附着原版本，修改前若已有新版则展示差异和重新基于新版提交的入口，不能静默套用。
5. 允许「保留这一段，调整其他部分」等意见，约束进入持久修订需求。保存的新成果展示修改前后和受影响分节；能从回执回到原阅读位置。
6. 选择过长、跨多个无法定位区域、来源已删除、磁盘失败、过期版本均给出明确原因并保留草稿。样式修订仍只改变样式，不改正文。

### D. 可纠正、有范围和来源的独立记忆

1. 保留现有记忆，新增原位编辑、更新历史、类型和适用范围。类型区分用户偏好、项目背景、共同经历、研究判断；范围区分此联系人长期、指定任务、当前会话。
2. 记忆新建/编辑使用公共模态约定。可用自然语言说「请记住」或「这条已经过时，改成……」；明确对象时更新原记录，多个可能对象才追问。聊天写入遵循现有联系人工具确认策略，不新增重复确认。
3. 人工纠正产生新版本，旧版本不再进入后续上下文，来源和时间可查。后台研究不得覆盖用户纠正；相矛盾的研究保留为候选并指出冲突，不默默替换。
4. 普通聊天、后台任务和主动工作检查使用统一检索边界：仅取当前联系人、当前任务/会话适用的有效记忆；按相关内容选择而非仅最近十二条，输出有界且明确是否截断。ChouYu 的跨联系人工作检查不读取其他人的独立记忆。
5. 为实际模型请求保存所提供记忆的 ID、版本及来源；UI 称「本次参考记忆」，不声称证明模型内部采用了每条记忆。查看后可纠正或忘记，旧消息仍引用原版本或显示已移除。
6. 共同经历来自真实对话、任务决定和正式成果；保留证据，不虚构现实经历，不增加好感度或人为关系等级。用户明确要求保存的经历直接处理，系统提取的候选不能把推测写成事实。
7. 更新/忘记影响正在执行的上下文时使旧快照失效并取消受影响轮次，保留已有成果和暂停状态；后续按原工作设置执行，迟到结果不得把旧记忆写回。
8. 保持单条长度限制与明确容量反馈；版本历史不占有效记忆条数，达到有效记忆上限不静默丢弃。忘记从后续检索中移除内容；历史引用保留「已忘记」标记而非继续暴露已删记忆正文。原聊天/成果不自动删除。

### E. 联系人资料空间

1. 资料入口支持模态添加文本/Markdown 文件、粘贴文字、保存已有文本附件、添加已有网页来源；不会自动把所有聊天附件变成长期资料。
2. 保存时明确「此联系人长期使用」或「仅此任务」，默认沿用当前任务上下文，没有明确任务则归当前联系人长期。使用已保存任务选择，不在任务描述表单加字段。
3. 本地文件导入后保存独立副本和不可变版本，原电脑文件变化不暗中改资料。更新同一资料产生新版本；同名文件不直接覆盖，内容哈希相同不重复创建版本。
4. 展示名称、范围、读取状态、版本与更新时间。网页读取沿用现有公开网页/指定来源权限与访问限制；新增网址不等于扩大权限，失败保留原有效版本。
5. 每轮提供相关资料目录，实际读取工具按范围返回正文片段、版本与位置。聊天、后台研究和写作都可使用；大资料按片段读取，超限明确，不声称读完未读取的内容。
6. 正式成果和回复可定位本轮实际读取的资料版本。工作中资料更新不篡改本轮快照；删除/撤回阻止新的读取并使受影响的旧写入失效，已交付成果保留来源移除提示。
7. 每次添加一份资料，文本/Markdown 文件上限沿用现有文本附件的 2 MB；每位联系人最多 100 份有效资料，包含历史版本的正文存储上限 200 MB。单次工具最多返回 12000 字并提供下一段游标，目录不冒充正文。容量耗尽明确说明并允许整理，不能自动删除历史版本。导入可取消、失败保留输入；解析失败/格式不支持不生成「读取成功」。不依赖用户原始绝对路径作为持久身份。
8. 资料属于数据而非系统指令；不把文件内命令提升为工具授权，不允许路径越界、执行导入脚本或读取其他联系人的私有资料。

### F. 明确版本的联系人协作

1. 在成果上选择「交给联系人评审」，通过模态选择接收者并填写一个自然语言任务描述，来源是只读版本引用；复用公共任务描述输入，不出现另一套任务配置。
2. 主进程核对来源、共享与读取权限。未授权时说明缺项并打开原工作设置，返回后保留交接草稿；不能因发起交接偷偷打开全量共享。
3. 用户提交后在接收联系人下建立真实评审任务，持久交接记录绑定来源作者、任务、版本、分节范围及接收任务。源任务不被修改，作者不因交接自动续写。
4. 新版可用与当前评审版本分别展示。用户明确要求持续评审后沿用原调度与预算，对新增/改变的正文去重评审；普通一次性交接不自动成为持续任务。
5. 评审结果准确引用被评审正文，可从结论跳回原文。作者出新版时旧评审仍可追溯，不能显示成新版已评审。
6. 用户选择单份评审中的意见并交回作者，进入原任务修订流程；这是逐项/单次操作，不增加任务多选或批量操作。修改前检查源成果版本，过期意见不静默应用。
7. 交接状态来自真实任务/轮次：待接单、执行、待回复、已交付、失败/暂停等沿用现有状态投影。取消、重复点击、重启、权限撤回、删除均不能重复建任务、重发成果或复活已暂停任务。
8. ChouYu 可以引用交接中的真实阻塞和结果提醒用户，不能代替用户认可意见，也不替其他联系人执行修改。

### G. 技能能力说明与文件成果

1. 技能卡片展示人能理解的说明和使用示例，依据实际技能说明/能力报告，不按名称杜撰能力；来源说明与已验证运行状态区分。
2. 分别呈现安装、联系人启用、脚本授权、运行环境、依赖和外部条件。无需脚本的技能不被 Docker 缺失误判为整体不可用；脚本可执行不等于外部服务已连接。
3. 使用示例可填入普通任务描述弹窗，用户提交后才创建任务；不形成快速新建或隐藏启动入口。
4. 失败卡片能到准确设置/依赖/日志页，修复后返回原事项重试。环境就绪不自动标任务成功，原暂停和额度不被绕过。
5. 实际保存的工作文件按联系人、技能、任务/会话、轮次、哈希与版本归档，可在成果页/作品集预览文本和常见图片、下载或导出其他文件。目录区分「工作文件」和已被本轮正式交付引用的「成果文件」，不能把脚本输入、临时文件或任意文件写入当成完成交付。路径同名覆盖不能改变旧成果文件。
6. 仅导入经过现有隔离运行器校验的普通文件；预览 HTML 沿用沙箱，不自动执行脚本/打开外部地址；失败或取消的运行不假报成功交付。
7. 普通聊天产生的文件保留会话来源，任务生成的文件保留任务来源。现有无法证明归属的旧文件显示为历史工作文件，不推断轮次或伪造任务关联。

## 5. 数据与接口设计

所有新模块通过现有 `AgentAPI`、preload、IPC 注册白名单、worker RPC 和 `AgentService` 接入，服务端校验联系人存在、归属、任务版本和输入长度；渲染层不能直接访问 SQLite 或任意文件路径。

| 对象 | 持久字段与约束 | 接入位置 |
| --- | --- | --- |
| 记忆版本 | memoryId、owner、revision、content、kind、scope、scopeId、source、created/updated、有效/忘记状态；来源历史不可改写 | 独立 memories 存储模块，替换 store 的直接增删；保留旧 API 兼容 |
| 模型参考记录 | 请求/会话/消息或轮次、实际提供的 memoryId/revision、实际读取的 materialId/version/位置 | 聊天请求上下文与后台运行快照；完成时关联实际消息/成果 |
| 成果索引与个人状态 | 来源 task/version/section、正文哈希、搜索文本；收藏按 owner/task；阅读按 owner/task/version/section | AgentDeliveries 提交事务更新索引；作品集只读该索引 |
| 正文引用 | owner/topic/version/section、quote、正文哈希和选择锚点 | 聊天消息扩展字段及修订请求；原消息来源契约继续保留 |
| 资料及版本 | owner、可选 task、名称、类型、version、hash、正文/受管文件、读取状态、来源、更新时间、撤回标记 | 独立 materials 模块与有范围的读取工具 |
| 协作交接 | handoffId、source ref、receiver、receiverTaskId、用户要求、请求幂等键、创建时间；状态关联真实任务 | 独立 handoffs 模块，创建任务与交接记录原子落盘 |
| 成果文件 | owner、skill、task/session、run、相对名称、hash、大小、格式、受管副本与生成时间 | 技能工作文件写入/导出边界，关联正式交付并提供只读文件入口 |

新模块使用增量迁移及事务，禁止重建用户任务或移动真实用户数据来完成 UI 改造。数据库版本超过当前支持版本时继续拒绝写入。旧记忆按原所有者和真实来源迁移，不猜任务范围；旧成果建立可重建搜索索引，不生成假阅读记录；旧消息没有结构化引用时照常显示。

持久文件采用暂存 → 内容校验 → 原子落盘 → 元数据提交的流程，提交失败和重启恢复清理孤立暂存，不覆盖旧有效版本。删除仅操作应用受管路径，先验证规范化绝对路径和归属。

模型上下文由统一选择器构造，保留公共交流约定和联系人独立人设；正式要求优先于记忆和资料。新工具继承现有工具开关、确认策略与后台预算，不能通过普通聊天引用扩大写权限。

## 6. 实施依赖与分批交付

以下是模块拆分，不是缩减目标的阶段性替代。实现计划在设计审阅后补充具体文件、测试与提交顺序。

1. 公共数据引用、数据库迁移与联系人卡片/概览投影；同时修复空人设提示与记忆弹窗偏差。
2. 成果索引、作品集、收藏、正文搜索与持久续读，复用阅读组件。
3. 段落引用、消息持久结构、原文导航、版本核对和精确修订。
4. 记忆版本、适用范围、检索、聊天纠正与参考来源展示。
5. 资料存储、导入/更新/撤回、目录/读取工具及模型请求关联。
6. 交接任务、持续评审关联、版本可见性与意见交回。
7. 技能能力呈现、原问题往返及文件成果归档。
8. 完整 UI/IPC/重启/模型验证、文档状态同步和逐条完成审计。

所有模块共用身份、版本、引用和返回定位约定，避免每页另造一套导航或缓存。多个数据来源更新时采用请求代次保护，防止切换联系人后的迟到响应覆盖当前内容。
