# 联系人 SkillHub 接入设计草案

日期：2026-10-10。状态：用户已确认推荐范围并授权实施。实现与验收记录见 [联系人技能](../../contact-skills-20261010.md)；现行行为以联系人任务规范为准。

## 目标与已有约定

用户希望为本系统联系人接入 SkillHub 技能市场，并支持给不同联系人配置技能。预期闭环为：在联系人中搜索技能 → 查看说明 → 安装到 ChouYu → 为当前联系人启用 → 在聊天及后台工作中实际使用。

技能是联系人独立配置的工作方法，不替代人设、公共交流约定或任务要求。所有联系人（含 ChouYu）复用同一界面与后端。任务新建、编辑仍只有一个自然语言描述框；不增加任务级技能配置表单。保留成果正文投递、权限、额度、暂停和未读闪烁约定。

## 设计阶段调查事实（实施前）

- [官方接入说明](https://skillhub.cn/install/skillhub.md)提供 CLI 安装与 search/install 命令，要求显式指定技能目录。
- [官方安装脚本](https://skillhub-1388575217.cos.ap-guangzhou.myqcloud.com/install/install.sh)通过 Bash 安装 Python CLI；默认附带技能进入 OpenClaw 工作区。不能直接把该目录当成 ChouYu 的联系人技能目录。
- 本次只在内存中读取官方 latest 安装包及源码，包内版本为 `2026.8.5`。搜索及安装支持 `--json`，支持 `--skip-self-upgrade`、配置文件路径覆盖与显式 `--dir`。此版本是调查所得，实施时应固定并记录实际版本和文件摘要。
- 当前 Windows PATH 没有检测到 `skillhub`，有可用的 Python 命令；尚未执行任何第三方代码或安装脚本。
- 项目是 Electron + React。当前没有联系人技能库、技能关联或技能加载器。
- 普通聊天模型入口位于 `src/main/ipc.ts`；后台联系人身份由 `src/main/agents/index.ts` 传递到 `service.ts`，执行在 `runtime.ts`；ChouYu 晨报和工作检查位于 `src/main/assistant-routines/`。必须覆盖这些入口，不能只改聊天提示。
- 现有后台执行器支持受控的网页研究、写作及成果协作，并非通用 Shell/Python Agent。安装含脚本的技能不会自动获得这些执行能力。

## 接入方式比较

| 方案 | 优点 | 代价与适用性 |
| --- | --- | --- |
| 官方 CLI 适配 + ChouYu 技能库（推荐） | 遵循用户指定渠道，复用官方搜索与下载；应用负责联系人隔离和技能使用 | Windows 需要 Python 启动适配与运行环境检测 |
| Electron 直接访问商店接口 | 可减少外部运行环境依赖 | 安装文档没有给出稳定的完整 API 契约，需要自行维护与服务端的兼容性 |
| 只打开 SkillHub 网页、人工下载 | 接入工作较少 | 无法完成应用内安装和联系人实际使用闭环，不满足本次目标 |

推荐使用第一种，商店适配器与技能运行器解耦，后续如有正式 API 可替换下载实现。

## 用户界面

在联系人现有详情导航增加“技能”页，使用共同的 `ContactAgentPanel`，显示“已配置”和“技能市场”。这是联系人能力配置，不放进任务设置。

市场支持关键词搜索、查看详情和单项安装。详情弹窗展示技能说明、来源、可获得的版本信息、依赖与支持状态，提供明确安装/取消操作。信息缺失如实显示未知，不能伪造安全评级。关闭支持 Esc；请求失败保留搜索和当前详情。

安装与启用分开：安装进入应用共享技能库，用户为当前联系人启用后才生效。已配置项支持查看内容、停用和移除关联；这些操作不删除其他联系人的技能。应用库卸载显示实际引用联系人，仍被使用时要求先移除关联，避免破坏其他联系人。

新联系人默认没有启用技能，但继续自动继承公共交流约定。相同技能可由多个联系人使用，各自的启用状态互不影响。搜索/安装失败明确原因；只有文件验证和持久化都成功才显示已安装。

## 数据与下载

- 应用数据目录保存 SkillHub 适配配置、技能文件和安装清单。技能库与 Codex/OpenClaw 的个人目录分离，所有安装显式传入 `--dir`。
- 技能记录包含稳定来源标识（含命名空间）、名称、说明、可得版本、内容摘要、实际安装时间、相对目录、依赖声明和兼容性说明。没有发布版本时使用内容摘要识别本地快照，不捏造版本号。
- 联系人关联独立存储，包含联系人 ID、技能 ID、启用状态和修改版本；主进程验证联系人存在，拒绝旧版本覆盖。删除联系人清理关联，共享文件按引用保留。
- 使用官方固定版本 CLI，以参数数组启动 Python，不使用 Shell 拼接。Windows 无需用户在 WSL 中安装另一套商店。缺少 Python 或版本不可用时展示可操作的环境错误，不能把搜索失败当成零结果。
- 使用应用专属 CLI 配置，关闭后台自升级和默认工作区技能注入；本接入不修改 Codex、OpenClaw 或其他应用的技能源优先级。
- 下载进入临时目录，完成大小、目录边界、符号链接、`SKILL.md` 和内容校验后再原子发布。异常归档不能影响现有安装。更新同样保留旧可用版本，失败回滚。
- IPC 只接受经过验证的技能引用，不接收渲染端提供的可执行命令或任意本地路径。每项操作有超时、取消及输出上限，同技能安装互斥。

## 联系人运行时

建立共同技能解析服务，由服务端按真实联系人 ID 加载启用技能及确定版本，不能由前端消息冒充其他联系人的技能。

技能与人设、公共规则分别组装。技能不能改变联系人身份，不能覆盖当前任务、权限、输出格式及成果持久化协议。规划和 JSON 输出仍服从各自机器契约；消息交付引用已保存正文，不新增逐消息润色调用。

聊天在请求开始时取得技能快照。后台任务在开轮时保存技能引用及内容摘要，恢复轮次使用该快照；更换技能不会把新旧版本混进同一轮。停用/移除影响下一次聊天及新轮次，界面明确“当前轮次沿用原配置”。真正的权限撤销继续遵循现有中止规则，不能靠技能配置扩大权限。

ChouYu 的模型生成晨报、问候工作检查使用同一技能解析；固定提醒文案不为应用技能额外调用模型。市场网络故障不影响已经安装并配置的技能。

技能说明和引用资料需要内容长度预算及明确错误，超长不能静默截断关键要求。读取资源仅限对应已安装技能的目录，不能借相对路径进入另一联系人数据、应用凭据或任意磁盘路径。

## 已确认的首版执行范围

用户已确认首版支持 `SKILL.md` 工作方法、技能内文本参考资料，以及当前运行场景已提供的工具。需要脚本、额外二进制、未连接服务或密钥的技能展示依赖与暂不可用原因，不声称完整兼容。

Python/Shell 脚本及依赖安装不属于此次确认的首版范围。以后增加时需要独立执行环境、文件访问范围、进程取消、凭据传递和后台授权语义，不能通过开放一个任意 Shell 工具来替代设计。

## 验收与文档同步

1. 实际安装/探测固定 CLI 版本，验证真实 SkillHub 搜索和选定技能的下载；真实网络检查与模拟测试分别记录。
2. 两个联系人配置不同技能，验证聊天、后台成果及 ChouYu 模型生成安排的隔离；停用和重启后状态正确。
3. 验证安装失败、超时、坏归档、缺失说明、目录越界、写入失败、重复安装及并发设置不会误报成功或损坏旧版本。
4. 验证技能配置不串用人设、私聊、成果，不绕过工具权限、资源额度或暂停状态；记录轮次使用的真实技能快照。
5. 对依赖脚本或外部服务的技能，以最终选定执行范围验证可用性；不能以提示注入测试代替实际执行验收。
6. 运行相应单元/集成测试、`npm run typecheck`、`npm run build`，以及联系人和助手安排冒烟。UI 使用隔离数据实际操作，检查深浅色、375/1024 宽度、键盘和失败状态。
7. 受影响现行验收项：UI-01/02/03/04/05、NL-04、RUN-02/03、RES-01、MSG-01/03/04、SCOPE-01。补充技能安装、关联、加载和隔离验收条款。
8. 实施前在 `docs/contact-task-spec.md` 补充最终行为；实施后同步其第 10 节真实实现状态、`docs/contact-topics.md` 和 `docs/contact-agents-architecture.md`。本草案不表示这些能力已存在。
