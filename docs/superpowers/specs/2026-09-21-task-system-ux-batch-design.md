# 任务系统 UX 批次设计（2026-09-21）

对应「任务系统」清单 4 个待办：视图手动收纳+拖拽排序、卡片菜单统一、子项升级（截止时间+提醒）、侧栏分割线拖拽。全部改动在 renderer + shared + 主进程提醒扫描，不动 tasks.db 表结构（子项扩展存于任务自身 checklist JSON）。

## 1. 视图管理：手动收纳 + 拖拽排序

现状：智能视图（今天/本周/待规划/全部/过期）顺序固定，侧栏显示数量由 `visibleViewCount` 按高度自动计算，溢出项与自定义视图全部进「更多」弹层，用户不可自定义。

设计：

- 新增 localStorage 配置 `chouyu:task-view-config:v1`：`{ order: string[]; hidden: string[] }`。
  - 视图 key 复用现有 Selection 形式：智能视图用 id（`today`、`week`、`unplanned`、`all`、`overdue`、`done`），自定义视图用 `view:<id>`。
  - 默认值 = 现有侧栏顺序：今天/本周/待规划/全部/过期 显示，`done` 与自定义视图默认收进「更多」（与现状一致）。配置中出现已删除的自定义视图 key 时静默忽略；新建自定义视图默认追加到「更多」。
- 「更多」弹层顶部新增「管理视图」入口，打开管理弹层（复用现有 tasks-dialog 样式）：
  - 列出智能视图 + 自定义视图；每行 = 拖拽手柄（复用 `useTaskLayoutOrder` 拖拽模式）+「显示在侧栏」勾选框 + 视图名；自定义视图行保留现有编辑/删除按钮（从「更多」弹层迁入）。
  - 勾选状态直接写回配置；拖拽排序写 `order`。
- 侧栏顶部只显示勾选视图、按 `order` 排列；未勾选的进「更多」弹层（保持现有编辑/删除/新建入口）。
- 删除 `visibleViewCount` 按侧栏总高自动计算的逻辑；改为以「视图区当前高度」为预算的自动收纳：拖拽设定 px 高度时按该高度计算，未设定（auto）时沿用原公式（侧栏高的 52% 与「侧栏高−头部−120px」取小），放不下的视图自动收进「更多」（运行时计算，不持久化）；视图区 `overflow: hidden`，永远不出现滚动条（2026-09-21 验收修正：替换原「区域内滚动」方案）。
- 当前选中视图被收进「更多」时，「更多」按钮显示该视图名（沿用现有 `hiddenViewSelected` 行为）。

## 2. 卡片按钮统一为「⋯」菜单

现状：列表卡与看板卡右侧是铅笔「快捷编辑」按钮（改优先级/清单/日期）；列表卡另有「更多」菜单（编辑/删除），看板卡没有菜单。

设计：

- 列表卡与看板卡统一：右侧一个「⋯」菜单按钮，菜单含「编辑任务」「删除任务」。看板卡补上与列表卡一致的 `details` 菜单结构；删除走现有 confirm + 回收站流程。
- 删除 `TaskQuickEdit` 组件及其在两处的使用；`rescheduleTaskDate` 等仅被其引用的工具函数一并清理。改优先级/清单/日期一律走编辑弹窗。

## 3. 子项升级：可设截止时间 + 提醒

现状：`TaskChecklistItem = { id, title, done }`，纯勾选；编辑器仅底部一行添加；卡片显示「子项 x/y」；「子项不单独提醒」。

设计（轻量嵌入方案，子项仍是父任务附属，不进视图、不可拖拽）：

- `TaskChecklistItem` 扩展为 `{ id, title, done, dueAt?: number | null, reminders?: TaskReminder[] }`，存于任务 checklist JSON，无 schema 迁移；`validateTaskChecklist` 扩展校验并向后兼容旧数据（缺字段视为无时间/无提醒）。
- 子项天然扁平 = 最多一级子任务；编辑器不提供嵌套入口。
- 编辑器子项行右侧操作区：截止时间按钮（弹出日期+时刻选择，可清除，时间非法时与任务同样的校验提示）→ 提醒按钮（基于子项截止时间的提前量选项，复用任务级提醒选项；子项未设截止时间时提醒按钮禁用）→「×」删除。
- 子项行 hover 时行尾显示「+」按钮，在当前行下方插入新子项；底部添加行保留。
- 卡片展示：保留「子项 x/y」；存在过期未完成子项时追加红色「n 个子项过期」。
- 提醒管线：`claimDueReminders` 扩展为同时扫描任务级与子项级 reminders，原子记录每个提醒的 fired 状态，同一轮积压按任务合并（现有规则不变）；通知文案为「任务标题 · 子项标题」。
- 重复任务生成下一期时，子项 `done` 与提醒 fired 状态一起重置（现有逻辑已重置 done，补上提醒重置）。

## 4. 侧栏分割线拖拽调高度

现状：`.tasks-sidebar` 整体滚动；视图区显示数量自动计算；视图区与清单区之间是固定 `border-top`。

设计：

- 侧栏改为三段：视图区（高度 = 持久化 px 值，放不下的视图自动收进「更多」，区域内不出滚动条）+ 中间拖拽手柄 + 清单区（flex:1，内部滚动）。
- 手柄：外观保持原有 1px 通栏边框线样式（hover 仅加深线条颜色），命中区 9px 高、`cursor: row-resize`，支持鼠标拖拽实时预览与键盘上下方向键微调（10px 步进）；拖拽范围限制为侧栏高度的 20%–80%（2026-09-21 验收修正：不引入新的手柄外观）。
- 高度存 `chouyu:task-sidebar-split:v1`（视图区 px）；双击手柄或 Delete 键恢复 auto（按内容自适应，即现状行为，此时清除存储值；auto 模式按上述预算公式自动收纳，视图区不出滚动条）。
- 窄屏纵向布局（≤640px）禁用拖拽，保持现状整栏滚动。
