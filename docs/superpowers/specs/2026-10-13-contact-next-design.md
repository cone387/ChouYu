# 联系人下一阶段完整优化

依据：用户在联系人评估后要求「全部做好」。范围包含评估中的五项优化及联系人卡片直达；现行产品权威仍为 `docs/contact-task-spec.md`。本文件细化实施边界，不将待实现能力改成用户批准的例外。

## 1. 聊天调整

支持当前联系人的工作方式（按需、连续、间隔）、工作时间、每日调用及 Token 上限、同时推进数，以及单任务解除 Token 上限、结束/放弃与删除。已有目标、约束、修订、回复操作继续复用。

- 无任务的联系人也能修改工作设置；不为普通闲聊创建任务。
- 设置使用字段白名单与完整校验，补丁只修改明确提出的字段，应用到读取时的版本。保存失败或版本变化不承诺成功。工具关闭、确认策略、取消和会话归属继续生效。
- Token 上限可明确解除；调用次数保护不隐式移除。若用户笼统说「所有额度不限」，解释调用次数保护，不能半保存后称全部完成。
- 结束保留成果和历史并取消该任务的在途执行；结束不等于验收通过。删除沿用当前删除范围和单任务明确确认，展示将删除的实际内容，不能通过普通聊天绕过确认。
- 多任务歧义先追问，混合不能原子完成的操作先说明；不凭当前焦点猜对象，不自动恢复暂停或结束任务。
- 原始用户要求和实际回执可追溯，用户看不到内部 JSON 参数。

## 2. 分批全文结束核对

有限目标的结束核对覆盖全部合并后的正文（保存版本加本轮拟提交分节）。超过单次容量时按分节和必要的分节片段分批，每批不超过 60,000 UTF-16 字符且不切断代理对。较短任务保持原有一次核对路径。

- 每批返回严格校验的范围回执、事实依据、缺口和支持的要求；全局结束判断同时看到原始要求、完整目录、各批回执、分节关联及跨章节问题。
- 分批通过不是整项完成，只有所有批次实际核对且最终判断通过才能结束；失败、无效回执或预算不足保留真实阻塞及已有正式成果。
- 以需求、正文内容、顺序及核对协议的摘要关联持久检查点。重启、重试或新一轮复用未改变的批次，正文修改仅重查受影响批次；要求改变全部失效。最终综合结论在任意相关变化后重做。
- 所有模型调用计入原任务/联系人预算，使用原有 Token 预留；取消、删除、修改后迟到结果不保存。持续任务仍不能以本轮产出为终点。
- 工作记录显示真实已核对范围、剩余范围和原因，不将内部回执当聊天成果。

## 3. 自然语言定时

共享日历规则支持每天、工作日、每周、一次性、每月指定日、每隔 N 个日历日，保留每个周期最多 5 个时刻。按本机当地日期计算，不以固定毫秒表示一个日历日。

- 每月 29–31 日在不存在该日期的月份跳过，不擅自换为月末；「每月最后一天」用明确的月末规则表示。
- 每隔 N 天需要持久起始日期；用户明确「从今天起」以请求当地日期为锚点，缺少必要起点才追问。编辑保留未修改锚点。
- 唤醒、重启或离线错过多次时，默认补一次最近到期执行，保留原计划时间与实际启动时间，随后回到原日历节奏；不密集补发全部历史。不把重试当新一期。
- 普通联系人拥有自己的定时任务，时间到达后经现有任务队列执行一轮；不改由 ChouYu 扮演该联系人。调度规则公共化，工作引擎保持原有实现。
- 定时约定必须实际保存，不能写成普通约束冒充调度。排队、待回复、失败退避、工作时段、预算、暂停/结束规则仍约束执行；同一任务不重入，不跳过尚未解决的必要问题。
- 新建/编辑/聊天统一走解析与校验，公共列表、详情、历史、快捷操作读取真实状态，不新增安排面板或多字段表单。

## 4. 查询与渲染性能

同一联系人同类数据共享读取、变化事件合并及在途请求；后到旧响应不能覆盖新联系人或新版本。保持现有只读补刷新作为连接恢复保障。

- 隐藏标签、保留返回上下文的旧页面停止非必要轮询；返回时补读取，窗口重新可见时校验状态。
- 资料、成果固定版本、草稿、滚动和焦点在切换与刷新后保留。
- 以隔离数据测量 30 位联系人、每人 20 个任务，以及较长成果/聊天的 IPC 数、刷新延迟和进程内存；记录环境、样本及前后结果。只有测量证明需要时才加虚拟化，不用人为减少成果容量通过性能验收。
- 对相同交互路径，同类并发读取最多一条；仅打开一个联系人时，隐藏页面不产生各自每五秒查询；操作后的可见状态更新不能因此延迟到下一次轮询。

## 5. 联系人卡片直达

姓名、头像及普通卡片区域继续打开聊天；「等你回应」打开准确的原待处理事项/原问题，「最近交付」打开该摘要对应的固定成果版本。交互区域用独立可访问按钮，不嵌套按钮。

目标来自真实结构化引用；目标删除或失效明确提示，不打开同名对象。返回保留筛选、排序和位置。深浅色、375/1024 宽、键盘、鼠标均可用；不增加批量操作或降低主动未读闪烁。

## 6. 运行验收与完成条件

隔离应用与数据库中贯通持续写作、独立评审、ChouYu 检查，覆盖跨日、断线、重启、取消、资料撤回、运行中修改及并发；检查执行历史、正式成果、通知来源、回执去重、预算结算和实际状态。

- 真实模型测试与可重复夹具分别记录；使用已配置模型时不得输出密钥或修改真实联系人任务。记录模型、用量、持续时间、失败和实际正文证据。
- 实际持续运行至少 24 小时，跨过本地午夜；系统休眠/唤醒使用隔离虚拟环境或获得当前宿主允许后操作，不擅自休眠用户电脑。受控时钟测试只能证明规则，不能冒充真实跨夜证据。
- 原生托盘逐类验证问候、回来、休息、个人提醒、定时和联系人交付/失败：送达后未读闪烁，点击正确定位，读后停止；不同消息不因类型降级。
- 真正不可用的环境保留具体缺口和复现入口，不勾选完成。全量单测、类型检查、构建及相关 Electron 集成通过，UI 变更实际交互并看截图。
- 最终独立代码审查、修复和总回归；同步唯一规范、使用文档和验收记录。实现、模拟验证、真实运行验证分栏，所有六项都有对应证据后才宣布全部完成。
