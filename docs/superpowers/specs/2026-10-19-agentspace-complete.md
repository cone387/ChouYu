# AgentSpace 完整模块化设计

用户要求：把上一轮列出的剩余模块化工作全部处理好。以下为完整目标，不以单个阶段完成代替全部完成。现行产品规范 `docs/contact-task-spec.md` 与 AGENTS.md 持续生效。

## 结构与职责

应用层 AgentSpace 是联系人组合根，持有 ContactAgent。每位联系人按能力装配 Chat、WorkLoop 等模块，提供独立取消、卸载和关闭。Chat 模块承接现有聊天流与 Harness 协调器；WorkLoop 模块通过进程端口连接共享 worker。原 worker 中的 AgentSpace 改为 WorkLoopHost，负责后台执行资源、持久化与恢复，不再冒充完整应用空间。主进程身份是配置权威；worker 使用执行快照，不独立决定联系人配置。

系统级 TaskCenter 注册联系人工作、用户待办、助手安排三个任务域。统一任务引用带 domain、owner、id；查询、能力检查及操作分派进入同一服务。各域模块保留已有数据库事务、自然语言解析、周期生成与执行历史，不复制任务或以一个通用状态覆盖各域语义。现有 UI、工具与调度入口实际接入该中心；只有接口定义或目录搬迁不算完成。

Harness 为执行能力模块。原生与 DSH 后台都必须逐次请求预留、结算、限额和取消；DSH 实际 SDK 多轮工具请求进入同一计费契约，不可静默降级原生或只在整段会话记一次账。配置由联系人设置保存，聊天与后台选择的作用域明确，变更不追改在途请求，下一次执行读取新配置。

## 生命周期与可靠性

联系人删除或模块卸载停止对应在途工作，等待真实退出；联系人之间不互相阻塞。应用关闭按模块依赖逆序清理，并等待 worker / DSH 子进程退出。模块错误应保留真实失败和重试边界。暂停、任务编辑、删除后的迟到结果不能覆盖现态，旧消息不能复活。

针对已观察到的 SQLite WAL 重启 I/O 错误，先用隔离数据与进程故障注入定位；根据证据修复启动资源回收或恢复流程。不可通过删库、吞错或把所有存储异常当瞬时错误解决。保留诊断，但不得记录密钥、私聊正文和供应商原始敏感响应。

## 验收与完成定义

1. 普通聊天的真实 IPC 入口经过 ContactAgent.Chat；后台工作经过同一应用层联系人实例的 WorkLoop 端口；卸载、删除、取消和关闭覆盖真实流及工具。
2. 三类任务的真实业务入口接入 TaskCenter，保留单任务版本、归属、重复调度、成果与持久投递语义。共同 UI 与单描述弹窗不回退。
3. DSH 后台可在联系人界面选择并实际运行；真实 SDK 对本地协议服务器的多轮请求证明额度、输出上限、工具、撤销与未知用量处理有效。
4. 启动/退出/硬终止恢复压力测试与真实 Electron 回归通过；已知间歇错误有诊断和针对性验证，不仅依靠一次重跑成功。
5. 使用隔离测试联系人和独立数据，进行真实模型至少 24 小时持续运行验收，包含原生与 DSH、任务产出及读取、实际计费记录、暂停与重启恢复。使用有界调用和 Token 额度；不得触碰用户真实任务或把夹具测试当真实模型结果。未到 24 小时不标完成。
6. 全量测试、类型检查、构建、联系人/聊天/助手安排/主动检查的 Electron 冒烟通过；独立审查修正重要问题，更新架构、产品实现状态及验收证据。

本任务完成前持续保留上述全部验收项；软件平台仍为当前 Windows 桌面应用，退出/休眠期间不宣称工作，不扩大为系统服务或云执行器、插件市场或第三方代码加载。
