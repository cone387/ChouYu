## 最新：完整记忆数据操作（2026-09-09）

列表分页之后，补齐内部完整数据操作：按规范化键直接查询已有活跃/待审核记忆，避免在最近 2000 条之外漏掉已有记录；新候选冲突检查、导入预览和待审核重试不再受列表页上限影响。Mem0 的确认新增复用同一查找，旧候选有未处理冲突时不会绕过审核。

本地导出在 SQLite 读取事务内遍历完整记录，包括活跃、待审核与归档状态。统计、身份维护及向量重建也采用完整读取；界面主题聚类仍保留原有最多 2000 条活跃记忆的分析范围，本次不改动其算法和预算。本地活跃记忆容量仍为原有最大 2000 条，不将它误当成所有状态或 Mem0 缓存的总条数上限。

完整导出不等于放宽单次导入预算：导入仍限制 5 MB 文件和 2000 条记录，超出条数明确拒绝并要求拆分，避免此前只预览前 2000 条的静默截断。Mem0 导出的是当前完整本地缓存；需要包含尚未缓存的远端记录时，先刷新远端列表。

验证：450 项单测、类型检查、构建和完整 Electron 回归通过（`temp/memory-full-data-smoke.log`）。本地 SQLite 验证 2101 条活跃/待审核记录完整导出；实际 Mem0 provider 配合隔离 SQLite 缓存验证 2102 条完整导出、旧活跃记录去重、旧冲突处理及排在 2100 条新候选之后的导入重试。旧缓存复用没有额外网络请求，超限导入不截断。测试没有访问用户托管账户。

## 此前：显式平台 V3 支持

平台模式的 Base URL 以 `/v3` 结尾时启用 V3：列表 POST `/v3/memories/`、搜索 POST `/v3/memories/search/`，查询范围放在请求体 `filters.user_id`；新增 POST `/v3/memories/add/`。单条编辑、删除仍使用官方 `/v1/memories/{id}/`，事件查询仍为 `/v1/event/{id}/`。支持代理路径前缀。V3 列表每页请求 200 条，必须提供分页元数据；分页始终保留同一请求体过滤范围。V3 搜索失败不退回旧路径。

使用方法：在连接设置选择 Mem0 平台，将 Base URL 设为 `https://api.mem0.ai/v3`，测试连接后在记忆库刷新远端列表。现有配置和默认值不自动迁移；地址参与缓存隔离，切换后先加载新地址对应缓存，不删除原地址缓存。自托管模式仍用原协议，即便其服务路径恰好名为 `/v3`。

本地 HTTP V3 测试服务与真实 SQLite 已验证两页列表、用户隔离、带 filters 搜索、同步新增、RUNNING 到 SUCCEEDED 的异步新增、事件仅确认一次写入、V1 单条管理及认证失败保留缓存。426 项单测、类型检查、构建和完整 Electron 回归通过（`temp/mem0-v3-smoke.log`，`CHOUYU_MEM0_V3_SMOKE_PASSED`）。没有访问用户 Mem0 平台账户，因此实际托管服务、代理部署及异步事件跨重启恢复仍未验收。下方未迁移说明属于此前阶段。

协议依据：[列表](https://docs.mem0.ai/api-reference/memory/get-memories)、[搜索](https://docs.mem0.ai/api-reference/memory/search-memories)、[新增](https://docs.mem0.ai/api-reference/memory/add-memories)、[编辑](https://docs.mem0.ai/api-reference/memory/update-memory)、[删除](https://docs.mem0.ai/api-reference/memory/delete-memory)。

## 历史阶段：手动刷新接入

本节记录 V3 支持完成之前的刷新阶段；其中 V3 待迁移项已由上方“显式平台 V3 支持”完成。

记忆库新增“刷新 Mem0 远端列表”。读取后在 SQLite 事务中导入或更新远端返回的正文与归档状态；总数核对完整时，移除有远端映射且未返回的非候选缓存。未提供总数的旧式响应只更新返回条目。认证失败、分页失败和映射冲突不提交缓存改动；本地候选不会因远端缺失而删除，连接或凭据改变后丢弃旧请求结果。

## 历史阶段：初次核对及适配器基础

本节记录补齐体验前的实际缺口与第一批适配器改动。完整刷新、对账及显式 V3 支持后来已经接入，当前状态以上方总览为准。

2026-09-09 初次源码核对：管理界面 `memory.list` 仍读取 Mem0 provider 继承的 SQLite 缓存列表；聊天通过远端搜索填充缓存。完整列表刷新、远端删除对账和刷新状态展示尚未接入。

本批补齐现有 GET 列表适配器的分页读取：支持原有数组、results、memories 等响应及嵌套 data 列表；有 `next` 时读取后续页。存在 `count` 时校验非负整数、跨页一致及最终条数。缺少 ID/正文、重复 ID、空页却仍有下一页、循环链接及后续页失败均报错，不返回已读的部分结果。既有编辑、删除确认及兼容召回也会使用该列表方法。

分页链接只允许当前来源站点与列表路径，保留配置的 user_id，拒绝其他用户值及重定向，避免凭据跟随分页跳到其他服务。整次读取共用 30 秒期限，调用方取消信号不能取消该期限；即使传输忽略取消，也不接纳晚到结果。最多 100 页、20000 条，超过时明确失败。

没有分页元数据的旧式数组无法证明服务端没有隐式截断，当前仅保留已有兼容解析。因此本批不接入“列表中不存在就删除缓存”的逻辑。后续对账还需定义完整性证据、远端 ID 映射、事务替换、配置切换和失败保留规则。

## 远端属性后续

缓存更新现包含 ChouYu 定义的类型、重要度、敏感标记、启用/归档状态、有效期及来源会话/消息 ID。缺失字段保留已有缓存值，新条目采用默认值；有效期和来源字段明确为 null 时清除。枚举、重要度范围、毫秒时间戳和来源 ID 类型/长度无效时失败，列表刷新事务不会部分提交。未知第三方字段不映射到本地属性；本地创建/更新时间及修订记录仍表示缓存行为，不冒充远端时间。

## 平台 V3 写入确认基础

官方 V3 新增接口的推理写入可能先返回 event_id/PENDING；infer=false 文档说明可同步返回。事件查询仍使用 GET /v1/event/{event_id}/，完成状态是 SUCCEEDED。[新增接口](https://docs.mem0.ai/api-reference/memory/add-memories)、[事件接口](https://docs.mem0.ai/api-reference/events/get-event)。

现有适配器在原始写入及批量写入返回事件 ID 时，会向同一服务的事件路径查询，核对 ID 与 ADD 类型。PENDING/RUNNING 继续等待，FAILED/未知状态/畸形结果不作为成功；每次事件确认最多 30 秒、30 次查询，每次间隔 1 秒，可取消。轮询不重复 POST；缺少事件 ID 的待处理响应明确报错。已被远端接收的操作可能在取消或超时后完成，应先刷新确认；本版没有持久化事件 ID 或跨重启恢复轮询。

（历史记录）默认配置和现有读写 URL 当时尚未迁移到 V3，同步旧式响应也仍保留既有路径。该阶段缺口后来已由上方“显式平台 V3 支持”完成；实际托管服务验收仍按当前状态总览保留。

事件确认验证：423 项单测、类型检查、构建及完整 Electron 回归通过（`temp/mem0-event-smoke.log`）。新增用例验证等待状态转换、失败、错误 ID/事件类型、未知状态、取消、查询次数上限和旧同步响应；适配器测试验证一次 POST 后只向原服务发 GET。没有调用用户平台账户。
