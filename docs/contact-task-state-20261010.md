# 持续任务状态与结束核对（2026-10-10）

用户指出：持续生产 idea 与持续评审任务不应在汇报中统称“尚未完成”，单次交付不是整个任务的终点。本轮受影响条款：RUN-02、RUN-03、RUN-05、RES-01、MSG-02、UI-05、SCOPE-01。

## 已实现

- `taskState` 统一投影任务生命周期、实际轮次、调度、失败及资源需求。联系人列表、详情、ChouYu 问候/回来检查、定时晨报复用状态，区分正在推进、等待新内容、等待下一轮、排队、待回复、暂停、结束和阻塞。
- 不从本轮 `completed` 推断任务结束，不用“尚未完成”概括正常持续任务。暂停/结束优先于旧轮次的待回复状态；列表摘要、详情待回复区域、顶部操作和启用计数同步处理。
- 每任务暴露真实调度时间、资料等待标记，以及首轮/恢复所需调用次数与已记录的 Token 请求预留需求。每日上限本身过低与今日剩余额度不足分开，不能错误承诺明日一定恢复。
- 普通生成、接单和修订共用持续任务约定。仅模型拟议 `completed`/`abandoned` 时，在提交前追加一次结束复核，核对原要求、需求修改时间、保存正文与本轮拟稿。没有指定终点的持续工作保持推进；明确限时才校验系统时钟；普通有限任务仍可通过核对后结束。
- 复核判定继续时保留实际正文，只修正生命周期、下一步与完成条件。复核失败或额度不足不写入未经核对的成果，也不结束原任务；已有成果保留。复核计入原调用/Token 额度，决定存入原轮次供恢复复用；暂停、修改或删除后的迟到决定不能覆盖现状。
- 用户修改时间只从实际改变目标/约束的历史读取，不把改名、交付方式调整或自动进展时间作为相对期限起点。最多提供最近 20 次要求变化，并明确历史是否截断；缺少可靠起点不能猜测截止时间。

## 验证边界与剩余能力

本轮使用本地模型夹具，没有调用真实供应商或执行全天持续监督。自然语言任务终点与截止时间的语义仍依赖模型，程序保证时钟检查、格式校验、保守拒绝、原始要求和证据提供，不声称语义零误判。

有限任务结束复核单次正文容量为 60000 字，按真实分节合并旧正文与拟稿，遗漏 ID 显式提供。未读完时即使模型声称达成，也不能结束有限目标；多批全文验收仍未实现，不应把容量限制当成用户批准的永久例外。限时要求在拟议终止时核对，没有新增到点强制终止调度器。

没有改写旧聊天、自动恢复暂停/结束任务，或直接改动用户正在运行的任务要求。没有新增任务表单字段、快速新建、批量操作或发布安装包。
