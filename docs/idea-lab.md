# 24 小时 Idea 实验

开发版本在应用完全退出后运行 `npm run build`，然后运行 `npx electron . --idea-lab`。该参数显式创建两个普通联系人及普通任务；普通启动不会创建实验。重复运行不重置或重复创建已启动的实验；未到期、持续工作仍开启且最近一轮失败时，会重试这一轮，不恢复用户已暂停的任务。

- 阿想 · Idea 实验员：小团队可实现的 AI 产品 idea，15 分钟一轮，每日最多 240 次模型调用，共享任务成果。
- 阿衡 · Idea 评审员：根据任务描述自行检索资料、读取原文、制定评分维度与权重、评价并引用来源。15 分钟检查一次，每日最多 400 次模型调用，允许读取共享成果。
- 两人沿用阿笔的供应商档案和模型（无阿笔时使用默认联系人）。模型调用会产生现有供应商的实际消耗。任务累计预算由接单规划估算，仍受联系人额度约束。
- 持续工作在创建实验后 24 小时自动关闭，调度检查精度约 15 秒。电脑需要保持唤醒、应用需要保持运行；不补跑离线时间。到期不删除成果，手动运行仍可使用。可在工作设置中提前关闭或取消截止时间。

## 通用能力与任务解耦

没有绑定生产任务和评审任务 ID 的特殊订阅。规划器有两项通用只读动作：

1. `discover_contacts`：按联系人名称、任务标题或分节标题检索共享成果。空 query 列出所有；多个词需同时匹配。返回最多 30 个分节目录、具体 ref 和当前任务是否已处理，未处理优先。
2. `read_contacts`：由模型从目录选择最多 3 个 ref，精确读取联系人、任务、版本、分节对应的正文。只读已共享的成果，不开放私聊、独立记忆或凭据。

每轮最多两次目录检索。首次检索、选择与分析通常需要 3 次模型调用，均计入资源预算。新轮次可重新规划数据来源。系统不会根据标题直接生成评分。

开启联系人成果读取的工作，每次模型响应最多 4,000 token，其余工作沿用 2,200 token；这是输出上限，不是固定消耗。评价正文只写入成果分节，报告只保留变化摘要，避免重复正文挤占 JSON 输出空间。

成功报告保存读取时的正文、来源版本及内容指纹。相同分节内容已被本任务成功处理时跳过；原文变化后可再次评价，失败的评价不消耗去重资格。已完成一轮后，调度器复用该轮模型选择的查询检查是否有新内容；没有新内容时不调用模型。首次发现来源仍需要规划调用。手动重跑也会进行规划。

模型负责评分规则和结论，系统记录引用并控制权限、额度、检查间隔与截止时间。评分是模型判断，不能当作市场验证。当前仅支持共享的任务成果和已有网页能力，尚未加入任意本地文件读取。

## 评分计算校验

规划器在需要打分的轮次选择 `evaluation: true`，分析阶段必须返回结构化 `evaluations`，缺失或不合法时不能保存为已校验评分。维度、量表和权重仍由 agent 自行制定，系统不固定业务评分标准。

系统校验维度名称不重复、分数不超出量表、权重为正且合计 100%、引用编号属于本轮实际读取的资料，再按 `Σ(score / maxScore × weight)` 计算百分制总分，最终四舍五入至两位小数。不同维度可以采用不同满分。无资料的主观评分可留空引用，成果会明确标注。

正式评分表和总分由程序生成，写入报告及成果版本，导出也使用同一份正文。模型不再重复手写表格或总分；若返回 `claimedTotal` 且与计算不符，系统保留原值并标出校正。例如首轮的分项应得到 71.75，而非模型原报的 68。权重或分项不合法时不自动归一化或裁剪。

历史纯文本评分保留原样，不通过猜测 Markdown 格式改写旧记录。只有新生成的结构化评分带有计算校验；没有选择评分计划且未输出结构化分项的普通文本不属于这一保证。算术正确也不代表维度选择或主观分项判断正确。
