## 源码中确认的设计

| 维度 | Mac | Windows |

## 不能直接照搬的部分

1. 用户目标是尽可能找回工作经历。Windows 默认分析后删除原始视频及窗口记录，会失去再次查看细节的依据；ChouYu 应按用户的保留期限和容量清理，不能把“总结成功”当作删除原始记录的条件。
2. Windows 的 15 分钟配置是批次时长上限，不是最低积累时间。调度会处理不足该时长的剩余批次；每段也分别调用视觉分析。费用必须按实际帧数和调用数统计。
3. Windows 所称关键帧实际是均匀采样，可能遗漏短暂内容；固定 1280×720 缩放会影响不同宽高比和多屏文本的可读性。应保持比例，针对每屏或窗口处理。
4. Mac 的 HEVC 存储估算来自其实现和硬件，不能当成 Windows 的实测结果。截图采集频率、存储编码方式和 AI 分析频率应独立配置。
5. 不把模型的生产力分数当作客观工作成果，也不根据应用名称直接判断用户是否在工作。
6. 项目许可证文本分别标为 Mac MIT、Windows CC BY-NC-SA 4.0。本轮仅参考架构，未复制第三方实现。

## 建议的 ChouYu 实现

保留 Electron 界面和现有聊天能力；使用独立 Windows 采集 helper 与后台分析队列。采集失败或 AI 离线都不能阻塞聊天。记录和分析分别启停。

数据分为三层：

- 原始证据：时间、前台应用、窗口标题、采集画面、空闲状态；网页 URL 和文件路径只有可靠接入来源时才记录为事实。
- 搜索资料：OCR 文本、来源关联、可重建的全文索引；语义索引在文字搜索验证后加入。
- 派生理解：活动片段、事项关联、工作日志，保留来源 ID 与分析版本，允许修正和重新生成。

工作日志与长期记忆分库管理：日志是高频、带保留期限的经历；长期记忆是筛选后的稳定事实与偏好。不能将所有屏幕文字自动写入长期记忆。

原型先使用独立压缩图片验证采集与检索，保持媒体存储接口独立；再根据实际容量和随机读取性能决定是否引入硬件编码分段。默认 10 秒采样仅作为试验起点，结合窗口变化触发与去重；不能承诺不漏掉短暂内容。

## 实施顺序与验收

1. **记录与回看**：显式开启、前台活动、截图、当天时间线、暂停/锁屏/排除应用、容量上限与完整删除。验收连续一天运行的 CPU、内存、磁盘增量、记录缺口和异常恢复。
2. **搜索与找回**：后台 OCR、时间/应用/关键词筛选、原始画面定位。用用户主动挑选的已知片段检查命中和遗漏；中文索引需单独验证。
3. **工作日志与问答**：异步生成活动片段、日报、带依据的历史回答；模型离线保留未分析数据，并支持重试而不重复生成卡片。
4. **与 ChouYu 联动**：从日志片段继续对话、关联事项，按需提炼为长期记忆，再验证是否比独立日志工具减少用户操作。

关键验收：暂停后的在途采集不再落盘；删除覆盖原图、OCR、索引与相关派生内容；恢复和重试不重复；采集记录与模型推测明确区分；云端分析仅在用户开启时发送选定范围的数据。

## 产品判断

两个项目已经覆盖自动日志，Mac README 也明确提供与日志对话。不能将“自动记录 + 日报 + 问答”宣传为独有功能。ChouYu 可进一步验证的方向是把历史证据接入日常桌面协助和任务继续，但它仍是待验证的产品假设。
