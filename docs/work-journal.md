# 工作日志：活动、关键画面与来源总结

2026-09-07，工作区实现，尚未进入现有 rc.3 安装包。

## 使用

从聊天顶栏“工作日志”、设置导航“工作日志”、托盘菜单或 `/journal` 打开独立窗口。首次默认关闭，点击“开启活动记录”后才启动 Windows 采集进程。

- 每约 5 秒读取前台应用进程名和窗口标题，合并相邻同应用、同标题的采样为活动片段。
- 按本机日期查看，搜索应用名和窗口标题，超过 100 条分页展示。
- 记录设置支持进程排除名单，以及 7/30/90 天保留期限。缩短保留期限会清理过期记录。
- 可在日志窗口或托盘暂停/继续。手动暂停会持久化，锁屏解除不会自动解除手动暂停。
- 锁屏、系统休眠期间暂停；连续 2 分钟无键鼠活动时不继续记时。采集失败单独显示错误，不伪装为空闲。
- 关闭窗口不停止已开启的记录；退出应用会停止 helper 并关闭数据库。再次启动按已保存的开启/暂停状态恢复。
- 默认排除若干密码管理器进程，以及 ChouYu 自己的前台窗口。排除只对当前应用进程生效，不识别网页类型。
- “删除当天记录”需确认，删除所有与当天重叠的完整片段；跨午夜片段会一起删除。若记录仍开启，当天之后的新活动仍会写入。

## 当前记录范围

默认仅记录应用名称、窗口标题及采样时间；活动记录和画面记录都需手动开启。数据保存在本机用户数据目录 `journal/journal.db`，图片位于 `journal/media/`，当前未额外加密。

在“记录设置”勾选保存前台窗口画面并保存后，已开启的活动记录会按 10/20/30/60 秒间隔尝试采图，默认 20 秒。只保存 HWND 匹配的前台窗口，采图前后复核进程、窗口和标题；不回退为整个桌面。同一活动中 JPEG 字节完全相同的图片只保留一份，未做感知去重或视频录制。当前未自动遮蔽窗口内部的密码或其他隐私字段。

“关键画面”可按日期和应用、标题、本地 OCR 文字搜索，每页 30 张，点击回看保存的 JPEG 和识别文字。Windows OCR 常驻隐藏进程逐张处理，不调用云服务；需本机可用的 OCR 语言包。暂停时后台 OCR 队列也暂停，单张图片仍可手动识别或重试。

画面空间上限默认 512 MB，可选择 256 MB/512 MB/1 GB/2 GB；达到上限后停止新增画面并显示提示，活动记录继续。该上限统计图片及待清理图片，不是整个数据库的硬配额。期限清理和按日删除同步清理图片及 OCR 索引，并清空可重新生成的总结缓存；文件占用导致清理不完整时明确报错。启动时清理孤立的临时图片。

“日志总结”手动调用当前聊天配置的模型，将所选日期的应用、标题和 OCR 文字发送至已配置的 AI 服务，不发送图片。新版按项目和事项归并，展示具体标题、活动/进展/决定/待解决类型、建议继续入口和可点击来源；可复制日志。旧版总结仍可查看，界面提示重新生成。仅标题证据的事项不会标记为已确认进展。

输入在整个日期范围内抽取约 200 个活动与 100 张画面，并保留范围两端；单张文字最多 3000 字，总计约 40000 字符。相同文字归组但保留各次来源和时间，不再简单丢弃较早记录。覆盖提示展示输入与可用来源数量、含正文来源数量；抽样可能遗漏事项。引用校验不能保证模型每句话都正确。

“问问这一天”支持针对所选日期的一次提问，发送问题与该日抽样文字至当前模型，回答附原始活动或画面来源。回答只在当前视图保留，不写入长期记忆。当前不是跨日语义检索或多轮聊天；未找到不能说明没有发生。总结和问答串行执行，最长等待 120 秒，可手动取消；普通聊天仍默认 60 秒。删除、锁屏等状态变化会取消在途日志分析。

宽窗口右侧展示当天概览、应用采样时长和证据情况，窄窗口移到主内容之后。当缺少 OCR 正文时明确说明只能找回活动线索。布局参考 Dayflow 的内容层次，沿用 ChouYu 主题，没有复制第三方界面代码或增加效率评分。

尚未记录键盘内容、独立网页 URL、文件修改；没有自动定时日报或自动长期记忆写入。

时长是采样估计：短于采样间隔的切换可能遗漏，窗口切换和空闲阈值也会带来误差，不能作为精确工时或产出统计。当前未做全天持续运行资源评测。

## 实现

内置可选 journal 模块；独立常规窗口展示时间线；常驻 PowerShell helper 通过 Win32 查询前台窗口；Electron desktopCapturer 异步获取窗口画面，单次等待上限 8 秒，未结束时不并发重试；SQLite、图片写入和清理在独立 Worker 中执行，OCR 在独立常驻 PowerShell 进程执行。脚本以隐藏窗口、最小环境启动，不降低系统执行策略。系统限制运行脚本时显示错误。

进程不会随应用启动自动采集：只有记录开启且未暂停时才按需启动 helper；空闲时停止 helper，恢复活动后重新启动。每个采集周期校验 epoch，防止暂停或删除后的在途结果回写。
