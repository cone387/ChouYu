# 联系人可靠性优化验收（2026-10-26）

实现分支：`feat/contact-reliability-implementation`，隔离工作树 `fcd3/ChouYu`。本轮保留共享 worker、默认 8 个执行名额和既有图节点；没有拆成每联系人一个进程。原项目工作目录与真实联系人数据未用于故障注入，也未合并或推送。

## 已实现

- 宿主真实状态、连接代际、排队/执行计时、有限诊断和重试入口；旧进程消息不能覆盖新状态。
- 任务库与检查点在持久安全边界成组备份、校验并原子发布，保留三组；原文件及 WAL/SHM 保留后才安装恢复文件。
- 恢复保护及新增额度存在应用库，不随联系人快照回退；未知消耗不记零，旧操作不重放。空联系人也可通过共同待处理卡片核对资料，任务外部结果与额度仍单独核对。
- 身份按联系人修订增量同步；会话列表、未读和搜索从元数据读取，正文按需缓存；应用库改为分片备份，关闭等待最新修改。
- 助手安排和陪伴执行器通过共同任务界面显示真实执行阶段。任务截止与成功产出/送达期次持久保存，不能冒充目标已经验收完成。
- 原生与 DSH 在每次新模型、工具执行前校验边界；异步用量结算完成后才能继续下一步。助手串行任务逐项检查当前截止时刻。
- 业务模块只依赖 Harness 契约和服务端口；检查点节点名保持兼容。当前规范、架构、恢复说明及图册同步更新。

## 性能测量及限制

以下是合成夹具、同机对比，不代表整个应用启动或常驻内存收益。

| 场景 | 原路径 | 本轮路径 |
| --- | --- | --- |
| 24 个联系人、每个 1000 条会话/通知，仅一位变化 | 身份载荷 623703 字节 | 26294 字节；未变化的 100 次轮询不读取正文、不发送身份 RPC |
| 24 × 1000 条消息，会话列表 | 约 20.4 ms、8.09 MB 保留堆 | 元数据约 0.30 ms、10 KB；子串搜索约 46 ms |
| 8192 × 4096 字节应用库备份 | 221 ms，总计 3 次事件循环机会，最大间隔 221 ms | 288 ms，84 次事件循环机会，最大间隔 177 ms |

应用库校验及 fsync 仍同步执行，因此不能称为完全不阻塞。当前活动聊天仍通过兼容接口读取完整会话，未宣称完整历史虚拟化；选中或未保存的大会话可以超过缓存软上限。联系人备份不包含应用聊天库、附件、技能和 DSH 原始日志。

Windows 上非正常退出后的 WAL/句柄根因、真实断电、长期休眠和安装包运行尚未被此次短时验证证明。共享进程崩溃会短暂影响所有后台联系人，这是保留的故障边界；恢复能力与真实状态提示降低影响，但不等于进程级隔离。未来只有在实际负载或崩溃数据证明需要时，再评估固定数量 worker 池；目前不引入每联系人独立进程的资源和协调成本。
