# 联系人工作计划格式恢复（2026-10-09）

排查阿想与阿笔的失败运行：三次模型调用均记录 `finishReason=stop`，使用量正常返回，错误来自工作计划 JSON 解析阶段。旧实现没有保存失败原文，不能还原究竟是额外说明、非法 JSON 还是空正文；不以猜测作为已验证根因。代码中确认的缺口是：成果格式已有修复，工作计划语法失败却直接终止整轮。

已实现：

- 唯一完整 JSON 对象可带代码围栏或外围说明；多对象、截断、空返回不直接执行，不推断缺失字段。
- 语法/必需动作字段失败时最多自动修复一次，复用现有模型通道及调用/Token 限额，剩余调用须足以修复并执行。
- 持久事件记录修复次数，重启恢复也不能无限重复修复；修复后重新校验动作、权限、网址、分节和联系人成果引用。
- 记录空输出、非完整唯一 JSON、缺失动作字段、修复中/完成/仍失败；日志不保存模型原文或凭据。
- 修复失败保留已有成果，既不伪造交付，也不清除失败历史。没有更改工作方式、用户额度或自动重试间隔。

验证入口：`npm test`、`npm run typecheck`、`npm run build`、`node scripts/smoke-electron.js --agents`。新增隔离模型测试覆盖外围说明、歧义 JSON、空/截断、成功恢复、只修复一次、额度不足、权限复核及已有持久修复记录。

边界：历史原文缺失，无法原样回放三次真实失败；隔离用例验证恢复路径，不代表真实模型从此不会输出无效计划。运行中的旧应用需重启加载新代码，历史失败不会改写成成功。
