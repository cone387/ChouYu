# 对话诊断、汇报质量与需求追溯验收

日期：2026-10-09。适用条款：UI-01、UI-05、NL-03、MSG-02、HIST-01、SCOPE-01。

## 实现

- 对话可用性改为实际流式请求判断，模型列表单独保留。诊断只发送合成短句，不附私人聊天、任务或工具。支持 OpenAI 兼容与 Anthropic；展示请求/返回模型、HTTP 状态、正文、耗时及完成标记。空正文、中途断流、上游错误、截断、超时均不能显示可用。模型或配置更改后清除旧诊断，并丢弃在途旧结果。
- 主动汇报提取共用生成函数，在线评估直接调用生产生成函数和 CompanionBriefing。发现模型可能把旧 nextStep 当成用户待办，已从摘要输入移除该字段，收紧仅报告事实、仅 waiting 问题要求用户答复的提示。
- 共用任务详情的互动标签增加同一个需求记录组件，普通联系人任务与 ChouYu 定时任务均读取已有 requestLog。原文纯文本展示，可展开、窄屏换行、长记录滚动。旧记录缺失明确说明。后续修改增加分隔；超出既有 8000 字限制时保留开头和最近记录并显示缺失标记，不再悄悄只留下最新修改。

## 真实在线验证

使用当前中转和 `as-glm-5.2`，只发送合成任务。真实诊断返回 HTTP 200、正文 OK、正常结束；请求模型为 as-glm-5.2，接口返回模型名 glm-5.2。

最终人工审阅样本：待回复准确询问国内/海外范围；失败明确 503 与未取得新资料；新增第二节初稿明确引用未核对且任务未完成。无变化不再调用模型，重复事件不重复投递。四种场景共三次摘要模型调用。已核对生成任务链接中的联系人和任务 ID；本轮不把链接字符串验证冒充 UI 跳转回归。

可重复执行 `node scripts/evaluate-companion-online.cjs`。须提供环境变量 CHOUYU_EVAL_BASE_URL、CHOUYU_EVAL_API_KEY、CHOUYU_EVAL_MODEL；默认 OpenAI 兼容，可用 CHOUYU_EVAL_PROVIDER 指定 claude。默认关闭 thinking，可用 CHOUYU_EVAL_THINKING=enabled 保留。结果写入 `temp/companion-online-results.json`，脚本会发起真实模型调用，仍需人工审阅正文。
