# 持续提醒验收（2026-11-17）

产品入口：[联系人任务规范](contact-task-spec.md)第 7、10、11 节。实现位于当前源码工作区，未发布安装包或重启用户应用。

## 已实现行为

- 新主动消息统一登记持久事项，阅读与处理分开。未读、已读未处理均默认每 30 分钟继续，单项间隔允许 1～1440 分钟；单次延后 10/30/60 分钟，到期后恢复持续跟进。
- 问候、回来、晨报、成果等告知需「知道了／已阅」；休息等现实活动可明确「已处理」；待办/子项执行真实完成操作，联系人问题与故障回到原交互处理。重试排队、运行中不冒充故障已解决。
- 原消息和催办共用事项；同源待办/交互跨会话去重，保留来源入口。新催办是独立未读事件，原消息的已读事实不回退。首次正文继续使用已保存成果，催办不调用模型或复制全文。
- 首次投递与登记、再次投递与下次时间分别在同一 SQLite 事务保存。失败催办不进入待刷写消息缓存，恢复时按最新来源重新分组，避免新旧分组重复发送；首次真实成果仍保留既有失败保存恢复方式。
- 清除全部原消息、删除会话/联系人/安排、待办删除或改期等核对后失效；读取失败保留事项及错误。处理、清除及安排变更会使异步检查过期，投递前再次核对版本和原消息。
- 退出期间不执行，恢复合并同一会话当前到期事项，不逐次补发。历史告知不追溯登记；旧有效稍后计划仍按原时间送达，再接入持续机制。关闭职责停止新触发，既有告知不被代为确认。
- 提供当前会话范围的查询/单项调整工具，供自然语言调用；沿用现有工具授权与确认策略，不引入批量操作。

## 真实平台边界

自动化覆盖应用数据库重启、渲染层重载和模拟离线时间，不等同于人工完成真实锁屏、系统睡眠唤醒、全天驻留或所有 Windows 托盘环境验证。未读继续进入既有桌宠/托盘通路，未改变闪烁强度或超时规则。

自然语言工具通过契约与权限测试，本轮未用付费真实模型枚举所有表达。告知确认只表示明确接收，不能证明用户已执行现实活动或认可成果质量。
