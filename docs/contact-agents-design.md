# 持续工作的联系人 Agent：首版方案

日期：2026-09-23。状态：已实现本地首版，使用 LangGraph JS；尚未发布安装包。所有联系人默认关闭持续工作，启用后才产生定时模型调用。下面先列出实际交付边界，后半部分保留长期产品设计目标。

## 本地首版使用与边界

通讯录 → 联系人菜单 → 查看详情 →「自己的工作」。填写长期方向、1–5 个公开 HTTPS 网页、间隔与每日调用上限，保存后可手动运行一轮，或勾选持续工作。通知专用的内置「助手」不执行研究。

- 关闭聊天继续工作；退出应用、关机或休眠期间不能执行。再次启动从 SQLite 检查点恢复未完成步骤，不补跑离线期间的每一次计划。
- 每轮读取指定来源，结合最近三轮成果、该联系人的近期聊天与独立记忆生成新成果和下一步；需要信息时用 LangGraph interrupt 持久化等待。回复后记录补充并完成本轮，后续轮次继续使用补充信息。
- 保存每轮状态、动作、失败、成果、下一步，以及来源 URL、读取时间、正文节选与 SHA-256。成果为模型研究判断，不能视为已经验证的收益机会；不会模拟没有发生的生活经历。
- 模型配置沿用联系人绑定的供应商；后台凭据只通过进程消息在内存中传递，不写入运行输入或 LangGraph 状态。
- 角色独立记忆来自自己的研究结论或用户手动记录，上限 100 条；结论带运行来源。其他联系人不检索这些记录。自定义角色的 `/remember` 写入其独立记忆；普通聊天不再抽取进旧全局库。
- 旧全局库仍由默认丑鱼使用，没有自动将混合历史记忆分配给角色；角色独立记忆没有接入 Mem0、向量检索、冲突合并或版本恢复。默认角色聊天可能同时引用旧库与自己的 Agent 成果。
- 历史界面显示最近 30 轮，近况读取最近 20 份成果；数据库保留旧记录，尚无更早记录的分页、导出或自动归档。忘记一条记忆不会删除历史成果。删除联系人会停止执行并删除其工作、记忆和检查点。

运行边界：全局同时一轮；调度检查约 15 秒；最短间隔 15 分钟，默认 180 分钟。每人每日默认 8 次、最多 48 次模型请求，在请求前计数，失败和恢复重试也计入。正常一轮一次模型调用，输出上限 2200 token，单轮总时限 120 秒，模型总时限 90 秒。每日额度是次数上限，不是金额或精确 token 账单。

网页读取仅限 HTTPS/443 公网 IPv4，同站最多三次跳转；固定已校验 DNS 地址，阻止内网和本机访问，不携带登录凭据或 Cookie。单页最多读取 512 KB，保存最多 12000 字节选；模型使用最多 5000 字的节选。JavaScript 渲染页面、登录站点、IPv6 专用站点、非 UTF-8 页面暂不保证支持；没有读取成功的资料就不会生成研究报告。

连续失败三轮自动关闭定时工作。暂停、修改工作设置或删除角色会停止旧运行并拒绝迟到结果。执行进程退出后最多自动重启三次，仍失败时可在详情重新读取并重试。成功运行的检查点被清除，正式成果及事件保留。

### 实现分工

`src/main/agents/index.ts` 是主进程身份校验和独立进程 RPC；`worker.ts` / `service.ts` 负责执行进程生命周期、调度和限额；`runtime.ts` 是 LangGraph 的读取 → 形成成果 → 等待补充 → 保存流程。`store.ts` 保存业务记录，官方 `SqliteSaver` 保存可恢复图状态；文件位于应用 userData 的 `contact-agents/`。没有依赖 LangSmith 云端、Python 服务或新的外部账号。

界面沿用现有通讯录、系统字体和主题变量：联系人姓名 → 自己的工作 → 近况/工作记录/独立记忆 → 折叠角色资料。成果先于详细工作日志呈现，窄窗口保持内部滚动；表单与错误状态支持键盘和深浅色主题。任务系统没有新增快速录入、多选或批量操作。

### 验证入口

- `npm run typecheck`、`npm test`、`npm run build`。
- `node scripts/smoke-electron.js --agents`：真实 Electron utility process、持久化 interrupt、强制杀进程后回复恢复、一次模型调用、资料证据与角色隔离。使用隔离 userData、回环模拟模型和固定合成网页，不调用付费模型或真实外部来源。
- 设置 `CHOUYU_SMOKE_ARTIFACTS` 可生成 1024/375 宽、深浅色截图；全量 `node scripts/smoke-electron.js` 包含此流程。
- 单元测试额外覆盖三轮研究延续、执行中断重试计数、定时调度、迟到结果、预算耗尽、删除在途角色、失败暂停、DNS 固定与重定向权限。

2026-09-23 验收：91 个测试文件、786 项测试通过；类型检查、生产构建、旧记忆评测与完整 Electron 冒烟通过。实际公开网页读取已检查；供应商使用模拟服务验证，没有测试付费模型的研究质量，也没有做全天运行或安装包验收。回归中发现并修复了切换页面前滚动事件尚未送达导致的聊天阅读位置丢失；窄窗口联系人详情也增加了边界约束。

## 后续产品设计目标（不代表首版已实现）

## 产品目标

通讯录中的每个人都有自己的长期方向、持续工作、独立经历和记忆。用户与其聊天时，角色能够接续自己的工作，引用真实记录说明进展，并根据用户反馈调整下一步。

“生活轨迹”由实际交互、执行、发现、失败和成果构成。没有执行的时间不编造活动；模型提出的推测与有来源的观察分开保存。角色介绍中的设定不充当真实经历。

所有联系人具备成为 Agent 的身份基础；用户为某个联系人设置方向、工具范围与预算后启用持续工作。未启用的角色明确显示“尚未开始”，避免预设联系人自动产生调用费用。

## 用户第一次使用

以“机会研究员”为例：

1. 打开联系人，为他指定长期方向，例如“研究适合我独立开发、能小成本验证的商业机会”。记录用户提供的技能、时间和预算约束。
2. 指定可用资料和外部来源，设置执行频率、调用上限与通知偏好。没有可用信息源时提示缺少资料，不把模型自行生成的点子说成市场调查。
3. 他完成第一轮工作：读取资料、提出假设、检查支持与反对证据，生成机会记录和下一步。
4. 下一轮从已有进度继续：补证据、验证关键假设，或说明为什么放弃某个方向。没有新发现也是合法结果。
5. 用户打开联系人，看到当前进展与成果，能问“为什么改主意”“昨天查到了什么”，并打开实际来源。
6. 用户可以暂停、修改方向或否定一条结论。修改影响后续工作，历史保留变化原因；需删除的内容按删除规则处理。

首个验证案例只做需求与商业机会研究，不进行自动投资、付款、账号注册或对外发布。

## 每个角色拥有的内容

| 内容 | 用途 |
| --- | --- |
| 身份 | 复用联系人 ID、姓名、人格、模型配置 |
| 长期方向 | 用户授权的目标、边界和结束/复核条件 |
| 当前进度 | 当前研究对象、待解问题、下一步、等待原因 |
| 经历 | 实际发生的运行、阅读、工具结果、失败、用户反馈 |
| 独立记忆 | 从经历中提取并带来源的事实、经验与有效约束 |
| 成果 | 可版本化的机会、报告、方案或文件，关联支持和反对证据 |

用户关于自身的共享资料与角色私有记忆分开。角色只使用明确授予的共享资料；用户可以检查自己创建角色的工作与记忆。“独立”指角色之间隔离，不对用户隐藏行为。

角色间协作后续通过可审阅的交接记录实现：发送者、接收者、内容与来源可见，不默认读取对方的全部私有记忆。首版不实现自动群聊或互相无限派活。

## 持续运行方式

持续工作由计划或事件触发，每次有明确的时间、工具步数和用量边界。一次运行输出进度、证据、成果变化与下一次可执行动作。角色可在授权目标内决定下一步；新增权限、扩大目标或突破预算需要用户决定。

运行位置尚待用户选择：

- **本地常驻**：关闭聊天面板后继续；应用退出、电脑关机或休眠期间不执行。重启后恢复进度，并记录离线时段。
- **云端执行**：桌面关闭后仍能执行，需要部署服务、凭据管理和数据同步；本地文件与桌面工具只能在对应设备在线且授权时使用。

本地方案不能宣称关机后仍提供 24 小时工作。两种方案采用相同的运行记录与状态协议；首版实现范围随上述选择确定。

执行状态：待执行、运行中、等待用户、等待外部条件、暂停、完成、失败、中断。状态由实际运行结果驱动；联系人“正在工作”必须对应真实运行。

可靠性要求：

- 调度和进度持久化，同一角色同一时刻最多一个后台写入型运行，应用级并发受限。
- 运行采用租约、心跳与检查点。进程中断后标记中断，重新检查外部结果再决定是否重试；不承诺任意外部动作恰好执行一次。
- 错过的周期合并处理，恢复时不一次补发大量请求。网络错误退避，连续失败或预算耗尽后暂停。
- 模型调用前预留用量，完成后结算；缺少价格/usage 时显示估算或未知，并保留轮数、时长、token 上限。不能把未知费用显示为零。
- 后台授权进入持久化待处理箱，不依赖聊天弹窗在线；批准绑定具体参数、目标版本和有效期，变化后重新确认。
- 外部页面和工具结果作为资料处理，不得据其内容擅自扩大权限或更换任务目标。

## 独立记忆与追溯

所有运行、记忆、证据和成果必须带 `characterId`，运行及其产物带 `runId`。身份在主进程/执行端根据有效联系人与会话确定，不能直接信任模型参数。

经历为可追溯事件；长期记忆是带版本与来源的提炼结果。摘要压缩不删除其引用的原始证据；按保留策略删除原文后，引用明确标记不可用。URL 内容可能变化，保存采集时间、允许保留的片段与内容指纹。

机会记录的演化示例：提出假设 → 补充证据 → 待用户选定验证 → 已验证或放弃。每次状态变化保存理由和证据。缺少证据的想法保持“假设”，不升级成“已验证机会”。

可查看的信息是行动、输入来源、输出、错误、结果与简明决策说明，不承诺提供模型内部完整推理过程。

旧记忆迁移要求：

- 不能把现有全局记忆复制给所有角色。
- 有明确会话来源的记忆，只能在归属规则可靠时归到相应角色；混合或未知来源保留待整理状态。
- 隔离必须覆盖检索、向量、去重、冲突检测、摘要、版本恢复、导入导出与缓存，不能只改聊天 Prompt。
- 当前 Mem0 服务/用户隔离不等于联系人隔离；未验证远端作用域实现前，不用于保存角色私有经历。
- 删除联系人时停止运行、撤销待审批操作并处理其数据与索引，阻止在途结果重新写回。用户可明确选择导出或删除，不静默留下孤立私有记忆。

## 与现有代码的衔接

| 当前基础 | 需要补充 |
| --- | --- |
| `src/shared/characters.ts` 已有身份、人格与模型配置 | 以稳定 ID 关联 Agent 配置，不从姓名生成身份 |
| 聊天会话按角色归属 | 聊天和后台工作共用角色作用域，后台活动另存，不大量灌入聊天消息 |
| `src/main/memory/service.ts` 使用全局 provider，检索无角色参数 | 引入受校验的记忆作用域，完善本地与远端迁移策略 |
| `src/main/ai.ts` 已有模型请求与工具循环 | 提取不依赖聊天窗口的运行入口，输入明确的执行上下文 |
| 工具上下文要求 `mainWindow`，授权主要位于聊天 IPC 流程 | 拆分工具能力、持久化授权和 UI 展示；后台不得假定窗口存在 |
| 任务提醒已有调度模式 | 新增独立 Agent 调度与运行存储，业务待办与后台执行记录分别管理 |

首版已新增 `src/main/agents/` 并采用 LangGraph JS 管理检查点与等待恢复。后续可将执行端迁往常驻云服务，但云端身份、加密凭据、计费与部署尚未实现。

联网研究需要可配置的真实搜索/读取能力及来源持久化。当前工具目录以桌面、任务和插件操作为主；不能仅接一个定时 Prompt 就认为完成研究能力。

本功能不改变任务系统约定：不增加快速新建、多选或批量操作；普通任务表单和单任务操作保留。

## 首版交付顺序与验收

1. **身份与隔离**：两个联系人分别经历不同事件；检索、冲突处理和引用不串用。用户向一个角色提供的信息不能自动出现在另一个角色的回答中。
2. **持续执行**：一个已启用角色在聊天关闭后完成真实读取与产出；下一轮使用上次进度。暂停阻止新工作，取消不提交晚到结果。
3. **恢复与边界**：执行中重启、网络中断、工具超时、预算耗尽、授权过期、删除角色均有可重复测试；不能重复执行不确定的外部写入。
4. **可见经历**：在现有联系人详情中查看当前工作、经历、成果与记忆；每项成果能定位运行和来源，错误与等待状态可见。
5. **机会研究案例**：同一角色至少连续三轮推进一条研究线，包含新证据引起的判断修正；重启后仍能引用之前的经历，另一角色不能读取其私有资料。

首版成功标准是“一个角色能真实持续工作，并拥有可验证、可接续的独立经历”。批量启用全部预设联系人、复杂社交模拟与自动角色协作不作为首版验收要求。
