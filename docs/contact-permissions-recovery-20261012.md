# 联系人权限与故障处理验收（2026-10-12）

用户要求失败必须明确提醒并提供交互解决入口，同时可给联系人预先配置权限，避免每次确认。对应任务规范第 6、7、9 节及 UI-03/05、RUN-02/03、MSG-01、RES-01。

## 已实现

- 首次失败就创建持久处理卡片，后续失败各自关联原轮次；继续显示真实自动恢复时间，停止或按需模式不虚报自动重试。
- 区分计划地址格式、访问范围、搜索服务、工具开关、技能环境与模型服务问题。缺失/错误的计划 URLs 在原有一次格式修复中处理，修复后重查权限，调用计入原预算。旧笼统错误无法还原原始计划，不推断用户未授权。
- 具体诊断可展开查看，检测到凭据或带参数地址时隐藏。卡片按联系人打开工作设置/技能页，工具或模型问题打开原系统设置入口；打开设置不等于解决。
- 修复权限后保留原失败卡片、更新版本；旧版本不能提交，删除、任务修改或新轮次仍使旧卡片失效。重试和回执事务保存，重复点击不重复执行。
- 阅读样式修改失败同样有卡片，只重试原意见、原成果版本及样式范围，不恢复正文工作。用户在暂停/完成任务上明确发起的样式请求可重试，之后任务或成果变化会拒绝旧操作。
- 工作设置新增联系人独立的四种工具确认策略，默认继承原系统行为；明确设置自动执行可免除该联系人的工具逐次确认。关闭的工具、网页范围、技能脚本授权与后台预算继续有效；已有等待确认不会被改策略自动批准。
