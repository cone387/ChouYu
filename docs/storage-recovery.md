# 聊天数据保存与恢复

适用范围：2026-10-22 增量存储开发分支，尚未发布安装包。

## 保存内容

- 不再因为超过 100 个会话、单会话超过 500 条消息而删除历史；消息正文也不再在保存时截取前 200,000 个字符。
- 模型上下文仍只使用最近 30 条消息，发送协议的长度限制不变。历史保存与模型上下文是不同边界。
- 截图和粘贴图片保存到用户数据目录的 `attachments` 文件夹；同一内容只保存一份。消息行只保存图片引用，打开会话时恢复图片数据。
- 支持 PNG、JPEG、GIF、WebP、BMP 和 AVIF 的 Base64 图片。无法保存的图片会触发保存失败提示，不会悄悄从记录中移除。
- 旧版本已经截断的会话/消息、未保存到磁盘的图片，无法由本次升级重建。

## 文件布局

用户数据目录由 Electron 管理。出现保存/恢复提示时，可以点击“打开数据目录”。Windows 通常位于 `%APPDATA%/chouyu`，实际路径以应用打开的目录为准。

| 文件 | 用途 |
| --- | --- |
| `chouyu-application.db`、`-wal`、`-shm` | 配置、角色、会话、消息、状态和送达回执的唯一实时存储；不要只复制尚在运行的主文件 |
| `chouyu-application.db.bak` | 经 SQLite 一致性快照生成并验证的恢复备份 |
| `chouyu-data.json` | v5 SQLite 指向与迁移身份标记，阻止旧 v4 应用覆写 |
| `chouyu-data.json.legacy` | 迁移前已验证的原始 JSON；新安装没有旧文件时不生成 |
| `chouyu-data.json.bak` | 旧格式恢复/切换遗留副本，不再随聊天更新 |
| `*.corrupt-时间戳-随机标识` | 读取失败时保留下来的原文件 |
| `attachments/` | 按内容哈希命名的图片文件 |
| `chouyu-memory.db` | 独立的 SQLite 长期记忆数据库，本节应用存储恢复不负责修复它 |

消息只更新变化行；配置和状态不重新序列化无关历史。SQLite 使用 WAL 和 FULL 同步，正文与送达回执在同一事务内提交。图片先落盘，再提交引用。

旧 JSON 先验证并保留 `.legacy`，再事务导入、逐项核对并保存迁移身份，最后写入 v5 阻写标记。标记失败时不能开始产品写入；重试复用已完成导入，不重复插入。已有目标库与旧文件身份冲突、格式较新或读取权限失败时阻断写入。

恢复备份在有保存之后定时（60 秒）及正常退出时通过 SQLite `VACUUM INTO` 生成，验证后替换备份；不在每条消息保存时全量复制。失败保留旧备份并提示。该快照仍是同步操作，大库可能短暂停顿。

## 保存失败

磁盘空间不足、目录权限不足、文件被占用或图片保存失败时，应用持续显示“数据尚未保存”，并提供“重试保存”和“打开数据目录”。最新修改仍可能只在内存中；不要强制结束进程。

修复磁盘或权限问题后点击“重试保存”。只有事务成功提交后，失败提示才会消失。失败交付的正文及回执保留在内存，重试不会多插一条。正常退出时会再次尝试保存；首次检查仍失败时默认返回应用，也可明确选择放弃未保存修改并退出。

后台停止期间也可能产生最后一笔修改，因此退出前还会再保存。若此时失败，普通窗口暂停操作，进入“退出前保存失败”对话框，可重试保存、打开数据目录，或明确放弃未保存修改并退出。保存成功后退出，重新打开即可继续使用；此阶段不会返回服务已经关闭的普通界面。

如果启动时无法读取原文件，或发现比本应用更新的数据格式，应用会保护原文件并停止写入。请修复读取权限或使用较新版本后重启；这种保护状态不能通过“重试保存”绕过。

## 自动恢复与手工找回

1. 应用 SQLite 损坏时，先隔离保存主文件及 WAL/SHM，再验证并恢复 `.bak`。
2. 备份有效时自动恢复，并提示备份之后的修改可能丢失。每条消息已持久提交不代表已经进入周期备份。
3. 没有有效应用库备份时阻断写入，保留损坏文件，不用迁移前的旧 JSON 冒充最新数据。尚未迁移的旧 JSON 继续沿用原来的损坏隔离和备份恢复规则；两份旧 JSON 均损坏时可建立带提示的空白工作区。
4. 文件读取/保留失败或较新格式时停止写入，不把权限问题误判为文件损坏。首次建表中断留下的、可验证为空的库允许重新初始化。

如需手工找回，先退出应用并复制整个数据目录留底。恢复副本必须保留匹配的应用库、迁移标记和附件；不要将旧 JSON 直接覆盖到已迁移的数据目录，也不要覆盖唯一一份损坏原件。旧 JSON 的单独导入应在新的隔离目录验证，避免与已有实时库形成两个来源。

缺失或校验失败的图片会显示全局提示，文字记录仍可使用；继续保存文字不会移除原图片引用。

## 当前边界

- 为保证备份仍能找到图片，本轮不自动清理删除会话后遗留的附件；数据目录可能随使用增长。后续需加入同时检查当前快照、备份和恢复文件的整理工具。
- 图片与聊天内容是本机普通文件，不属于 API Key 的 `safeStorage` 密钥加密范围。
- 启动仍加载全部会话，检索仍扫描内存；单会话编辑也会检查该会话的消息。增量落盘解决全量重写，并不等于这些成本消失。完整测量见 [本轮验收记录](system-evolution-acceptance-20261022.md)。
- 本地备份不能替代独立设备备份，也不能保证系统强制结束、硬盘损坏等情况下的零丢失。

## 联系人成果版本

联系人任务库 `agents.db` 的格式版本现为 18。每版成果保留章节顺序、标题、来源、轮次与阅读样式，正文通过 SHA-256 引用不可变块；相同正文跨版本复用，联系人归属和读取权限仍单独校验。检索索引的规范化正文也共享保存，不再逐版本复制全文。

旧快照在原库内事务转换，重建内容与旧版逐项核对后替换；格式标记与整个初始化事务一起提交，中断后重试。旧应用会拒绝版本 18，不能直接降级打开。阅读、引用与导出仍得到原成果结构；缺块或哈希不符明确报错，不能显示空白正文冒充有效成果。

删除任务或联系人时只清理没有任何版本引用的正文和索引块，其他任务的引用保留。SQLite 空闲页会被后续写入复用，删除后文件不一定立即缩小。此库不使用聊天库的周期 `.bak`；备份任务数据时仍需在应用退出后完整保存数据目录。

## 反馈、依赖与恢复记录

反馈及原始请求回执、恢复尝试关联、继续任务请求回执和成果依赖均存于原联系人任务库。修订创建与反馈登记同事务；实际成果完成、结果版关联及依赖更新也同事务。恢复尝试不会改写原提交回执，重复 ID 携带不同内容会被拒绝。

依赖消费按精确来源与实际读取的固定正文指纹确认，重启不丢失待处理更新；当前共享和读取权限仍在调度时复核。删除任务或联系人清理对应关系，正文块只在无版本引用时删除。以上记录不构成跨应用库的分布式事务，也不扩大来源授权。

## 验证

- 数据库回归测试覆盖数量边界、图片重启恢复、损坏隔离、备份恢复、权限阻断、失败重试、最终替换失败和附件校验。
- `npm run test:smoke:built` 使用临时用户目录，在真实 Electron 中制造写入失败，等待界面提示，点击重试，验证提示消失且状态已写入磁盘。
- 设置 `CHOUYU_SMOKE_ARTIFACTS` 为截图输出目录后，冒烟还会检查保存提示在亮暗主题、375px/1024px 等效视口中的布局，并输出 PNG。这是该提示的检查，不代表整个应用已完成视觉回归。
