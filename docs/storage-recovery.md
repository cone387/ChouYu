# 聊天数据保存与恢复

适用范围：2026-09-07 可靠性迭代后的开发版本，尚未发布安装包。

## 保存内容

- 不再因为超过 100 个会话、单会话超过 500 条消息而删除历史；消息正文也不再在保存时截取前 200,000 个字符。
- 模型上下文仍只使用最近 30 条消息，发送协议的长度限制不变。历史保存与模型上下文是不同边界。
- 截图和粘贴图片保存到用户数据目录的 `attachments` 文件夹；同一内容只保存一份。聊天 JSON 只保存图片引用，打开会话时恢复图片数据。
- 支持 PNG、JPEG、GIF、WebP、BMP 和 AVIF 的 Base64 图片。无法保存的图片会触发保存失败提示，不会悄悄从记录中移除。
- 旧版本已经截断的会话/消息、未保存到磁盘的图片，无法由本次升级重建。

## 文件布局

用户数据目录由 Electron 管理。出现保存/恢复提示时，可以点击“打开数据目录”。Windows 通常位于 `%APPDATA%/chouyu`，实际路径以应用打开的目录为准。

| 文件 | 用途 |
| --- | --- |
| `chouyu-data.json` | 配置、会话及应用状态的当前快照 |
| `chouyu-data.json.bak` | 上一次发生内容变化前的有效快照 |
| `*.corrupt-时间戳-随机标识` | 读取失败时保留下来的原文件 |
| `attachments/` | 按内容哈希命名的图片文件 |
| `chouyu-memory.db` | 独立的 SQLite 长期记忆数据库，本轮 JSON 恢复逻辑不负责修复它 |

写入先完成临时文件并刷新文件内容，再替换正式快照。旧的有效快照保留为 `.bak`；重复保存相同内容不会把备份轮换掉。图片先落盘，再提交引用它们的 JSON。

## 保存失败

磁盘空间不足、目录权限不足、文件被占用或图片保存失败时，应用持续显示“数据尚未保存”，并提供“重试保存”和“打开数据目录”。最新修改仍可能只在内存中；不要强制结束进程。

修复磁盘或权限问题后点击“重试保存”。只有快照成功写入后，失败提示才会消失。正常退出时会再次尝试保存；仍失败时默认返回应用，也可明确选择放弃未保存修改并退出。

如果启动时无法读取原文件，或发现比本应用更新的数据格式，应用会保护原文件并停止写入。请修复读取权限或使用较新版本后重启；这种保护状态不能通过“重试保存”绕过。

## 自动恢复与手工找回

1. 当前 JSON 损坏时，先保留原文件，再尝试读取 `.bak`。
2. 备份有效时自动恢复，并提示可能缺少最近一次修改。备份只有一代，不是完整版本历史。
3. 当前文件与备份均损坏时，分别保留原文件，再建立空白工作区，并显示恢复提示。
4. 文件读取/保留失败时停止写入，不把读取权限问题误判为文件损坏。

如需手工恢复：先退出应用，复制整个数据目录留底，再将确认可用的聊天 JSON 副本放到 `chouyu-data.json`，同时恢复对应 `attachments` 目录，最后重新启动。不要直接覆盖唯一一份损坏原文件。

缺失或校验失败的图片会显示全局提示，文字记录仍可使用；继续保存文字不会移除原图片引用。

## 当前边界

- 为保证备份仍能找到图片，本轮不自动清理删除会话后遗留的附件；数据目录可能随使用增长。后续需加入同时检查当前快照、备份和恢复文件的整理工具。
- 图片与聊天内容是本机普通文件，不属于 API Key 的 `safeStorage` 密钥加密范围。
- 当前仍使用整体 JSON 快照；取消数量上限后，极大历史库的加载与写入性能需要后续实测和存储演进。
- 本地备份不能替代独立设备备份，也不能保证系统强制结束、硬盘损坏等情况下的零丢失。

## 验证

- 数据库回归测试覆盖数量边界、图片重启恢复、损坏隔离、备份恢复、权限阻断、失败重试、最终替换失败和附件校验。
- `npm run test:smoke:built` 使用临时用户目录，在真实 Electron 中制造写入失败，等待界面提示，点击重试，验证提示消失且状态已写入磁盘。
- 设置 `CHOUYU_SMOKE_ARTIFACTS` 为截图输出目录后，冒烟还会检查保存提示在亮暗主题、375px/1024px 等效视口中的布局，并输出 PNG。这是该提示的检查，不代表整个应用已完成视觉回归。
