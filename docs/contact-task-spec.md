# 联系人任务产品与交互规范

版本：1.0；更新：2026-09-30。
状态：产品约束以用户已明确要求为依据；实现现状与缺口单独列于第 10 节。本文不是“全部功能已经完成”的声明。

## 1. 权威入口与维护规则

本文是联系人任务系统唯一的现行产品与交互规范。适用对象包括 ChouYu 的任务、问候与提醒、联系人晨报，以及其他联系人的持续工作任务。

优先级：用户最新明确要求 → AGENTS.md 的产品硬约束与本文 → 当前架构和使用说明 → 历史设计、计划与验收记录。出现冲突先服从用户要求，同时修正文档；不得让用户重新解释已经明确的约定。AGENTS.md 和本文有冲突时应记录并消除，不能自行选择较宽松的版本。

- 改动前阅读本文与 AGENTS.md，按第 11 节列出受影响的验收项。
- 在现有规则内的修复与实现直接推进，不要求用户再次批准已有要求。
- 改变产品规则时，只有用户明确改变要求才更新对应硬约束；工程实现困难不构成自行豁免理由。
- 新增能力先补充行为、状态、失败处理与验收项，再实现；不先堆 UI 再补解释。
- 每次改动同步第 10 节的实现状态、相关使用说明与验收证据。测试通过不等于需求全覆盖。
- 历史文档保留时间与来源，标明已被本文取代的部分，不作为恢复旧入口的依据。

## 2. 产品定位与范围

| 对象 | 定义 | 责任与边界 |
| --- | --- | --- |
| 用户 | 交代目标、接收消息、补充必要信息的人 | 不承担填写内部任务参数的工作 |
| ChouYu | 用户的专属助手 | 接收安排，主动问候、提醒，检查联系人真实工作状态并汇报 |
| 其他联系人 | 有独立身份、工作、记忆和成果的人 | 自己理解并推进任务，在需要时向用户提问、汇报 |
| 联系人任务 | 交给某个联系人执行的事情 | 归属明确，保留进度、结果、互动和历史 |
| 用户待办 | 用户本人要做的事情 | 属于独立待办模块，不将其结构化编辑器搬进联系人任务 |

ChouYu 的助手定位不要求独立 UI。联系人能力可以不同，任务界面必须复用一套代码。旧“助手”消息保留并归入 ChouYu，不重新引入第二个通知助手身份。

## 3. 不可回退的产品约束

- **一个任务描述**：新建、设置、编辑任务均只提供一个自然语言输入框。标题、目标、约束、时间、周期、类型、修改原因、预算等不能拆成要求用户填写的字段，也不能藏入“高级设置”重新引入。
- **全部使用弹窗**：普通新建及任务编辑直接打开同一个公共表单弹窗；禁止页面内展开表单，禁止“设置面板 → 编辑任务 → 再开表单”的多层入口。
- **无彩色焦点装饰**：输入框聚焦不改变默认边框颜色，不增加彩色 outline、ring、发光或 box-shadow。保留原控件样式、光标与正常键盘操作；不借此重做全站样式。
- **共用一套 UI**：共用列表卡片、详情导航、操作栏、概览、新建/编辑/删除弹窗；不是仅共用外壳、内部仍各写一套。
- **禁止快速新建与批量操作**：不加快速录入、对应快捷键、多选任务、批量处理。普通新建与单任务操作保留。
- **保留陪伴与闪烁**：所有已发送主动消息的未读提示都应受到重视；问候、休息、回来提示和工作进展不能因类型被降为仅静态角标。优化触发准确性、可靠送达、去重和已读状态。
- **不反复增加已否定功能**：不添加今天页过期任务提示、筛选条件标签。
- **不伪造结果**：模型承诺不等于实际安排；解析成功不等于保存成功；运行结束不等于目标完成；研究判断不等于已验证事实。

## 4. 自然语言任务契约

### 2026-10-14 联系人对话工作迭代

用户明确要求全部联系人设置支持自然语言修改、全部必要用户处理通过聊天交互卡片完成、成果按任务特点动态呈现，并要求完整实现及充分单元测试。设置页保留手动入口，聊天/卡片/手动入口复用实际修改服务。无任务时也能配置联系人和处理事项；临时、任务和联系人长期偏好区分；模型理解不替代持久保存，权限修改不能仅写为文本要求。新增行为、失败处理及 CONV/CARD/VIEW 验收矩阵见 [实施附件](superpowers/specs/2026-10-14-contact-conversation-design.md)，[实施计划](superpowers/plans/2026-10-14-contact-conversation.md)记录逐项进展。本轮实现及分层验收已完成，实际覆盖和外部运行边界按验收记录逐项说明；此新增要求不取消任务单描述、共同UI、独立身份、固定成果正文与未读闪烁约定。

已接入全部现有工作设置字段、联系人资料/人设/模型、技能说明/脚本及安装/环境准备入口、搜索凭据安全卡片、公共持久事项与自然语言处理、分任务动态成果和分范围输出偏好。手动资料及密钥编辑与聊天共用有效配置版本；内置ChouYu的人设/模型同步原系统配置，修改模型时说明对跟随默认模型的联系人影响；空人设普通联系人保持自身身份。跨域组合设置保留独立持久步骤和回执，不声称原子保存，也不扩展批量任务。真实执行后回执不确定时禁止重放，允许用户核对后关闭；不将操作自身造成的任务变化掩盖为普通失效。具体实现、测试、独立审查及真实运行边界见 [实施验收记录](contact-conversation-acceptance-20261014.md)。

### 4.1 公共表单

弹窗仅含标题、“任务描述”标签、一个多行文本框、必要说明、保存/提交与取消按钮。错误信息和补问上下文是展示内容，不是额外配置字段。

- 新建可使用“交给 AI”，编辑使用“保存”或与实际行为相符的提交文案。
- 设置按钮直接打开描述，预填当前完整任务要求；旧目标和约束合并展示，不能丢失旧约束。
- 用户可以表达“每个工作日早上八点半检查联系人进展，重点告诉我哪里等我回复”，不填写时间选择器或周期下拉框。
- 修改已有安排时保留未提及的要求、启停状态与身份，不创建重复任务。
- 缺少执行所必需的信息才提问；已交代的内容不重复询问。保留原始要求、此前补充与当前问题，每次仍只有一个回复输入框。
- 不能支持的时间、周期或能力必须明确说明并追问；不能悄悄换成每日安排、立即执行或默认时间。
- 提交中防止重复提交，保留表单；失败显示原因并保留输入，可重试。只有持久化成功才能报告已保存/已安排。
- Esc/取消只关闭当前弹窗，不连带关闭联系人任务窗口；关闭后恢复合理焦点与原阅读位置。提交中不能造成重复保存或界面误报成功。
- 表单不得包含要求用户输入内部 ID、版本号、调用参数或解释实现细节的内容。

### 4.2 解析与保存

自然语言入口负责理解目标、约束和执行要求；由模型及经过校验的工具适配成实际任务。解析与写入之间必须验证归属、版本、能力和允许范围。

任务描述应作为需求来源保留；模型生成的摘要、标题和执行参数是派生信息，不能反过来覆盖用户未撤销的要求。多轮补问应关联同一任务请求。持久化原文与补问的现有缺口见第 10 节。

任务编辑必须修改原任务，保留历史和成果。编辑导致旧执行无效时取消旧运行，防止迟到结果覆盖新要求，并明确说明影响；不能默默恢复已暂停任务或提高资源权限。

### 4.3 内置职责与能力差异

问候、回来提示、休息提醒也属于共同任务体验。固定触发机制可以作为只读说明，不应成为再建一套配置 UI 的理由。用户对这些任务的调整仍应经自然语言理解：可支持的修改实际保存，不支持的明确反馈。

当前内置职责只读并不是用户同意的永久产品例外；实现缺口必须保留，不能据此声称“所有任务均可自然语言编辑”。

### 4.4 聊天中的任务修改（2026-10-10）

- 用户调整现有任务时先做结构化意图路由，经工具权限、归属及版本检查写入原任务。目标、范围、长期要求、任务名称和累计额度实际保存后才能回复已修改；单次正文修订、阅读样式、暂停、继续和回答问题沿用对应操作。
- 2026-10-15 编辑消息后“保存并重发”以编辑后的本次原话为当前请求，之后的旧回复不进入新请求。历史中的追问仅作上下文，不能覆盖本次已明确的书名/目标；不重新询问用户已经指定的作品。“写一章看看”等要求另写新内容的单次正文请求进入正常回复，不仅凭作品带“续”就恢复已暂停的长期任务；明确要求修改已保存成果仍走成果修订，明确要求恢复后台任务才走原继续操作。路由追问需对应本次原话，来源不符沿既有一次修复重判，仍失败如实报错，不转发旧话题追问。
- 只修改明确要求的字段，保留未撤销约束、成果、历史、其他额度和暂停/结束状态。内容与任务额度联合修改在同一事务中完成，失败全部回滚。原始用户消息进入任务需求记录。
- “一次汇报一个”是交付粒度，不得改成“一轮只研究一个”。结构化评审按已保存的各个评价分别投递，每条正文来自正式成果，不另调模型改写；各项独立来源、回执和重启去重，保留全部研究成果，不增加隐藏冷却或重发旧消息。
- 后台近期对话排除自动通知，按时间保留最新真实交流。正式要求来自持久字段，不依赖短期聊天截取。修改取消旧轮次，迟到结果不能覆盖新要求。
- 多任务含糊指代不能仅凭当前焦点猜测。无效模型字段和数字必须校验，格式最多修正一次，仍失败明确未修改。不支持的能力明确说明，不把文本约束冒充实际设置。

## 5. 列表与详情结构

### 5.1 列表

- 展示“共 X 项”，另行标明启用/进行中数量，不能用进行中数量冒充总数。
- 未配置晨报是安排建议，不计入实际任务总数；明确标注未配置。
- 卡片展示标题、真实状态、有用摘要。摘要优先待回复问题、下次时间、下一步或最新进展。
- 时间存在才展示；不堆叠无意义的“未记录”。缺失统计不能显示成零。
- 单任务删除在该任务操作入口内提供，使用公共确认弹窗；不扩展多选或批量删除。

### 5.2 共用详情

共用五个标签：概览、阶段计划、任务成果、互动记录、历史记录。使用数据与能力适配说明不适用的内容，不为 ChouYu 复制新的详情组件。

互动记录通过同一组件提供“任务需求记录”，可展开查看实际保存的原始描述、补问和后续修改。按纯文本呈现，不能执行其中的 HTML 或链接。旧任务未留存时明确说明，不能用当前目标伪造原文。沿用 8000 字存储上限，超长时保留开头与最近内容并明确标注中间缺失。

概览优先级：需要用户回复的问题 → 任务目标与当前状态 → 下一步 → 最新结果。指标、日志、工作时间、资源消耗为次级内容，按需展开。不能让资源面板挤占任务本身。

任务设置只编辑描述。联系人级工作规则、权限和每日总额度属于联系人工作设置，不复制到任务弹窗。只读用量可留在概览或活动与消耗，不能借此恢复多字段任务配置。

### 5.3 布局与焦点

2026-10-12 聊天快捷操作：现有联系人聊天工具栏增加当前任务名称、真实状态和单任务操作。运行、排队或等待续跑时可暂停，暂停后可继续，等待必要答复时打开原任务回复入口；查看任务仍复用公共详情。多项任务明确选择一项，不能以联系人整体暂停替代单任务暂停，不增加批量操作。状态沿用公共任务投影，动作复用任务详情的启停入口并核对任务版本；重复点击防重入，保存失败就地报错，不假报成功。切换聊天不串联系人，刷新后保留选择，不因另一个任务开始执行擅自切换操作目标。没有可操作任务时不展示空的控制区；已结束任务不自动恢复。

阅读样式修改失败时，快捷操作及详情主按钮打开原失败记录，沿原修改意见、成果版本与样式范围重试，不能用普通继续操作恢复正文工作；详情对暂停、已完成或已放弃任务同样遵守该范围。

2026-10-12 用户纠正布局：任务操作必须直接并入现有聊天快捷工具栏，不另起独立控制行。名称使用紧凑入口，完整名称和状态放在悬停提示及任务选项中；不重复展示状态文字和「查看任务」按钮，详情沿用已有「任务」入口，单任务名称也可直接打开详情。窄屏沿用工具栏自然换行，不为任务控制固定预留一行。

「待处理」弹窗与技能弹窗共用有边界的鼠标交互约定：窗口内接收点击，移出可见边界恢复桌面穿透；不能因原生模态背景命中而拦截整个屏幕。关闭按钮和 Esc 仅关闭待处理弹窗，先解除模态再恢复入口焦点，保留底层聊天；Esc 随后沿用公共逻辑清除按钮焦点。

任务快捷入口使用真实状态图标：只有正在执行本轮时显示旋转圆环，暂停、等你回复、排队或等待调度显示静态图标，受阻使用感叹号。状态读取失败停止显示运行动画，悬停和无障碍名称给出状态说明；遵守系统减少动画偏好，不增加工具栏行数或整体宽度。

- 窄容器下使用单列详情和横向标签导航，任务正文使用可用宽度；不能因页面嵌入位置不同而判断错误。
- 联系人资料页进入任务时收起不必要的头像、人设与资料操作，为任务留出空间。
- 待回复问题应优先进入首屏；输入与操作按钮可达，不被浮层或固定操作栏挡住。
- 标题可随内容滚动，操作栏可保持可见；不能出现重复运行按钮。
- 后台切换执行对象不切走用户正在阅读或回复的任务。
- 深浅色、宽窄窗口和键盘操作使用同一组件与样式规则。

## 6. 状态与操作语义

任务生命周期、当轮执行状态、定时开关是不同维度，不能混成一个“已完成”。

2026-10-10 用户明确持续任务语义：全天/24h持续产出和持续评审不存在以单次交付为终点的“完成”。汇报、列表与详情共用真实推进状态，区分正在推进、等待新内容、等待下一轮、排队、待回复、额度/服务阻塞、暂停与结束，不再用“尚未完成”概括正常持续工作。没有新内容时保持等待，不虚称此刻正在执行；真正暂停仍如实显示，不自动恢复。

只有用户明确的有限目标、截止时间或限时运行要求可成为任务终点。“全天/24h持续运行”不能自行改成“一天后结束”；一个 idea、一次评审或当前阶段全 done 不结束持续任务。模型拟议结束/放弃时另行核对原始要求、用户修改时间与实际已保存正文，只有核对通过才允许停止；不改为多字段配置。复核只在拟议终止时调用，计入既有调用和 Token 额度，结果按原轮次持久保存。无法核对或额度不足如实保留阻塞；原任务不被误结束，暂停/删除后迟到结果不能生效。

| 情况 | 必须展示或执行的行为 |
| --- | --- |
| 未配置安排 | 明确未配置；收集缺失信息，不显示虚构下次执行时间 |
| 普通任务待执行 | “立即执行”启动一轮，不暗示永久启用自动工作 |
| 定时任务暂停 | “启用定时”恢复未来触发，不冒充立即执行 |
| 内置提醒暂停 | “启用提醒”恢复条件触发 |
| 正在执行/已排队 | 展示真实状态，提供符合当前能力的暂停操作 |
| 等待回复 | 原问题和回复入口优先；保存后绑定原任务、原轮次继续 |
| 执行失败 | 显示原因，允许重试；不标成成功，不丢原始请求 |
| 本轮完成 | 展示本轮结果；目标未结束时不宣布任务完成 |
| 任务已结束/放弃 | 保留成果与原因；不自动重新执行 |
| 删除 | 明确删除范围，停止后续执行，迟到结果不得复活任务 |
| 旧版本表单 | 拒绝覆盖新版本，说明刷新/重新打开，不静默覆盖 |

工作计划返回格式异常时，兼容唯一完整 JSON 的外围说明；不能直接执行的计划最多自动修复一次，计入原额度并重新校验权限、来源与成果引用。修复次数持久化，失败保留成果与真实原因，不以猜测补足动作。实现与验证边界见 [工作计划格式恢复](contact-plan-repair-20261009.md)。

每项绑定联系人、任务、轮次与有效条件；操作前重查状态、权限与额度，重复点击只执行一次，保存及恢复在同一事务中完成，失败保留输入。手动暂停、删除、问题被替换或已从其他入口解决时旧卡片失效/已处理，不能复活任务。只展示实际需要调整的额度，明确任务累计/联系人每日及 Token/调用次数。卡片提交即为用户明确授权，不重复弹确认，不默认增加额度；已读不等于处理。新角色自动继承。验收覆盖提交、重启、去重、回滚、过期与跨联系人隔离。

2026-10-10 用户确认补齐：待处理入口位于现有联系人快捷工具，已读不清除未解决事项；ChouYu 汇总引用同一个事项并复用同一张卡片，不复制待办。服务商余额/密钥、网络、格式失败显示对应处理建议与配置/重试入口；打开配置不代表已解决，用户明确点击后才重试。执行进程启动、排队与执行分别计时，旧进程超时不能杀死新进程，诊断不记录密钥或模型正文。

## 8. 历史、可靠性与运行边界

### 2026-10-26 可靠性优化（已实现，验收边界见记录）

本轮采用共享 worker，保持联系人/任务逻辑隔离；进程级故障的共同影响是设计边界。新增行为与验收按[已确认设计](superpowers/specs/2026-10-26-contact-reliability-design.md)实施：宿主真实状态与有限恢复诊断；任务库/检查点成组备份及恢复核对保护；身份增量同步、按需会话查询和异步备份；明确截止/成功期次的持久结束规则；原生/DSH语义矩阵。以下规则自本轮起约束实现，代码覆盖状态须另据验收记录判断。

- 备份恢复不同于正常崩溃续跑。旧备份中的上下文、权限、在途外部操作和未知消耗须核对；不自动重放旧checkpoint、通知或扩大额度。缺失消耗不当零，额外额度须明确授权；组恢复失败保留原文件，不产生混合代际两库。
- 到截止时间停止新步骤，已在途操作在安全边界处理；截止不等于目标达成。明确成功期次按保存或送达模式计数，同一期重试不重复计数；未知语义必要追问。只改名称/要求不重置期限或历史计数，全天工作不自行变成限时24小时。
- 主动消息未读闪烁、单描述弹窗、共同任务UI、各域独立引擎和事务继续保持。宿主异常不伪造任务状态或成果，不改变正在阅读的固定版本。

本节不宣称实现完成，当前进度见[实施计划](superpowers/plans/2026-10-26-contact-reliability.md)。

- 保存每次定时执行尝试的计划时间、实际时间、状态、结果/错误和可用的会话/消息 ID；失败与取消同样记录。
- 持久化送达回执保证重启与重试不重复发消息；用户清空的消息不能因重试复活。
- 执行历史定位对应聊天消息；查看历史不能把未展示的新消息一并标为已读。
- 分页不能因新记录进入而重复或跳过旧记录。升级前没有记录的历史不补造，仅显示真实保留的最后结果。
- 数据按联系人及任务隔离，读写与导航均核对归属，编辑使用版本校验。
- 应用运行时后台可工作；退出、关机、休眠期间不能宣称仍在执行。恢复按各引擎既有持久状态处理，不逐次补跑全部错过周期。
- 共用 UI 不要求迁移或合并执行引擎；未支持的统计/阶段应诚实呈现能力差异。

## 9. 资源与权限

### 2026-10-12 联系人工具确认策略

- 在现有工作设置「资料与协作权限」中独立配置工具执行确认：沿用系统设置、需要确认的操作逐次询问、读取自动且修改前确认、已授权工具自动执行。默认沿用系统，不自动修改已有联系人授权。
- 显式选择自动执行后，该联系人的已授权工具（含修改事项）不再逐次弹确认；只读自动模式仍确认写操作。聊天每次准备好工具调用后读取最新联系人策略，保存按联系人隔离并检查版本。已弹出的确认仍等待用户处理，不因改设置暗中同意；待确认不超时终止。
- 此设置决定是否逐次确认，不开启关闭的工具，不扩大网页范围或技能脚本授权，不提高预算。后台任务继续使用已配置的资料权限与技能授权；变更确认策略不取消后台待回复检查点。其他联系人的设置不变。
- 验收需覆盖四种策略的实际 IPC 执行、持久保存、跨联系人隔离、旧设置兼容、关闭工具不能绕过，以及从失败卡片打开该联系人的设置并返回重试。

### 2026-10-10 联系人技能（SkillHub 与运行能力）

首版先接入技能说明、文本参考资料与现有工具；用户随后要求完善此前列明的执行能力缺口，范围扩展到按能力启用、隔离脚本、依赖准备与日志。下面是现行约定，真实运行验收状态单独记录。

- 所有联系人复用“技能”页，提供应用共享技能库、SkillHub 搜索/安装、按联系人启用/停用/移除关联。安装不等于启用；新联系人默认不启用技能。技能配置不进入任务单描述表单，不替代人设或公共交流约定。
- 用户于 2026-10-10 要求参照官方技能目录：打开“技能”默认加载评分排序的市场，无需输入关键词；提供分类、来源、下载量/上新排序、列表/卡片与分页。浏览不依赖本机 CLI，首次安装技能时自动准备商店组件。加载失败展示重试，筛选切换不混用迟到结果；安装过程取消后不能继续发起后续安装。
- 官方商店组件放在 ChouYu 数据目录，显式指定下载目录；不更改其他 Agent 的技能目录或优先源。安装版本固定、文件校验通过后才能使用；缺少 Python、网络失败、取消、坏包和写入失败必须如实提示。
- 下载后的完整文本检查包括说明与本地参考资料。说明与脚本权限分别启用；可选脚本和静态资源不再禁用整个包，旧安装重新检查即可使用说明。能力报告列出脚本、依赖清单、不支持文件及外部服务线索；必须明确必要能力缺失时相应流程不可执行，不能因说明启用声称完整兼容。自然语言依赖线索不是完整语义判定。
- Node/Python/Bash 脚本仅在 Docker Linux 隔离环境执行，按联系人明确授权，不降级为宿主命令。运行无网络、无用户密钥，包与工作输入只读，写入容器限额目录；成功后校验并导入普通工作文件（8 MB、128 文件、单文件 200 KB）。限制 CPU/内存/进程数，最长 120 秒；取消、授权撤销和退出清理容器，日志持久化，异常进程记录及残留容器可恢复清理。
- 依赖准备单独发起，可联网下载，使用资源受限容器；支持 package.json 禁用安装脚本、requirements.txt 仅预编译包，导出上限 64 MB。镜像构建只复制内容并用应用固定代码恢复经过边界校验的内部链接和执行权限，不执行第三方构建脚本。源码编译、其他清单、外部账号、常驻服务及视觉伴侣暂未接入，不能伪报成功。
- 技能文件工具只访问本轮已启用技能和该联系人独立工作目录。聊天和后台共用工具契约；工具总开关与单工具撤销实时读取，运行中的脚本最多 500 ms 内发现撤销并取消。每轮模型工具往返分别占用调用和 Token 预算。
- 每个联系人最多启用 8 项；单技能文本最多 32000 字符，组合上下文最多 64000 字符；超限明确拒绝，不截断关键要求。包最多 200 项、10 MB，禁止越界路径、链接及 Windows 特殊路径。
- 聊天按已核对的联系人在请求开始时读取技能；后台开轮直接读取最新技能库并持久保存内容与摘要，恢复原轮沿用原快照。停用下一次聊天/新轮次生效，不中止当前轮次；权限撤销继续遵守原有中止契约。输入内容计入原 Token 预算，不新增逐消息润色调用。
- ChouYu 模型生成晨报、问候工作检查使用同一技能解析。固定提醒不为技能新增模型调用，成果引用正文、未读闪烁和投递契约保持不变。
- 保存采用修改版本校验；旧窗口不能覆盖新配置。损坏技能仍能停用/移除，避免把联系人锁死。仍有联系人关联的技能不能卸载；联系人删除后清理关联。失败保留界面输入，Esc 仅关闭当前技能弹窗，不能关闭底层联系人详情。
- 技能详情与能力弹窗的鼠标交互范围限于可见弹窗边界，不能因全屏透明窗口或原生 backdrop 遮挡桌面点击；弹窗内按钮可实际点击，关闭后恢复焦点。技能库优先展示已启用卡片，集中呈现简介、说明与脚本各自状态；启停操作常驻，移除关联与卸载收进“更多”。

- 涉及 UI-03/05、NL-03/04/05、RUN-02/03、RES-01、MSG-01；本轮实现及验证边界见 [工作设置验收](work-settings-acceptance-20261009.md)，不以专项测试代替全部任务规范验收。

每日联系人调用上限与任务跨天累计预算独立校验。排队不预占调用，失败与重试按实际消耗计数。提高一个上限不自动提高另一个。

| 阻塞原因 | 说明与操作 |
| --- | --- |
| 今天额度已用完 | 说明次日恢复或调整联系人额度，保留队列 |
| 每日上限不足一轮所需 | 说明即使次日也无法执行，提供联系人工作设置入口 |
| 单任务累计预算不足 | 保留成果与状态，用户通过任务描述表达预算/范围调整；未打通解析时明确失败，不谎称已调整 |
| 密钥、工具或权限不可用 | 给出实际缺项和对应设置入口，不让用户猜测 |

模型不能自行放宽权限或无依据追加已有预算；明确的用户请求仍需校验并实际落盘。普通任务新建/编辑仍禁止恢复预算数字输入框；本节交互式卡片仅对当前真实阻塞提供直接额度调整，不能变成另一套任务设置。
