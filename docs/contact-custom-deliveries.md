# 联系人自定义任务输入与成果

更新：2026-09-29。

用户通过普通「新建任务」描述目标。联系人根据目标、人设和已有交流整理任务需求，已知信息直接填入，只有阻碍执行的缺项才追问。等待时仍发送原有主动消息并保留未读提示；用户可以在任务概览直接回复，或填写联系人生成的需求表单。

需求项支持自定义名称、说明、建议选项、已知值和必填标记。表单回复与普通回复共用任务恢复、预算检查、通知和互动记录。结构化回复会校验字段，保存的用户值优先于模型重复输出的旧值。阶段计划页可查看需求，在本轮结束或暂停后提交调整。

## 成果展示

成果版本分别保存正文 `sections`、需求 `inputs` 和展示 `presentation`。展示包含标题、HTML 片段、CSS 和原生 JavaScript。联系人可以为作家设计阅读排版，也可以实现目录切换、字号调整等逻辑。

- `window.delivery` 提供当前版本的标题、摘要、需求和完整分节数据。
- 系统向 `#content` 插槽放入正文，使用 `article[data-section-id]`、`h2`、`.body`，可直接用 CSS 排版。
- JavaScript 可以读取这些数据并操作阅读区 DOM；正文作为文本处理，不执行正文中的 HTML。
- 同一任务后续省略 `presentation` 即沿用，显式 `null` 恢复普通正文。
- 已有正文时允许只提交展示或需求，省略 `section`；不能因此改动完成条件、阶段进度或覆盖正文。
- 首次交付仍须有正文。旧成果继续使用原有 Markdown 阅读器。

成果页可切换自定义展示和正文，比较版本，提交修改意见，以及导出 Markdown 或带样式和交互的 HTML 阅读页面。修改意见例如：「只调整排版，保留正文，使用宋体并加大行距」。跨任务的模板管理与用户代码编辑器尚未提供；默认视觉方向来自联系人人设和任务偏好。

## 运行边界与验证

展示使用独立 `chouyu-artifact:` 协议和不带 `allow-same-origin` 的 sandbox iframe，按 [Electron 协议文档](https://www.electronjs.org/docs/latest/api/protocol)注册。CSP 禁止网络、外部依赖、子页面、表单提交；页面无 Electron/Node 接口，应用拦截展示页发起的跳转。宿主只接收该 iframe 的就绪或失败信号，并向其同步深浅色主题。展示脚本报错或超时可切回正文，不影响已保存的内容。

当前展示用于阅读与本地交互，不提供写回任务、访问文件或调用外部服务的接口。生成的视觉质量仍取决于联系人所用模型；代码通过结构与大小校验不等同于视觉验收。HTML 导出保留同样的 iframe 沙箱和 CSP。

验证命令：

```sh
npm run typecheck
npm test -- src/main/agents src/shared/delivery-presentation.test.ts
npm run build
node scripts/smoke-electron.js --presentation
```

专用烟测使用隔离数据，不调用真实模型；覆盖脚本执行、交互、正文注入隔离、宿主/网络隔离、跳转拦截、375/1024 宽度、深浅色、错误信号与 HTML 导出。真实模型的生成效果需结合实际任务体验评估。
