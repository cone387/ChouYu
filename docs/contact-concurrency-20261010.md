# 联系人同时推进上限：实现与验收

日期：2026-10-10。产品依据：[联系人任务规范](contact-task-spec.md)第 6、9、10、11 节，用户确认每个联系人分别设置同时推进上限。

## 已定义与已实现

- 联系人工作设置增加「最多同时推进任务数」，默认 1；正整数就地应用/Enter 保存，版本校验、失败保留输入及无彩色焦点装饰沿用现有组件。按需和自动模式均有效。
- 后台按联系人限制正在执行的轮次，按任务防重入。提高上限立即补位；降低上限让已开始轮次完成。排队、等待回复、到期等待和无法恢复的额度阻塞不占实际执行名额。
- 手动启动、聊天继续/修订、回复恢复共用名额。新交付任务先接单，随后按到期时间轮转；连续任务不能永久占据调度优先级。旧单槽任务提高上限时保留其真实调度，不激活无执行历史的闲置任务。
- 单任务修改、暂停和删除只取消自身。取消中的请求退出前仍占名额，同任务替代轮次继续等待；旧结果不能写回。关闭和重启按各自持久检查点恢复。
- 启动轮次时暂留可确定的调用容量，实际计数与追加格式修复都扣除其他运行任务的暂留。排队本身不计费、不预占 Token。Token 仍在请求前事务预留，累计预算独立校验。
- `task_failures` 独立保存任务失败次数和恢复时间；旧串行失败连同已有在途重试一起迁移。一项成功不清除另一项失败；恢复说明与预算待处理卡片按各任务展示。
- 共用任务列表、详情和单描述弹窗保持；ChouYu 问候、提醒和定时安排仍使用原触发引擎，不计入持续任务上限。

主要实现：`src/main/agents/service.ts`、`store.ts`、`task-failures.ts`、`interactions.ts`、`tools.ts`；`src/shared/agents.ts`、`work-settings.ts`；`ContactWorkSettings.tsx` 和 `ContactTopics.tsx`。
