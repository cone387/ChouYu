# 日志语义召回评测

本工具使用仓库内人工编写、人工标注的合成记录，不读取个人日志、聊天或应用凭据。当前数据集包含 8 条来源、12 个问题，其中 4 个无答案。覆盖跨日范围、应用筛选、同义表达、长 OCR 末尾、仅标题来源、多相关来源和不能证明已完成的事项。时间戳为合成日序；不是实际工作日期。

默认命令只校验数据并展示发送规模，不联网：

```powershell
npm run test:journal-retrieval
```

需要真实评测时，先通过运行环境设置 `CHOUYU_EVAL_EMBEDDING_URL`、`CHOUYU_EVAL_EMBEDDING_KEY` 和 `CHOUYU_EVAL_EMBEDDING_MODEL`，再显式执行：

```powershell
node scripts/evaluate-journal-retrieval.cjs --live > temp/journal-retrieval-live.json
```

该操作向指定服务发送合成查询及来源文字，可能产生费用。不会自动读取桌面应用配置。共享 Embedding 客户端执行响应校验、兼容路径及单批超时；整体期限 5 分钟。鉴权、限流和服务端故障不自动重发，失败不输出服务响应或凭据。报告记录模型、服务地址、时间和数据集 SHA-256。

评测复用产品的分块、余弦排序和来源合并逻辑；每个问题先应用日期和应用限制。数据集当前只有画面来源，未覆盖跨界活动时段裁剪或数据库查询性能。为减少评测费用，所有问题与分块在一次评测中去重后分批发送，最多每批 32 段；产品后续已加入持久来源向量复用，重复查找的实际发送量在产品预览中展示；本评测的去重发送规模不代表产品每次使用的费用。向量只在本次进程内使用。

对有答案问题分别报告 Recall@1、Recall@3 和前 20 名内的倒数首个相关排名，再对问题取平均。Recall 是命中相关来源数除以标注相关来源总数，多来源问题不会因为只找到一条就算完全召回。

无答案样例不进入召回率分母，保留返回来源与分数供诊断。当前产品没有校准后的拒答阈值，因此报告明确标记 `rejectionSupported: false`，不报告拒答成功率。例如“休眠已通过的证据”没有正例，文本仅说明尚未验证；检索到这条相反证据不等于证明问题前提成立。这项区分仍需要后续答案评估。

2026-09-09 验证：388 项单测及类型检查通过，默认命令输出 12 个问题、21 段去重文本、6156 字符、1 批。本地 HTTP 测试服务验证 `--live` 的发送、共享客户端解析和完整报告生成，使用恒定人工向量，仅证明管线可运行。尚未运行真实 Embedding 模型，不能据此声称召回率达标。这套小型合成数据也不能替代真实工作记录的独立标注与盲测。
