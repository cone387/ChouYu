# 联系人持续事项

现行产品与交互规则见 [联系人任务 spec](contact-task-spec.md)，修改前必读。本文说明当前能力；末尾旧日期记录仅为历史验收，不能恢复已移除的 UI。

任务弹窗展示具体事项，每轮工作更新同一事项，并保存判断变化与依据。支持重要进展主动发到联系人聊天、通过聊天确认后调整事项，以及可选的自主搜索补证据。

## 2026-09-28：持续交付

聊天交付任务后，联系人可以分轮研究或直接写作。事项中新增「阶段计划与成果」：完成条件、阶段状态、累积摘要、完整分节正文、历史版本及前后正文比较。每轮最多更新一个分节，其他分节原样保留；导出按钮通过系统保存对话框导出当前查看版本的 Markdown，包含来源与读取时间。

「修改意见 → 提交并修订」立即按最新成果执行一轮；可选择具体修订分节，尤其适用于仅指定资料模式下的早期正文。聊天可通过 `update_contact_topic` 的 `revise` 操作确认后执行。完成或暂停的事项也可重新修订，不自动开启持续工作。存在未完成轮次时先回复或暂停，不覆盖在途工作。

新运行收到待确认问题的答复后，会额外调用一次模型，实际修订成果再提交；不会只追加备注。只使用该轮已读取的证据，需要额外调查则标记待补证据，不能声称已补查。额外调用计入原有额度，额度不足不接收回复。旧检查点保留旧语义，不中途增加调用。失败的修订保留回复与修改意见，重新推进会带入尚未处理的反馈。

模型输入包含完整目录、累积摘要、阶段及最近三个分节；规划可以按稳定 ID 选择更早分节并读取全文。分节最多 10000 字，单个成果最多 300 节、正文合计 100 万字；不会截断本地完整成果。每轮输出仍受 2200 token 上限约束，建议分节正文不超过 800 字。版本存储完整快照，当前没有自动压缩或归档。模型阶段判断不等于外部事实验证。

成果版本、报告、事项变化与记忆同事务提交；取消、过期、写入失败不发布半份成果。记忆上下文取本事项研究记忆及联系人手工记忆。旧报告保留原位置，不自动拼成作品；兼容缺少结构化成果字段的模型响应时，将报告保存为独立分节，完成条件显示尚未明确。

实现计划与验收见 [持续交付迭代](agent-delivery-plan.md)。下面流程已按当前实现同步，末尾旧日期记录是历史验收结果。

## 使用

### 任务资源规划

顶部工作设置中的每日调用次数限制当天实际消耗；任务的 `resourceBudget.modelCalls` 是跨天累计调用上限，两者独立校验。其他任务（包括暂停任务）的累计预算不预占今天的调用容量。模型在接单或后续规划时估算首次预算并说明理由，自动首次分配最多为联系人配置的一日调用上限（最多 10000 次），不会自行追加已有预算；底层支持用户明确指定更大的跨天预算，仍受每日实际调用上限约束；旧数字输入入口已移除，自然语言预算调整尚未完整打通，见 spec 的实现缺口。

任务预算跨天、重启和重试保留，包含规划、执行、失败尝试、格式修复及回复修订。每次调用前同时校验联系人每日总量和任务累计预算。任务预算不足下一轮时暂停并发出资源提醒，保留已交付成果；联系人今日额度不足则等待次日恢复或由用户调整总上限。调度在开始执行时检查本轮所需调用，不以尚未执行的排队任务占用额度。

概览和阶段计划可按需查看预算和用量；任务设置仅提供一个描述输入框，不再提供数字预算编辑。底层预算校验仍要求不能低于历史用量，在运行中的任务需先暂停。AI 规划仍需说明分配理由。旧任务及未输出资源字段的兼容模型暂沿用联系人上限，后续规划继续要求补充分配，界面明确显示尚未分配；不会清空历史消耗或自动提高联系人上限。本次任务分配以模型调用次数为单位，搜索次数仍受联系人原有每日搜索限制。

### 操作入口

1. 和联系人聊天，点击输入框上方「任务」。也可从通讯录详情进入。
2. 直接在聊天或普通「新建任务」表单中逐项交付，空闲且额度足够时开始；忙碌或今日额度不足时先保存到持久化队列。只有缺少关键信息时追问。新联系人首次派发默认开启持续工作；已有联系人的开关保持原值。「权限与额度」只保存偏好，不创建事项。
3. 当前工作尚未结束也可以交付下一项。排队按接单顺序保存，界面显示「排队中」，不消耗模型调用。当前任务结束、暂停或等待用户回复时，联系人接续其他已安排的工作；普通事项编辑继续保留。
4. 「立即执行」处理所选普通任务的一轮工作；定时安排使用「启用定时」，内置职责使用「启用提醒」，不混淆立即运行与条件触发。正在运行的另一事项先完成，资料与调用额度由同一个联系人共享。
5. 每轮读取该事项的当前快照与最近三轮报告，更新判断、待验证问题、下一步和状态。联系人自己的近期聊天和记忆仍可作为背景，不读取其他联系人数据。
6. 「判断如何变化」按时间回看建立、调整和研究记录，展开可比较此前与当时判断、目标约束、待验证问题与下一步；「查看本轮报告与证据」打开实际采集页面、时间与正文节选。历史每页 30 条，可读取更早经历。

任务设置直接打开单描述编辑弹窗，旧目标与约束合并预填，不要求用户另填标题、约束或调整原因。编辑和状态操作由系统记录对应原因；编辑和状态变更会取消该事项尚未完成的运行。旧页面提交使用版本校验，不能覆盖后来变化。切换当前事项只影响后续调度，不取消正在执行的其他事项。

暂停、结束或放弃的当前事项不再执行，有明确交付的排队任务时自动接续；不会自动拾取旧的未安排事项。等待用户回复只挂起对应事项，其他已安排任务可以继续。回复绑定原轮次，当前另一个任务正在执行时先保存答复，待轮次结束后恢复，不并行写入同一联系人的成果。关闭持续工作时，每个明确交付的任务只执行首轮；联系人整体「暂停工作」会同时暂停已安排任务，单任务暂停只影响自身。模型结束或放弃事项仍须给出理由；「已结束」不等于外部事实已验证。

每个已安排任务独立保存下次执行时间，保留研究退避间隔。队列、待回复和检查点均跨重启保留；暂停或删除任务阻止其后续执行。后台任务切换不改变用户正在阅读的任务页。提醒保持原有未读闪烁和来源定位。

首次未运行的事项保持「待研究」。运行中或等你回复是当轮执行状态；事项判断在报告正式提交前保持原样。新轮次回复后实际修订再提交；升级前的旧轮次仍只保存补充信息供后续参考。

## 数据与恢复

- Agent SQLite 数据升级到 v6，新增按事项保存的成果版本；保留事项、通知发件箱、研究计划、搜索计数与变更历史。旧的在途轮次仍按原快照与检查点恢复，不中途增加权限。
- 已有工作方向生成一个待研究事项。旧报告、旧事件、记忆和运行保持原样，不根据相似标题猜测归属。升级前的在途运行继续使用其原输入和检查点，完成后留在旧工作记录中。
- 报告、事项进展、变更历史和记忆在同一个事务里提交。写入失败不留下半份进展；同一轮重复提交不重复增加事项版本。
- 恢复使用原事项快照和检查点；不会重复规划或搜索。新轮次答复后会调用修订模型，旧轮次不增加调用。修改或暂停事项会撤销旧运行，迟到结果不能更新事项或写报告。
- 执行进程恢复后主动通知已打开的界面重新读取，避免进程退出时的在途读取失败让「等你回复」停留在旧画面。
- 事项属于联系人；读取历史、编辑、切换当前事项、推进和状态变更均校验归属。删除联系人一并删除事项及历史。
- 每位联系人最多保留 100 个事项；支持单任务删除，确认时明确删除范围并停止执行；任务成果支持导出，结束但未删除的事项保留可追溯历史。用户待办系统不受影响，没有快速新建、多选或批量操作。

## 重要进展与聊天反馈

- 首份成果、新来源正文变化且判断改变、事项结束或放弃、需要用户答复时，联系人主动留下消息。来源比较使用 URL 与正文哈希，采集时间变化或同一资料换一种表述不会单独触发通知。重要性的识别目前是规则，不是额外一次模型评估。
- 消息写入该联系人最近的聊天，没有会话则建立工作进展会话；不切走正在看的聊天。会话显示未读，打开聊天后标读。消息的「查看事项 / 查看本轮记录」打开原有模态弹窗，按稳定 ID 定位，较早报告也可访问。
- 普通进展受每滚动 24 小时 8 条与至少 30 分钟间隔限制；需要答复的问题优先发送，不受通知开关、间隔或总量限制，避免任务等待时漏掉提醒。尚未投递的旧事项版本或已回答问题会抑制；同事项待投递进展只保留最新有效项。工作设置只关闭普通进展通知。
- 待确认问题以聊天确认卡片展示，点击「查看并回复」进入任务概览中的回复表单；提交后保存答复并继续执行。概览优先展示待回复问题、目标、状态和下一步；日志与消耗为次级内容，不挤占回复区域。「互动记录」按时间倒序分页展示每次问题和回复，已暂停或结束的轮次仍保留记录，可打开对应工作报告。记录直接来自持久化事件，不依赖最近 30 轮概览列表。
- 进展和发件箱与报告一起提交；问题在等待状态落盘时入队。主进程先同步保存聊天及投递回执，再确认发件箱。重启、进程退出或磁盘失败重试不重复追加；用户清空聊天后也不会因重试复活。磁盘失败期间保留待投递项，每 30 秒重试。回执保存在本地聊天状态中。
- 在聊天中明确说“继续这个事项”“暂停它”“预算改成 200 元”，模型通过 `get_contact_topics` 读取当前联系人的真实 ID 与版本，再用 `update_contact_topic` 提交变更。多个可能对象时应先明确对象。个人待办工具保持独立。
- `answer_contact_question` 把答复绑定到正在等待的具体轮次。预览同时显示原问题和答复，确认后从检查点接续；新运行根据答复修订成果，不重复读取已存资料，不声称执行未发生的补查。
- 所有写操作展示具体预览，即使工具权限设为完全允许也必须确认；拒绝、取消或聊天被删除不执行。确认期间事项版本或工作设置已变化则拒绝旧指令。一次聊天请求只允许一次写操作。工具开关关闭时可继续用弹窗表单操作。
- 聊天里的“继续”将该事项设为当前事项，并按现有来源与额度立即运行一轮；持续工作原先关闭则仍关闭。本任务已有待回复问题时需先答复；其他任务仅在等待回复时不阻止本任务执行，仍在实际执行的轮次须先完成。修改约束停止旧轮次，后续按既有计划执行；不会自行增加预算、来源或外部写权限。

## 自主补证据

在联系人「任务 → 权限与额度」中保存该联系人的 Brave Search API Key，再开启搜索服务并保存设置。默认公开网页通行，参考网页可选；选择「仅指定资料」时必须提供来源且不允许搜索。直接创作不需要网页证据。搜索默认关闭。

- 当前实现固定的 [Brave Web Search API](https://api-dashboard.search.brave.com/app/documentation/web-search)，使用 `X-Subscription-Token` 请求头和固定 API 地址，禁止搜索 API 跳转；密钥沿用本地敏感状态存储，在系统支持时使用 safeStorage 加密，不进入 Agent SQLite、检查点、证据或模型提示。密钥按联系人配置，修改时取消未完成轮次。移除密钥后停止自主研究调度，重新配置或关闭自主补证据后可继续。
- 正常一轮先调用模型选择 search / read / wait，再执行一次搜索或读取已知网页。有新证据或事项版本调整时才调用模型分析；同一轮通常最多两次模型请求，创建前预留两次额度。失败或崩溃重试也计入模型上限，未完成调用可能重复执行。
- 每次搜索最多取三个去重的 HTTPS 结果，可同时核对两个参考来源；读取最多五个网页。公开网页权限下模型可提出新 URL，只有真实读取成功的正文才算证据；仅指定资料模式严格限制来源。网页仍经公网 DNS 固定、同站跳转、大小与超时限制读取；搜索标题和摘要不作为证据。
- 搜索按联系人、设备本地自然日单独计数，默认每天 8 次，可设 1–24 次；请求前计数，失败也计入，不是金额预算。额度不足或服务不可用时，记录失败并尝试允许的起点网页；所有正文都读取失败则本轮失败，不写出虚构报告。没有自动更换服务或越过付费额度。
- 计划会说明要验证的疑问、检索词或重查原因。研究问题会发送到搜索服务；规划提示仅提供当前事项与允许的 URL，不传联系人私人聊天或独立记忆。网页正文仍发送至该联系人配置的模型做分析。开启前界面说明这一数据流。
- 同一事项版本下，所有成功读取正文的 URL 与哈希集合均与上一份报告相同时，沿用已有判断、不再调用分析模型、不写重复报告、不发进展消息。下次检查按计划间隔乘 2 / 4 / 8 逐步延后，上限七天；最早不低于用户设置的频率。出现新证据并生成报告后重置退避。wait 只记录等待原因及下次检查时间，不生成报告。
- 搜索计划、检索词、结果 URL、读取成功/失败、正文哈希、等待原因与下次检查时间可在「工作记录 → 本轮实际做了什么」查看。搜索已返回并持久化后，在读取网页阶段中断，重启会复用该轮搜索结果；若崩溃发生在外部请求返回但结果尚未保存之间，可能重试并再次计数。等待用户答复的轮次恢复不重新规划或搜索。
- 调度仍需应用运行；联系人之间独立并行，同一联系人内串行。暂停、结束、缺失密钥、模型额度不足等条件优先于计划时间。整轮没有固定总时限，单次模型请求保留 90 秒超时，网页请求也有独立超时。没有付费交易、账号登录、发送消息给外部对象或云端常驻能力。

## 验证入口

`src/main/agents/topics.test.ts` 使用真实 SQLite 和 LangGraph，覆盖同一事项三轮推进、反对证据修正判断、重启和用户回复接续、事项间报告隔离、联系人权限、编辑/暂停撤销、过期版本拒绝、写入失败回滚、结束后停止调度、完整历史分页以及 v1 迁移。

`node scripts/smoke-electron.js --agents` 使用真实 Electron 独立进程与弹窗：三组不同的合成来源、三次模型调用、进程重启、任务弹窗新建/暂停第二事项、原事项演变和证据跳转、关闭重开与联系人切换。可通过 `CHOUYU_SMOKE_ARTIFACTS` 保存深浅色和窄窗口截图。

验证中的模型、搜索结果和网页均为隔离的模拟数据，证明流程与数据约束，不代表真实模型的研究质量。真实搜索需用户配置自己的服务密钥，尚未使用付费服务做质量验收。
