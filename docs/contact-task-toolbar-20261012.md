# 聊天当前任务快捷操作验收（2026-10-12）

用户要求在聊天快捷工具栏直接操作当前正在运行的任务。对应任务规范第 5.3 节及 UI-01/03/05、RUN-02/03、SCOPE-01。

## 实现

- 按用户布局纠正，任务名称和操作直接并入现有聊天快捷工具栏，不另起控制行。完整名称、公共状态放在悬停提示及任务选项里；运行/排队/等待续跑可暂停，暂停后可继续，待回复打开原问题。去掉重复状态文字及「查看任务」按钮，复用已有任务入口，单任务名称也可打开公共详情。
- 多任务明确选择一项，单项暂停不影响其他任务；刷新、暂停及另一个任务开始执行后保持选择。原选择结束或删除时不擅自改为另一任务，切换联系人清空原选择。
- 任务详情与工具栏复用执行状态判定及启停按钮。提交前读取最新数据、校验任务版本与操作类型；防重复提交，保存失败就地报错，读取失败禁用修改并提供重新读取。
- 阅读样式修改失败打开原失败记录，沿已有重试入口保留原修改意见、成果版本和样式范围。详情中的暂停、已完成、已放弃任务也不会因样式重试恢复正文工作。
- 沿用现有深浅色与控件样式，窄屏换行；未增加批量操作或多字段任务设置。

## 待处理弹窗穿透修复

用户报告点击「待处理」存在点击穿透。根因是弹窗通过 Portal 挂在聊天面板之外，漏了鼠标交互标记；主进程收到窗口穿透指令后，弹窗内仍无法阻止穿透。增加与技能弹窗相同的交互标记和可见边界限制，避免原生模态背景被算作整个屏幕的交互区域；Esc 停止向父界面传播。关闭时先调用原生 close，再恢复入口焦点，避免模态尚存时底层入口不可聚焦。

隔离 Electron 冒烟先复现鼠标移入后主进程仍保持穿透，修复后通过；同时复现并修正关闭后的焦点恢复顺序。验证原生鼠标点击输入框获得焦点、关闭按钮有效并恢复入口焦点、移出边界恢复穿透、重新移入关闭穿透、Esc 仅关闭弹窗。工具栏原有暂停/继续/回复、版本、回滚及联系人隔离一并通过。`npm run typecheck`、构建及鼠标路由单测 3 项通过，日志为 `.superpowers/skillhub/pending-pointer-*.log`。未修改用户真实待处理事项或提交答复。

状态图标回归时发现原验收把 Esc 后入口持续聚焦当作通过条件，与公共 `core/escape.ts` 在关闭浮层后清除按钮焦点的约定冲突；已改为分别验证关闭按钮恢复焦点，以及 Esc 保留底层聊天，未修改公共焦点策略。

## 边界与未覆盖能力

没有修改真实用户任务、答复或授权；没有恢复阿笔已暂停的写作任务。运行验证采用隔离数据及本地模型夹具，不代表真实模型全天质量。

快捷控制覆盖联系人持续任务。ChouYu 定时安排与内置职责的现有接口只提供启用状态，没有即时执行状态，仍从公共任务详情操作；本轮未改动该执行引擎，也不把启用称为正在执行。共享状态仍按实际额度、工作时间与调度约束显示，点击继续不承诺绕过这些限制。
