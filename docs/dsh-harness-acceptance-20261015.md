# DSH 首阶段接入验收（2026-10-15）

状态：实现位于 `feat/dsh-harness` 独立工作区；默认仍为 legacy。真实供应商、完整故障注入及安装包验收门槛未全部关闭，不能据此启用日常联系人。

## 已实现范围

- 普通聊天通过统一 HarnessAdapter 接口选择 legacy 或 DSH。仅 `CHOUYU_DSH_PILOT_CHARACTER_ID` 指定的联系人进入 DSH；macOS 明确拒绝启动 DSH，无自动回退或重发。
- 保留原自然语言意图路由。路由直接完成的请求不计为 DSH 成功；LangGraph 长期任务、额度和任务界面继续原路径。
- 官方 SDK 负责启动、初始化和关闭。自有插件通过公开 AgentRegistry/Agent/sessionPersistence 接口建立隔离会话、执行、取消、落盘和只读核对；SDK 私有会话表不允许外部预建会话接管，未使用私有补丁。
- 每次请求重新装入当前 user/assistant 历史、独立人设、公共交流规则和上下文。图片与额外 system-role 历史尚不支持，发送前明确拒绝。
- 认证回环 TCP 通道保留 SDK 原 stdio；帧 1 MiB、socket 待发送 8 MiB、未应答请求 256 条上限。工具回到主进程执行。
- 开放资料读取、阅读偏好修改，以及读取偏好真实版本所需的 `get_contact_output_preferences`。确认复用原卡片和写入服务；DSH 只等待保存回执，不能再调用原 writer。
- 执行与工具关联存入独立 SQLite；原业务库继续拥有卡片、写入及回执。完成消息附稳定 ID，原聊天保存和未读流程继续工作。
- 重启只读核对正式日志，不恢复旧 Agent 或重放输入。清空聊天、删除联系人/会话、撤回资料和记忆边界清理关联日志；无法清理时原删除操作报错，可重试。

## 运行和打包

开发：先 `npm run setup:dsh-runtime`，再 `npm run build:dsh-runtime`；普通 `npm run dev` 不下载运行时。内部试点由启动环境中的联系人 ID 控制，没有新增产品设置。

Windows：`npm run package:win` 在构建阶段校验 Node 24.15.0 归档、按独立锁文件安装 DSH 0.2.1-alpha.3，将物理依赖放入 `resources/dsh-runtime`。运行时不安装依赖，不使用 Electron 当 Node，不依赖 dsh-desktop 仓库或全局 CLI。macOS 原构建入口保持原路径，DSH 未验证。

完整依赖闭包目前包含 63,716 个文件，约 **791 MiB**（未压缩）。这是一项实测成本，首阶段尚未裁剪默认 CLI 带入的非运行必需资源；后续优化必须重新验证依赖闭包，不能直接删除猜测无用的包。

回滚试点：移除 `CHOUYU_DSH_PILOT_CHARACTER_ID` 后重启，后续请求恢复原执行器。已产生的原确认卡片和回执仍由原服务管理；不复制/重放旧请求。不要手工清理正在使用的 SQLite 或 SDK 日志目录。

## 未关闭门槛

1. 真实可用供应商的普通聊天、资料读取及确认写入三项。
2. Windows 安装包的无全局 Node、含空格路径、无外网请求与退出残留检查。
3. 所有跨库间隙的强制 kill/重启注入；现有状态矩阵及公开日志读回不能代替这项证据。
4. `--dsh-harness-live` 完整 UI 驱动尚未实现；该参数明确失败，不能误跑普通 smoke 后输出成功。现有 opt-in provider-live 测试仅为供应商接口探针。

以上门槛未关闭时保持内部实验状态。没有完成全功能迁移，也未替换联系人后台执行引擎。

## 独立审查与修复

审查范围为基线 `5208e23d` 至 `f9fe7e2`；未发现 Critical，提出 5 项 Important，实施者逐项修复：

- 等待原服务迟到的 offer 完成，作废新关联卡片后停止才收敛。真实 SDK 延迟工具测试通过，期间没有第二次推理。
- 最终 flush 后检查取消和上下文；协调器/IPC 拒绝时保存不可恢复发布标记。取消或过期回复不再在重启后冒充成功消息。
- 每次 acquire 都校验图片能力，复用运行时也不能静默丢图。
- 识别关闭/断开/已退出的 helper，只有下一条明确的新请求才启动新进程；真实进程终止测试证明未重放旧请求。
- 失败、中断、取消及恢复后成功均清理敏感日志，保留账本关联；清理失败保留持久重试标记。显式删除先抑制回复恢复，避免残留日志复活消息。

5 个针对性测试文件共 23 项通过，随后全量 1830 项通过。补正了错误提示中的问号占位符，并同步产品规范、设计和计划状态。此处是修复与回归记录，不声称审查员对修复后版本再次审阅或外部验收门槛已经通过。

实现裁定：官方 SDK 用于启动/初始化/关闭，公开 scoped Agent API 用于执行；有序认证 TCP 替代原设想的 HTTP 加事件流。两者均未修改依赖或使用私有会话表。首次供应商探针因 429 无法完成后，继续独立本地实现并保持默认关闭；没有把该失败登记成用户批准的能力例外。
