# 运行后系统鼠标卡顿排查（2026-09-22）

## 结论与证据边界

已修复 Windows 全局鼠标转发这一高风险路径。尚未在现场复现用户描述的长时间运行卡顿，因此不能宣称已经证明唯一根因，或排除了显卡驱动、系统服务等因素。

`src/main/mouse-events.ts` 原先在透明桌宠窗口上调用 `setIgnoreMouseEvents(true, { forward: true })`。本项目安装的 Electron 44.2.0 在 Windows 实现中使用 `SetWindowsHookEx(WH_MOUSE_LL, ...)`。Windows 将该回调交给安装钩子的线程执行，因此应用主线程停顿可能拖慢其他应用的鼠标输入。单看整机 CPU 不高不能排除此问题。

来源：[Electron 44.2.0 Windows 窗口实现](https://github.com/electron/electron/blob/v44.2.0/shell/browser/native_window_views_win.cc)、[Microsoft LowLevelMouseProc 文档](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc)。以上是代码和平台机制证据，不是本次卡顿的现场因果测量。

## 本次修复

- Windows 显式使用 `forward: false`，通过 75ms 光标坐标轮询判定交互区域；其他平台保留转发及 300ms 兜底轮询。
- 光标静止不发送重复 IPC；同一穿透状态不重复调用原生 API。1px 边界移动也能被检测，窗口位置变化使用相对坐标重新计算。
- 显示、恢复、显示器变化后重新判定光标；锁屏/挂起时跳过采样，恢复后重判。控制器重复挂载、关闭和销毁均清理监听与定时器。
- 保留桌宠、普通新建任务和单任务交互；未引入快速新建、多选或批量处理。

取舍：正常主线程调度下，从穿透区进入桌宠/面板可能有最多约 75ms 的检测等待；主线程繁忙时应用自身仍可能迟钝，但不再依赖该全局鼠标钩子。真实鼠标快速点击、拖动、外部文件拖入、多显示器和睡眠恢复仍需实际交互复验。

## 验证

- `npm run typecheck`：主进程和渲染进程均通过。
- 鼠标控制、渲染侧穿透、日志 service/capture、剪贴板、任务 scheduler、数据库，共 7 个测试文件、140 项测试通过。
- 隔离日志循环：`node scripts/journal-soak.cjs --minutes 1 --interval-seconds 5 --restart-seconds 30 --output temp/performance-journal-20260922`。12 轮全部成功、0 失败、1 次存储/OCR 重启恢复；Electron 总工作集约 509.47 → 509.86 MB。此测试使用隐藏合成窗口并禁用 GPU，覆盖 OCR 和 SQLite，**不覆盖真实桌面捕获、活动辅助进程或完整桌宠界面**。结果见 `temp/performance-journal-20260922/report.json`。
- 当前开发实例主 PID 18056 的短时采样没有显示持续的主进程内存/句柄增长。采样期有其他开发与测试进程运行，不是受控性能基准，也不是新旧版本对照。初查整机约有 12GB 可用内存，没有内存耗尽证据。
- 正式 30 秒资源采样输出：`temp/performance-audit-20260922-final.csv`。15 组采样，主进程平均 CPU 约 0.83%（整机口径），私有内存 182.49 → 182.62 MB、句柄 1201 → 1201；GPU 进程私有内存 331.54 → 321.20 MB、句柄 1280 → 1280。此前两个调试 CSV 存在采样脚本精度问题，不作为 CPU 结论依据。

## 长时间复测

完全退出并重新启动应用，让主进程加载修改。已在运行的旧进程不会因为源码修改自动获得此修复；本次未强制结束用户开发实例。

新增 `scripts/measure-process.ps1`，只读取目标进程树的 CPU、工作集、私有内存、句柄、线程数，不读取窗口内容或业务数据，也不会修改或终止进程。每 30 秒发现新增子进程；主进程退出即停止。CPU 为按逻辑处理器数量归一化的整机百分比，首样本无 CPU 差值。

在任务管理器确认新的 ChouYu 主进程 PID 后，例如 PID 为 12345：

```powershell
powershell -NoProfile -File scripts/measure-process.ps1 -MainProcessId 12345 -DurationSeconds 1800
```

建议按正常使用方式复测到以往出现卡顿的时间点，记录发生时间、当时页面、是否正在记录画面，以及退出 ChouYu 后是否立即恢复。若仍出现，再对照暂停活动记录、隐藏桌宠等状态，区分截图/OCR、透明窗口合成和主进程阻塞。30 分钟采样也不能替代更长时间或多显示器环境复测。
