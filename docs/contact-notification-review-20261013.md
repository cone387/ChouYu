# 联系人通知场景复核与改进

## 问题与范围

用户报告《吞噬星空》同人续写消息只说“本次工作未完成”，要求用户翻记录，又同时提供自动与手动重试。只读核对真实记录：2026-10-13 09:45:18 因资料引用不在本轮目录快照中失败，09:46:22 已开始后续尝试。这不是工作时间或额度失败。没有修改真实任务、资料、消息，也没有替用户点击重试。

本次覆盖联系人异常通知、持久处理事项、聊天卡片及资料工具的错误恢复。成功交稿、无变化检查、问候提醒继续遵守原规则；不把正文改写为状态摘要，不增加模型润色，不降低首次失败和主动未读提醒。

## 场景与处理

| 场景 | 原因与影响 | 下一步及边界 |
| --- | --- | --- |
| 资料 ID/版本不在本次目录 | 明确“资料引用需要纠正” | 同次模型请求允许一次纠正工具结果；仍错则终止并通知。目录、权限、版本不放宽；每轮调用照常计费并检查预算。 |
| 资料撤回、删除、范围不符 | 明确参考资料不可用 | 核对任务资料；撤回、取消、存储错误不会被引用纠正吞掉。 |
| 章节继续/收尾/推进判断失败 | 明确章节衔接尚未确认 | 不提交可能接错的正文，提供续写重试。 |
| 任务结束条件核对失败 | 不声称整项工作完成 | 重新核对原要求与交付。 |
| 工作计划格式/地址参数错误 | 与正文格式失败区分 | 沿用计划内有界修正和原权限检查；不建议为格式问题开放权限。 |
| 正文格式、截断、分段恢复耗尽 | 说明本次不能交付完整新成果 | 正式正文和草稿分别核实；不凭错误字符串猜测已有成果。 |
| 本地存储异常 | 无法确认本次结果保存 | 检查磁盘和目录写入能力；不把失败描述为模型余额不足。 |
| 记忆纠正/忘记导致旧上下文失效 | 明确参考内容变化 | 保留既有取消及提交前校验，后续使用新上下文。 |
| 模型服务余额不足 | 区分服务商余额与应用任务额度 | 服务商补充或更换配置；任务卡加额度不能解决。 |
| 模型密钥/配置异常 | 明确模型服务配置不可用 | 对应配置入口；打开配置不等于解决。 |
| 网络、限流、暂时服务错误 | 明确服务暂不可用 | 沿用现有退避；排定重试不表示已经恢复。 |
| 搜索服务、网页权限、工具关闭 | 按实际类别区分 | 继续路由相应权限/工具/搜索设置。 |
| 技能环境/依赖、工具循环上限 | 明确技能或调用上限 | 保留环境检查与安全上限，不自动扩大授权。 |
| 应用内每日/任务累计额度 | 实际阻塞字段和用量 | 保留原持久额度表单，用户提交才调整；旧已处理卡片不再标题催促补额度。 |
| 必要追问 | 展示原问题 | 原检查点回复，不把“继续”当答案；已回答展示历史问题及处理结果。 |
| 自动重试未到时间 | 真实持久时间 | 明确已经安排；普通暂时故障无需用户重复操作。配置类仍提示先处理原因。 |
| 工作时段外、按需模式、三次停止 | 根据真实设置分别说明 | 不再所有失败都追加“仍受工作时间和额度限制”。 |
| 已重新排队/运行/待回复/再次失败 | 旧卡片显示后续真实状态 | 撤掉失效重试按钮和旧时间，不仅显示“操作失效”；后续失败说明最新原因。 |
| 后续单次完成、任务完成 | 两者明确区分 | 单次完成不宣称整项任务结束；不重复催促重试。 |
| 暂停、结束、删除 | 明确当前生命周期 | 旧卡不能恢复任务；样式修改独立于正文任务生命周期。 |
| 阅读样式失败 | 明确只改样式、正文未动 | 不自动续写，不虚报自动重试；已暂停/完成任务的样式重试仍显示实际排队/运行状态。 |
| 未识别异常 | 明说原因尚未识别 | 折叠安全技术诊断，不猜余额、网络或权限。 |

## 实现约束与取舍

- 新失败通知正文和卡片复用同一原因、影响和恢复描述。已发送历史正文保持不变，处理状态可动态刷新。
- “之前有正文”根据失败时点的正式版本判断；“有未交付草稿”仅根据该次失败所属的草稿判断。新草稿记录保存所属执行 ID，旧无归属记录不补造本次草稿事实。
- 卡片监听状态变化，并在可见页面每 30 秒补刷新，避免时间已过却仍显示旧安排。成本是只读 IPC 查询，不新增模型请求。
- 模型引用纠正只处理专门的无效引用错误，同次模型请求最多一次；再次无效仍停止。原始失败未记录调用参数，不能反推究竟是哪一个参数错了，也不能保证所有模型都能纠正成功。
- 自动重试时间表示最早可调度时间，不承诺该秒启动或一定成功；工作时间、实际预算和已有名额继续约束执行。
- 存储或未知错误仍有诊断边界；不把分类器声称为对所有服务商错误的穷尽识别。

## 验证

测试覆盖原因分类、无正式正文、失败影响快照、实际通知文本、跨重启处理、排队/运行/再次失败/完成、工作时段、按需、三次停止、样式重试、草稿归属、预算/权限/版本边界和诊断脱敏。新增断言均先见失败，再修复通过。

独立审查发现两项 Important：暂停/完成任务的样式重试显示错误；旧草稿被误认未交付。均以失败测试复现后修复。无 Critical、Minor。

最终验证：完整测试 1474 通过、20 默认跳过；类型检查与构建通过，保留既有大 chunk 提示。`--contact-experience` 真实 Electron/worker/HTTP 工具链通过，覆盖错误资料引用返回纠正结果、正确版本读取、正文/文件交付与后续评审；`CHOUYU_SMOKE_PERMISSIONS_ONLY=1 --agents` 通过真实设置按钮、重试提交、旧卡状态刷新、资料失败原因及 375/1024 深浅色截图检查。人工检查了浅色窄屏权限/资料失败卡和深色宽屏运行状态；卡片边界与按钮交互检查通过。

日志在 `artifacts/contact-notifications/`：`suite-review.log`、`types-review.log`、`build-ui.log`、`experience.log`、`ui-verified.log`，截图在 `ui/`。初次 UI 验收暴露测试脚本未等待工作状态加载，以及对正在由真实 worker 执行的测试轮次强行注入状态造成竞态；已改为等待实际 IPC 就绪，并用独立合成任务验证显示状态，未放宽产品的来源校验。验收使用隔离数据库和本地 HTTP 模型夹具，未调用付费模型、未改动用户真实任务。有限夹具通过不等于任意模型都能自纠正。

## 生效方式

涉及主进程及联系人执行进程，须完整退出并重新打开应用；只刷新界面不能加载执行修复。本次不强制终止用户正在运行的任务，不改写旧消息，不推送远端。
