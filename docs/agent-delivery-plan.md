# 联系人 Agent 持续交付迭代

日期：2026-09-28。范围：阶段计划、累积成果与版本、反馈后修订。

## 实施顺序

1. 为事项保存交付标准、稳定 ID 的阶段、阶段状态、成果分节及摘要。每轮只更新一个分节，其他正文保留；报告、事项和成果版本同事务提交。
2. 新运行携带成果目录、阶段摘要和有界正文上下文。保持旧运行检查点兼容，不把历史报告猜测拼成作品。
3. 用户回答新运行的问题后，调用模型根据回答修订再提交。另提供单事项修改意见入口和聊天工具；受原额度、版本校验和权限限制。
4. 原事项弹窗显示阶段、完整成果、历史版本与前版比较，支持导出单个 Markdown 成果。
5. 验证多轮写作、研究修订、旧库升级、重启恢复、事务回滚、归属隔离、过期结果和预算限制；运行类型检查、全量单测、构建、Electron 专项及完整冒烟。

## 产品边界

- 应用保持运行时执行，不增加云常驻、联系人互相派工、个人待办快速新建、多选或批量处理。
- 完成条件及阶段由模型根据用户目标整理，不代表事实已经外部验证。
- 每轮交付一个有界分节；完整作品在本地累积，模型上下文使用摘要和有限正文，不承诺无限上下文。
- 旧运行按旧语义结束；新运行启用交付与反馈修订。没有结构化交付字段的旧模型响应仍保留报告并按独立分节累积，不伪造阶段完成。
- 反馈修订只使用实际已有资料；需要新证据时标为待补证据并安排下一轮，不能声称已经补查。
