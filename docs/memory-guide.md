# ChouYu 本地记忆系统

`1.1.0` 起，ChouYu 使用独立的 SQLite 数据库存储长期记忆。默认实现位于 `src/main/memory/sqlite-provider.ts`，通过 `MemoryProvider` 接口可以替换为其他本地或远程实现。

## 记忆类型

- `fact`：稳定事实
- `preference`：用户偏好
- `person`：人物和称呼
- `project`：长期项目背景
- `workflow`：用户确认的工作方式

## 写入规则

- 只有“请记住”“我偏好”“我叫”“我的项目”“以后请”等明确表达才生成候选。
- 所有自动提取的候选都要用户确认后才能参与检索。
- 密码、API Key、Token 和 JWT 会在 Renderer 与 Main Process 之外的共享规则中识别，并在 Main Process 再次阻止。
- 附件正文、窗口标题、剪贴板内容和工具结果不会自动提取为记忆。
- 相同标准化内容只保存一份。

## 冲突与合并

`1.1.2` 起，新候选会和已启用的同类型记忆比较。系统目前可识别同一事实的不同值、对同一偏好的相反态度，以及高度相似的项目/工作方式更新。

发现冲突时不会自动覆盖，必须由用户明确选择：

- **用新记忆替换**：归档相关旧记忆、移除旧向量，并启用新候选。
- **两条都保留**：保留旧记忆，同时启用新候选。
- **拒绝新记忆**：删除候选，已有记忆保持不变。

冲突卡片会同时展示已有记忆和新候选。一次候选匹配多条已有记忆时，同一决策会应用到全部待处理冲突。

## 版本历史

- 编辑已启用记忆前会保存旧内容、类型和重要度。
- 替换记忆前会为被归档的旧记忆保存一个版本。
- 恢复历史版本前会先保存当前值，因此恢复操作本身也可追溯。
- 版本历史保存在 SQLite 的 `memory_revisions` 表中；删除某条记忆会同时删除它的版本。
- 记忆中心中的恢复和永久删除均需要卡片内二次确认。

## 生命周期与容量

`1.1.3` 增加了本地生命周期管理：

- 容量预算默认为 500 条，可在 50–2000 条之间调整。
- 超出预算时按照重要度、最近使用时间、使用次数和来源反馈计算保留分，优先归档低价值记忆。
- 新记忆默认永久保留，也可设置 30 天、90 天、180 天或 1 年的默认有效期。
- 已到期记忆会自动归档并移除对应向量，不再参与 Prompt 检索。
- 记忆中心可以预览低价值建议、多选批量归档，并查看到期、容量整理、手动整理或替换等归档原因。
- 归档不是永久删除；容量未满时可以恢复使用。恢复到期记忆会清除旧有效期。

## 来源反馈

回答下方的长期记忆来源支持“有帮助”和“不准确”评价。同一条回答对同一条记忆只计一次，修改评价会替换旧值，不会重复累计。反馈仅作为有界的辅助信号，关键词相关度、重要度和时间仍是主要排序依据。主题摘要来源多个原始记忆时，评价会同步写入这些原始来源。

## 主题聚类与摘要压缩

`1.1.4` 增加了本地可解释的主题聚类：相同类型且关键词重合度较高的已确认记忆会组成主题。主题提供提取式摘要、关键词、原始记忆数量和可节省字符数；展开后可查看每一条来源。

开启“摘要压缩”后，检索结果中的同主题记忆会合并为一个摘要条目，Prompt 仍携带所有原始记忆 ID（例如 `[memory:id-a|id-b]`），因此不会丢失溯源。关闭开关即可恢复逐条原始记忆注入。聚类和摘要不修改、不删除 SQLite 中的原始记录。

## 人工主题与拆分

`1.1.5` 起，可以在记忆中心选择至少两条同类型的已确认记忆，创建命名的人工主题。人工主题优先于自动聚类。自动主题或人工主题都可以拆分；拆分后的记忆会保持独立，不再自动聚合，直到用户再次人工合并。

## 单条有效期

已确认记忆可以单独设为永久、7 天、30 天、90 天、180 天或 1 年。单条设置会覆盖创建时采用的默认有效期；到期后仍按现有规则归档而非永久删除。

## 导入与冲突预览

记忆中心支持导入 ChouYu JSON 导出文件或同结构的记忆数组。Main Process 会限制文件为 5 MB、重新校验字段并阻止密码、Token 和密钥。预览阶段将条目标记为新增、重复、矛盾或更新：

- 新增：写入新记忆。
- 重复：默认跳过，避免重复保存。
- 矛盾/更新：选择与已有记忆并存、替换已有记忆或跳过。

提交导入前会再次确认；替换仍采用归档旧记忆和保存版本的安全流程。

## 本地统计与纠错

统计概览使用本地数据库计算类型分布、近 8 周新增、归档构成、反馈总量和摘要压缩量，不包含网络遥测。将来源标为“不准确”后，可以直接跳到记忆中心定位并编辑原始记忆。

## 远程适配器与 Mem0

`1.1.6` 增加了独立的 `MemorySyncAdapter` 协议。它负责远程列出、连接检查和上传，但不替换本地 `MemoryProvider`：SQLite 仍是默认主数据源，关闭远程适配器后所有本地能力保持可用。

首个实现为 Mem0：

- 默认关闭，不会因为配置完成就自动上传。
- Base URL 默认为 `https://api.mem0.ai/v1`，也支持用户配置的 HTTP(S) 自托管地址。
- API Key 使用系统 `safeStorage` 加密后保存在本机。
- User ID 必填，用于隔离 Mem0 中不同用户的记忆。
- “测试连接”只读取远程列表和数量。
- “拉取并预览”将远程内容映射为本地候选，并复用导入冲突预览；提交前不写入 SQLite。
- “上传本地记忆”必须二次确认，只发送已确认记忆；按 `chouyu_id` 和标准化内容跳过已存在项，每批最多并发 5 个请求。
- 上传元数据包含本地 ID、类型、重要度、更新时间和有效期，便于后续增量同步。

当前版本不会自动同步、删除远程记忆或传播本地删除；这些行为需要更完整的双向状态模型后再开放。

## 检索

基础检索不依赖 Embedding 模型，使用以下信号组合：

- 中文二元关键词和英文词元匹配
- 内容精确匹配
- 记忆重要度
- 90 天时间衰减
- 历史使用频率

`1.1.1` 增加了可选的 OpenAI 兼容 Embedding Provider。启用后使用 55% 关键词/结构化分数与 45% 向量相似度合并排序；连接失败、模型不支持或索引缺失时自动退回上述本地检索。

Embedding Base URL 和 API Key 可以独立配置；留空时复用主 AI Provider。向量以 Float32 BLOB 形式按模型存放在 SQLite 的 `memory_embeddings` 表中。切换模型后应在记忆中心执行“重建全部索引”。

已确认的偏好和工作方式可以作为全局偏好参与检索。返回结果会以 `[memory:<id>]` 来源标记加入 system prompt，并明确声明记忆不能覆盖系统指令。

## 隐私

- 数据文件：`<userData>/chouyu-memory.db`
- 记忆默认仅保存在本机；只有启用远程适配器并显式确认上传时才会发送到外部服务。
- 当前 SQLite 文件没有额外加密，因此不建议手动保存密码、密钥、身份证号等高度敏感数据。
- 敏感候选会显示提示，但用户仍应在确认前检查内容。
- 记忆中心支持逐条编辑/删除、JSON 导出和“忘记全部”。
- 关闭长期记忆后不会提取、检索或注入记忆，但不会自动删除已有数据。
