# 工作日志性能与恢复测量

## 可重复运行的隔离测量

在项目根目录运行：

```powershell
npm run test:journal-soak -- --minutes 2 --restart-seconds 45
npm run test:journal-soak -- --hours 24
```

工具为每轮创建独立的 `temp/journal-soak/<时间和随机标识>/`，编译固定的测量程序与存储 Worker，并创建隔离配置和数据库。不会修改实际工作日志、调用云端模型或抓取其他应用。默认每 5 秒从隐藏的自有测试窗口渲染一张 JPEG，经过实际日志存储与本地 OCR；OCR 必须识别出固定校验文字。图片内容重复时仍遵守产品的去重规则，因此成功轮数不等于新增图片数。

`--native` 改为显示自有测试窗口并调用原生窗口抓取路径；该窗口会出现在桌面。`--no-ocr` 可单独测量采集与存储。`--interval-seconds` 调整采集间隔，`--restart-seconds` 调整存储/OCR/采集器的重启间隔，默认每小时一次；重启后校验图片计数、媒体字节数和末张图片可读性。

输出目录必须不存在，避免覆盖其他测量。Ctrl+C 或在该目录创建空文件 `stop.request` 可请求正常停止；当前轮次结束后关闭资源，保留数据库与报告。系统休眠期间暂停工作，但工具不会主动让电脑休眠或锁屏。

## 如何解读报告

- `report.json`：运行状态、进程 ID、开始/更新时间、源文件哈希、实际运行时版本、成功/失败轮数、恢复次数、延迟均值和 P50/P95/最大值。`running` 只是上次写入状态，应结合更新时间和进程是否存活判断；进程被强制结束时可能保留旧状态。
- `samples.jsonl`：约每 30 秒一条资源采样，以及失败和重启事件。包含 Electron 各进程 CPU/工作集/私有内存、Windows OCR 辅助进程的独立 CPU/内存、图片占用、SQLite 数据库和 WAL 大小。磁盘数值不包含整个输出目录、日志与编译文件。
- `console.log`：进度和退出信息；`options.json`、`bundle/` 保存本轮选项和独立构建，以便后续代码修改时仍能区分测量版本。

CPU 首次观测或 OCR 进程重启后的首次观测记为缺失，不当作零。Electron CPU 保留其运行时指标含义，OCR CPU 使用进程累计秒数除以两次观测的实际间隔；不要直接与任务管理器整机百分比等同。Electron 工作集是进程工作集合计，可能重复计入共享页；不等于应用的独占物理内存。读取 Windows OCR 指标所用短命 PowerShell 进程自身的开销未纳入统计。

`complete` 表示指定时长内没有检测到轮次、资源读取或恢复失败；`stopped` 表示主动提前停止，`failed` 表示存在失败。不要仅凭进程正常退出推断全天验收通过。

## 验收边界

这是隔离的采集、SQLite 与 OCR 管线负载，不包含整个聊天/记忆界面或前台活动辅助进程。默认隐藏窗口模式也不包含原生屏幕捕获开销。脚本重启管线不能替代真实的系统休眠、锁屏和恢复测试。即使完整跑满 24 小时，也只能形成该固定负载的长期数据，不能证明真实窗口变化、多屏/DPI、用户日常使用或 macOS 已通过验收。

真实全天测试仍需分别记录采集覆盖、窗口切换、排除应用、锁屏/休眠后恢复、资源变化与失败原因。容量建议需结合实际画面尺寸与变化程度，不从简单测试图片直接外推。
