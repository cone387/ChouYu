# AgentSpace 模块重构验收（2026-10-16）

基线：`master@4015528`。实施分支：`feat/agentspace-modules`。代码修复截止：`aa39fd5`。本轮按已确认的三层架构重构现有联系人后台，没有增加新的任务界面或环境变量设置。

## 实际实现

| 模块 | 运行中的职责 |
| --- | --- |
| AgentSpace | 联系人装配、事件唤醒、共享名额、故障记录与关闭 |
| ContactAgent | 独立身份快照、模块装配、卸载与关闭 |
| WorkLoop | 本联系人任务选择、时间及预算检查、执行、取消与恢复 |
| TaskCenter | 原联系人任务数据库和命令入口；保留成果、进度、待投递消息的事务 |
| Harness | 原生后台能力入口，传递逐轮预算预留、结算、用量与取消 |

默认全局并发为 8，联系人自身上限继续生效；同一任务串行。取消后必须等旧请求真正退出才能释放名额。按联系人轮转，事件唤醒及时补位，15 秒检查补偿到期和漏事件。卸载 WorkLoop 保留任务与成果，删除联系人另走原删除流程。

普通命令及其身份同步按联系人排队。周期名单同步分别加入各联系人队列；包含仍在初始化队列中的联系人，防止其已删除却迟到创建。只有 init/close 使用全局屏障。普通 RPC 执行超时不会直接杀共享进程，先返回结果未确认，再通过独立 ping/pong 检测健康；5 秒探活失败才重启。单个请求超时不代表操作已撤销，不能自动重放。

## 独立审查与修正

整分支进行了一次独立只读审查，发现 1 项 Important：普通请求前的全局 sync 会等待其他联系人的慢删除，抵消新队列的隔离效果。已接受并修复：主进程普通入口仅同步目标联系人，周期名单同步分派到各联系人队列；新增分派测试及真实 AgentSpace 集成测试。修复后执行上述全量测试、类型检查、构建及 Electron 回归。

另外，原并发测试以数据库中的 running 作为“模型调用已发出”的依据；该状态还包含资料读取阶段。现改为等待实际模型请求进入，再保留原并发和结果断言。

## 失败记录与剩余边界

- 初次 Electron agents 冒烟在工作面板等待 20 秒超时；修正同步调用链后越过该阶段。
- 中间一次 agents 冒烟在第二次强制重启后的 SQLite WAL 初始化出现 `SQLITE_IOERR_TRUNCATE`。最终独立复跑覆盖多次强制重启并完整通过，但本轮没有证明该间歇错误的根因或永久消除；后续耐久验收继续跟踪。没有通过删除数据库或吞掉错误使测试通过。
- 本轮没有执行真实供应商 24 小时耐久测试、安装包验收或跨平台验收。应用退出后后台仍停止，没有新增系统服务。
- DSH 后台逐轮预算契约仍待实现。当前 WorkLoop 使用原生后台 Harness，联系人聊天执行器设置仍只影响普通聊天。
- TaskCenter 当前管理联系人任务域；用户待办、ChouYu 定时安排继续使用各自原引擎。普通聊天尚未迁入 ContactAgent 的模块实例。
- 模块装配与卸载目前是内部代码接口，没有插件市场、动态加载第三方代码或新的模块设置页面。共享 worker 的崩溃仍会影响全部联系人，不能称为进程级隔离。

## 实施裁定

- 复用干净的受管 worktree，新建功能分支，主分支保持不变。
- 已批准架构后连续执行，不重复索取实现许可；没有为新项目增加旧类名兼容层。
- 保留原任务事务及产品 UI，避免为目录统一重写用户待办或 ChouYu 的独立引擎。
- 健康但慢的请求需要联系人级排序及身份同步，不能只增加 ping。代价是必须明确处理名单变化与排队初始化的顺序，已补充回归。
- DSH 能力缺口作为后续实现项登记，不能当成用户批准的预算豁免。

产品约束仍以 [联系人任务规范](contact-task-spec.md) 为准；代码职责见 [架构文档](contact-agents-architecture.md)。
