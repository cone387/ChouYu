# ChouYu 1.4.7 发布验证

## 范围

持续提醒已在 `b6b6ccd` 合并，详细行为和验证见[持续提醒验收](persistent-reminders-acceptance-20261117.md)。用户随后要求准备 release，并反馈下载包退出很慢。本轮进一步定位和优化联系人最终备份；不取消最终保存、不强杀正在保存的数据库、不修改用户当前安装或原始数据。

## 退出性能调查

在本机离线数据库副本上测量：联系人数据库 301,969,408 字节（约 288 MiB），其中可复用空闲页较多。旧实现每次备份使用驱动默认 100 页分批，并在计算时间顺序和轮换时重复全量校验旧备份；三个历史备份会产生八次完整读取校验。退出路径必须等最后备份完成。

- 旧实现单次备份：10,337 ms，八次完整校验。
- 仅调整复制批次实验：4,887 ms。
- 优化后：3,907 ms，四次校验（本次新快照及三个旧组各一次）。
- 1.4.6 成品完整退出：从 UI 验收完成到进程退出 6,717 ms，其中联系人关闭 RPC 6,155 ms。
- 当前构建完整退出：同一份隔离数据为 3,353 ms。两者都含脚本固定的 300 ms 退出触发等待；这组实测约缩短一半，不代表所有机器、在途工作和存储故障场景的时间保证。
- 增加临退出实际写入的独立场景为 5,338 ms，退出后已核对最后修改同时存在于主库和最新备份，两库摘要、schema、完整性、外键与检查点归属全部通过。该场景增加了工作量，不与前述无额外写入场景混算性能比例。

原始数据仅用于生成隔离副本，所有任务在复制环境禁用，未对用户的实际数据库压缩、清理或改变任务。日志与副本在本地 `temp/quit-probe/`，不随发布上传；指标日志不含正文。

## 实现与回归

复制按约 8 MiB 分批，继续在批次之间让出执行权。时间顺序从本功能拥有的目录名读取，发布新组仍执行 SQLite 完整性、外键、来源归属、摘要和 fsync 校验；轮换只删除已验证的旧组，保留两个有效前代与新组，损坏组留存调查。

新增测试先复现重复扫描，再验证每个旧组只检查一次；损坏较新备份时仍保留三份有效快照。联系人备份/恢复、最终脏数据保存、退出保存失败确认、关闭时主动投递等六套件 29 项通过。类型检查和构建通过。

`scripts/smoke-electron.js --shutdown` 复用更新界面夹具，经真实联系人接口写入唯一事项后执行真实应用退出，记录至进程退出的耗时；15 秒为该验收夹具的上限。退出后检查末次修改、两库摘要及检查点归属，不能以退出码 0 代替保存成功。可显式提供 `CHOUYU_SHUTDOWN_SNAPSHOT` 离线目录，脚本只复制到临时目录执行；常规 CI 使用生成的隔离数据。Windows/macOS 成品更新专项同时检查该退出门槛。

首轮全量中 `result-designer/model.test.ts` 的测试子进程出现原生退出码 3221226505，未得到该文件测试结果，不能视为全量通过；单独复跑 5 项通过。原日志为 `full-tests.log`，本轮不据此宣称原生进程退出的系统原因已解决。

最终全量复跑 324 文件、2,427 项通过；17 文件、62 项按原配置跳过。类型检查、模块边界、构建、脚本语法检查通过。独立审查两轮均无剩余 Important/Critical 发现，覆盖备份保留与退出后磁盘核验。
