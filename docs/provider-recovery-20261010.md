# 供应商恢复自动接续（2026-10-10）

用户明确要求补齐供应商额度恢复后自动继续。遵循 [联系人任务规范](contact-task-spec.md)，本次不修改任务累计上限，不恢复用户暂停任务。

## 行为

原来 failures >= 3 永久挡住调度。现在只有已识别的余额/资源包不足、网络/超时/限流故障可进入低频恢复；第三次失败等待 15 分钟，第四次 30 分钟，第五次起 60 分钟。间隔模式取原间隔与退避时间中的较长者。

使用原任务下一轮真实请求探测，不额外调用通用余额查询接口，不承诺充值完成立即被发现；请求及重试仍计入实际调用和 Token 用量。成功保存成果后沿用原执行器清零失败数并继续既定节奏。

恢复候选必须为联系人最新的失败轮次、原任务与原版本；任务仍可执行且已安排/处于当前焦点，联系人仍处于自动模式。按需、手动暂停、删除、结束、权限/来源修改导致版本变化均不通过；格式/密钥/权限/未知错误维持三次停止。原工作时间、每日及任务调用上限、Token 预留继续校验。

失败时间、计数、调度时间均已有持久记录。旧版本留下的余额阻塞按原失败时间加退避计算最早恢复点，不清空失败次数。启动后到期最多排队一轮，已排队/执行时不能重复创建；再次失败延后，不补跑停机期间每个间隔。

失败通知、原交互卡片及工作设置展示自动尝试时间，并说明仍受工作时间与额度限制。手动提前重试继续使用同一事务路由，新轮次令旧卡片失效。
