2026-10-30。用户先要求看板与全员活动迁移，并授权直接实施；随后明确全 App 图表视角。最终六项调整：全员活动首屏可见、全 App Token 图表、移除记忆、移除联系人工作、时间图易懂及彩色指标卡、去除顶部介绍文案。

## 当前界面

- 全局导航入口顺序：会话、看板、通讯录、任务、活动、记忆。通讯录不再展示全员活动侧栏，列表使用完整宽度。
- 看板顶部只保留标题/日期/7或30天/刷新。四色指标为全 App Token、活动记录时长、我的待办、未读消息；后三项可进入原页。
- 首行左侧全 App Token 日趋势，右侧全员活动。窄窗口活动排在 Token 图之前。活动固定高度显示最新日志，来源姓名/任务链接复用已有详情与任务 UI。
- 下方是「每日电脑活动时长」小时柱图、「任务完成情况」环图、应用时长横条、模型消耗横条与会话消息分布。
- 不再展示记忆统计、联系人工作分区、联系人消耗横条或联系人筛选。无新任务编辑器，无快速录入或批量操作。
- 保留深浅主题与窄窗堆叠。图表含键盘入口、准确单位、文字数值和完整数据表；SVG 按实际容器宽度绘制。

## 全 App Token

- `app-usage.sqlite` 保存每次实际请求的 ID、开始时间、模型和已上报 Token；不保存正文、密钥或端点。主进程与联系人独立进程使用同一文件、WAL与锁等待。
- 采集覆盖 native OpenAI/Claude、DSH 前台/后台每轮、embedding、直接记忆提取与模型连接诊断。聊天、任务、助手和日志分析经这些模型入口的调用统一计入；不再用联系人任务的旧累计数冒充全 App。
- 同一请求的 SSE 累计用量更新同一行；工具多轮与实际重试分别记账，预算协商等未请求模型的步骤不计。取消/失败前已经上报的用量保留。
- 无调用为0；有调用但全部未上报为未知；部分上报只展示已知总和并提示缺失次数。统计开始前的无记录日期为缺口，不伪造零值。日界线按本地日期，聚合仅限所选7/30天。
- 页面显示采集开始日期，旧版本未保存的用量无法追溯；不回填局部历史制造全量曲线。第三方远端服务内部未向本 App 返回的模型消耗不可观测。
- 统计故障不阻断正常模型调用。初始化失败只让用量模块提示不可用；采集写入失败会保留统计缺口提示，已持久化的缺口跨重启保留。兼容服务仅拒绝用量参数时保留工具定义后重试。

## 其他数据与交互边界

- 活动记录时长来自开启采集后记录到的电脑活动，不代表全部设备在线时长或专注时长。每日失败留空缺，总时长未知；应用分布仅含成功读取日期。
- 用户待办使用完整 SQLite 聚合，不受已完成列表50条分页影响；排除归档清单、删除与重开任务。本期完成按本地完成日期统计，任务环图是当前保留状态。
- 会话消息为当前保留会话的累计量，未读为当前值，均明确标注。7/30天不伪装成会话历史筛选。
- 全员活动沿用最近120条事件窗口，完整历史仍从原任务查看。详情加载失败保留明确错误与重试，Esc仅关闭详情。
- 页面首次打开后保留挂载与时间范围；隐藏停止轮询和日志待发请求。不同数据域独立报错；切换日期立即屏蔽上个范围的数据，旧异步结果不能覆盖新范围。
- 不改动任务执行语义、共同任务UI、通知强度与未读闪烁。
